# 邀请码联机使用说明

联机使用 Python 与 AsyncSSH 加密转发 Minecraft Java TCP，不需要虚拟网卡、驱动或 Docker。服务端代码在 minecraft-tunnel，启动器和 SDK 在 buggcraft。每个房间有一台游戏主机，节点只转发该房间的游戏连接。

## 主机创建房间

使用账号身份时，先在节点网页「用户账号」中注册或登录，再领取个人启动器接入码，粘贴到大厅节点菜单的「添加与管理节点」。普通节点码用于匿名联机，个人码用于账号身份；启动器不需要账号密码。个人码最长有效 7 天，可在其他设备使用，到期后重新登录网页领取。未开启加密副本的账号只在注册节点登录。好友列表暂不跨设备同步，详细步骤见 [账号说明](../technical/node-accounts-security.md#在启动器使用账号)。

1. 在原有启动游戏页面点击“进入联机大厅”。首次使用打开管理员提供的节点网页，用玩家访问密码领取接入码；从大厅右侧的节点下拉菜单选择“添加与管理节点”，粘贴接入码并验证添加，再返回大厅。仍支持导入 relay-profile.json，同样先验证节点身份再保存独立副本。
2. 点击“创建房间”，自动使用首页选中的游戏实例，也可在本页切换已安装实例。进入 Minecraft 世界，按 Esc → 对局域网开放 → 开始局域网世界，再回来点击“查找世界”。没有找到时可展开端口设置，只需填写游戏显示的端口；版本、加载器和模组自动读取。
3. 选择查找到的世界，点击“确认世界，下一步”。启动器会实际探测本机游戏端口。连接成功后进入“设置房间”，填写房间名称。默认不公开，仅凭邀请码加入；选中“在大厅公开这个房间”后，可再选择“加入需要邀请码”：关闭时，大厅内直接加入；开启时，大厅展示房间，但加入者须填写该房间的邀请码。游戏聊天同步默认关闭；如需大厅与游戏双向聊天，勾选“同步大厅与游戏聊天”，并填写虚拟玩家英文名称。开启后会多一个虚拟玩家进入游戏，占用一个游戏人数名额；名称须为 3–16 位，以英文字母开头，只能包含英文字母、数字和下划线，不能与真实玩家重名。
4. 点击“创建房间”。允许直接加入时，连接完成后提示朋友可从大厅加入；需要邀请码时，复制邀请码发给朋友，再回到游戏等待朋友加入。

大厅使用 QML，Python 控制器负责联机和本机存储。房间列表在主区域，节点切换在顶部，创建和加入操作固定在列表上方。节点管理从节点菜单进入，可查看、选择、导出、移除节点，或粘贴接入码；删除前需再次确认。创建和加入页面提供返回入口。好友窗口可从首页或大厅打开，关闭好友窗口不会断开房间。加入房间后，节点选择会锁定；返回箭头退出前会询问是否断开。

未添加节点、节点配置失效、连接检查未完成或节点不可用时，不能创建或加入房间；大厅、表单、公开房间和好友入口都受此限制，Python 控制器也会再次拦截。保存过配置不代表节点在线，房间列表请求成功后才解锁。可手动刷新重查；大厅窗口显示期间每 15 秒检查一次节点，不清空已加载列表或正在填写的表单。切换、移除节点或刷新后，旧请求的结果不能恢复新节点的可用状态。

一级页左侧显示页面名称，右侧为最小化和关闭按钮。二级页的返回箭头与标题放在同一行。房间详情隐藏大厅菜单，点击返回会提示断开；房主确认后关闭房间，访客确认后退出，取消则继续保持连接。复制邀请码和游戏地址的反馈显示在原按钮上。

首页与大厅共用游戏实例选择，双向同步；版本、加载器及模组摘要均从安装元数据读取。游戏运行时联机固定使用启动时的实例，退出后可切换；读取中的按钮会暂时禁用。原启动游戏、下载、设置和实例页面仍使用现有 Widgets，保留既有设计。技术结构见 [QML 界面说明](../technical/qml-interface.md)。

大厅显示房间成员数，房间内另列游戏内人数；读取游戏状态失败或数据过期时显示未知。成员数包含启动器房主和访客，不等于游戏内人数。节点可设置房间容量与带宽准入，游戏主机仍控制实际人数上限、角色身份和存档；节点容量不能代替游戏服务端的内存、CPU、带宽与人数配置。

## 好友加入和本机联系人

1. 选择同一联邦中的任意可用节点；独立节点则需与房主选择相同节点。在大厅点“加入房间”，粘贴邀请码并加入。公开房间列表标明“直接加入”或“需要邀请码”，按钮统一为“加入”；需要邀请码时弹出输入框，错误房间的邀请码不能提交。默认使用首页实例；未选择时，可在加入页选择已安装实例，无需手填版本。
2. 连接完成显示“连接成功，去游戏里见吧”。按页面第 1 步打开 Minecraft → 多人游戏，进入自动显示的房间。没有显示时，按第 2 步复制直连地址，在游戏的“直接连接”中粘贴加入。
3. 在首页点击“好友”，或进入大厅后点击右下角可拖动的“好友”浮钮，单独打开好友窗口。点“＋ 添加好友”，输入好友的用户名或完整账号 ID；所选节点作为入口，查询同一联邦网络的公开账号目录并绑定唯一匹配的账号，不要求双方注册于同一个节点。重名时使用完整 ID。好友收藏仅保存在本机，不需要对方密码或接入码。每行可编辑或移除；旧版邀请码收藏仍可直接加入。关闭好友窗口不会关闭大厅或房间连接。添加好友不会绕过房间的邀请码要求。
4. 大厅的已有房间入口可回到连接详情。点击左上角返回箭头并确认，停止转发和发现报文；取消不影响连接。关闭大厅窗口保留连接；关闭主启动器会关闭大厅和联机后台服务。

联系人只保存在本机，没有远端好友关系、联系人跨设备同步或可信在线状态。远端好友账号查询要求用户主动开放加密备份目录。节点网页提供可选账号，用于跨联邦节点登录、领取个人接入码和保存加密个人设置；匿名接入码仍支持联邦，无需注册。账号范围和安全边界见[账号与源站保护](../technical/node-accounts-security.md)。邀请码是访问凭据，请通过可信渠道分享。默认本地游戏代理只监听 127.0.0.1，发现报文也只发到本机，不会把朋友的房间代理暴露给整个局域网。

主机退出世界后，Minecraft 的 LAN 服务会关闭，房间切换到等待状态。重进世界后重新对局域网开放；端口变化时点“重新选择世界”，保留原邀请码。网络中断后 SDK 会尝试重连，但正在进行的游戏 TCP 会话不能迁移；恢复后需要重新进入游戏。房主联机连接消失后保留 120 秒恢复宽限期，超过后关闭房间。

## 版本、核心和模组

加入前检查已知的游戏版本、协议版本、加载器及其版本、模组文件摘要。明确不一致时阻止建立本地代理；缺少信息时提示自行核对。可以读取当前安装实例的继承版本及 Forge、NeoForge、Fabric、Quilt 标识，摘要基于本地 mods 目录中的 jar 文件。

这是保守检查，不自动转换协议、不下载补齐模组、不保证所有服务端插件与客户端模组组合兼容。客户端专用模组可能导致严格摘要不同；配置文件、脚本、资源包和运行参数也没有被摘要覆盖。实际允许的版本组合仍以游戏服务端和目标整合包验证为准。

## 房间聊天

加入成功后，进入“我的房间”查看当前房间详情，在“房间聊天”输入并发送，或按 Enter。消息按房间隔离，并由当前节点经加密聊天通道发送；进入房间的启动器客户端都能看到最近 200 条记录。大厅聊天始终可用。只有房主创建房间时主动开启“同步大厅与游戏聊天”，才会让指定名称的虚拟玩家加入房主开放的 Minecraft LAN 世界。关闭时不会添加虚拟玩家，断线重连、换版本和重新开放世界也保持关闭，所有加入者会看到“游戏聊天同步未开启，仅在大厅内聊天”。开启时，大厅消息会带“[大厅] 昵称”前缀出现在游戏聊天中；玩家的普通聊天会带“[游戏] 玩家名”标记回到所有加入者的大厅房间聊天列表。聊天区域显示“游戏聊天已同步”时，表示游戏桥已经连上；大厅发送状态以节点确认作为成功条件。若游戏桥未连接，消息仍在房间大厅里，状态会明确提示。

截至 2026-10-20，聊天协议适配器覆盖 Minecraft Java 版 1.6.4 至 26.3 正式版清单中的全部 85 个版本：1.6.4 使用独立旧协议实现，其余覆盖 52 种协议。85 个正式版均已在经 Mojang SHA-1 校验的对应原版服务端上完成 10 轮双向聊天、同一身份重连及持续连接回归，全部通过。1.21.8 / 协议 772 另有四名实际游戏协议角色与四个 QML 大厅集成验证。版本矩阵结果见 [`chat-version-results.json`](../../../multiplayer-tests/chat-version-results.json)，复测时设置环境变量 `BUGGCRAFT_CHAT_VERSIONS=all`，然后在 buggcraft 目录运行 `python -X utf8 -m unittest discover -s tests -p test_chat_versions.py -v`；只测每种协议的代表版本可将变量设置为 `protocols`。正式版清单来自 [Mojang 版本清单](https://piston-meta.mojang.com/mc/game/version_manifest_v2.json)，测试快照保存在 tests/fixtures/java_releases.json。

大厅房间聊天独立于 Minecraft 账号模式，正版和离线启动器玩家均可互发大厅消息。游戏内同步会让房主端的独立离线观察者加入 LAN 世界，因此仅支持允许未认证观察者加入的 vanilla/LAN 环境；`online-mode=true` 的认证专服、强制签名聊天和模组专用握手不受支持。观察者会占一个游戏人数名额，房主的白名单、人数上限和聊天设置仍适用，游戏版本与模组组合仍需匹配。聊天是普通消息，不会执行命令；不转发系统提示、私人消息、动作栏和被过滤内容，也不声称验证了其他玩家的签名身份。记录在节点进程内存中，节点重启或房间销毁后清除。

房主只是退出 LAN 世界或暂时关闭局域网开放时，房间进入“房主不在游戏内，请等待”状态，访客停止重连数据通道，房间聊天和邀请码保留；房主重新开放世界后可沿用邀请码，端口变化时从“重新选择世界”更新端口。房主点击房间顶部返回箭头并确认关闭，会终止房间、断开访客并清除当前会话记录和聊天历史；访客确认返回只退出自己的会话。节点保留短暂终止标记，以便断线访客重连时收到房间已关闭，而不会恢复旧记录。

## 玩家自建节点

按照 [节点部署与维护说明](https://github.com/vdjango/minecraft-tunnel/blob/main/docs/deployment.md) 生成独立密钥、HTTPS 网页和配置。Windows、Linux、macOS 使用 Python 服务，Linux 可由 systemd 托管。从大厅右侧节点菜单进入“添加与管理节点”，粘贴接入码验证添加，也可导入、导出配置。已添加节点可直接在大厅下拉切换。节点网页公开展示状态，管理员密码与玩家访问密码分离。管理员互换联邦邀请后，玩家可从任意成员节点找房；房间所属节点承担中转。手动切换节点只影响后续操作。

节点配置包含服务访问凭据和固定服务器公钥，应来自可信管理员。不要泄漏服务器私钥或将配置上传公开仓库。节点管理员可以看到转发流量端点，也控制目录元数据；不要把未知第三方节点当作可信身份服务。当前主机和访客共用房间邀请码，邀请码持有者能在房间离线时以主机身份使用同一凭据；需要更强权限时应另行引入独立主机凭据与邀请轮换。

节点默认最多 512 个 SSH 连接、128 个房间、每房间 128 条游戏通道、全局 512 条通道、每访客连接 8 条通道。房间目录请求有大小、速率和会话数量限制。成功发现联邦后，启动器缓存备用入口；入口故障可切换，房间节点故障时房主尝试在备用节点重建，访客重新定位。旧目录约 10 秒过期，恢复还受连接超时和重试影响；已有游戏 TCP、会话及聊天记录不能迁移，需重新进入游戏。这些机制不能替代 DDoS 基础设施防护。验证见 [联邦测试记录](../validation/node-federation-validation.md)。

## SDK 与验证

安装 Python 3.11+ 和 buggcraft/requirements.txt 后，从 buggcraft 目录运行以下命令；源代码模式需把 src 放入 PYTHONPATH。

    python -m buggcraft.hookup host --profile relay-profile.json --game-port 25565
    python -m buggcraft.hookup client --profile relay-profile.json --invite "bugg1-..." --listen-port 25566

客户端可直连 127.0.0.1:25566。CLI 保留基础邀请流程；完整房间信息和兼容检查使用大厅或 SDK 的 room_settings/local_game 参数。

SDK 的 `TunnelHost` 默认不启动游戏聊天桥。需要同步时显式传入 `game_chat_enabled=True, game_chat_name='LobbyBridge'`，同时提供 `room_settings` 中的游戏协议信息。指定名称会用于初次登录和后续重连，UUID 由名称确定。此桥接方式会在游戏中新增一名独立参与者；不额外加入玩家的方案需要另行开发并安装游戏模组或服务端插件，当前没有实现。

实测结果见 [联机验证记录](../validation/multiplayer-validation.md)，未完成项见 [完善计划](../planning/multiplayer-roadmap.md)。已实测 Windows 客户端与 Ubuntu 服务节点；macOS/Linux 客户端尚需真机验收。分发前还需检查仓库及依赖许可，当前测试结果不等于完整发布验收。
