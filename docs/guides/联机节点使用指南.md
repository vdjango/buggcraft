# 邀请码联机使用说明

启动器通过 minecraft-tunnel-native 的 C++ Bridge 加密转发 Minecraft Java TCP，不需要虚拟网卡或驱动。Python 负责启动器界面、配置和调用原生接口；建房、加入、P2P、中转、聊天和模组传输均由 C++ Bridge 处理。每个房间有一台游戏主机，节点只转发该房间的游戏连接。

## 主机创建房间

从大厅节点菜单进入「添加与管理节点」，填写节点域名、IP 或完整 HTTPS 地址，点击「浏览器登录」。启动器会自动打开默认浏览器，在节点网页注册或登录后确认授权，再回到启动器。账号密码只在节点网页输入；启动器通过系统凭据库保存设备密钥，并自动续期。已保存的节点可直接选择，无需反复输入地址或接入码。旧版启动器接入码的输入、领取和导入入口已从启动器界面移除。账号范围见 [账号说明](../technical/节点账户安全.md#在启动器使用账号)。

1. 在原有启动游戏页面点击“进入联机大厅”。首次使用从节点下拉菜单选择“添加与管理节点”，填写管理员提供的节点域名或 IP，点击“浏览器登录”并在网页确认。浏览器未能打开时可复制页面上的登录链接。授权通过后自动验证并保存节点，再返回大厅。
2. 点击“创建房间”，自动使用首页选中的游戏实例，也可在本页切换已安装实例。默认选择“先开房，稍后进入游戏”，无需先启动 Minecraft。已有开放世界时，选择“关联已开放的世界”：进入 Minecraft 世界，按 Esc → 对局域网开放 → 开始局域网世界，再回来选择查找到的世界。没有找到时可展开端口设置，填写游戏显示的端口。
3. 在同一页填写房间名称和加入方式。默认不公开，仅凭邀请码加入；选中“在大厅公开这个房间”后，可再选择“加入需要邀请码”：关闭时，大厅内直接加入；开启时，大厅展示房间，但加入者须填写该房间的邀请码。游戏聊天同步默认关闭；如需大厅与游戏双向聊天，勾选“同步大厅与游戏聊天”，并填写虚拟玩家英文名称。开启后会多一个虚拟玩家进入游戏，占用一个游戏人数名额；名称须为 3–16 位，以英文字母开头，只能包含英文字母、数字和下划线，不能与真实玩家重名。
4. 点击底部创建按钮。未关联世界时，房间显示等待开放世界，房主可自行启动游戏；世界开放后检测并关联。允许直接加入时，朋友从大厅加入；需要邀请码时，复制邀请码发给朋友。

本次已调整创建入口和安装完成后的等待行为。房间锁定实例、成员进度、安装日志及管理操作按[房间准备方案](../technical/房间准备流程.md)分阶段补充；未开世界时的跨客户端完整准备流程仍需实机验收。

大厅使用 QML，Python 控制器负责联机和本机存储。房间列表在主区域，节点切换在顶部，创建和加入操作固定在列表上方。节点管理从节点菜单进入，可查看、选择、移除已保存节点，或通过节点地址和浏览器授权添加节点；删除前需再次确认。创建和加入页面提供返回入口。好友窗口可从首页或大厅打开，关闭好友窗口不会断开房间。加入房间后，节点选择会锁定；返回箭头退出前会询问是否断开。

未添加节点、节点配置失效、连接检查未完成或节点不可用时，不能创建或加入房间；大厅、表单、公开房间和好友入口都受此限制，Python 控制器也会再次拦截。保存过配置不代表节点在线，房间列表请求成功后才解锁。可手动刷新重查；大厅窗口显示期间每 15 秒检查一次节点，不清空已加载列表或正在填写的表单。切换、移除节点或刷新后，旧请求的结果不能恢复新节点的可用状态。

一级页左侧显示页面名称，右侧为最小化和关闭按钮。二级页的返回箭头与标题放在同一行。房间详情隐藏大厅菜单，点击返回会提示断开；房主确认后关闭房间，访客确认后退出，取消则继续保持连接。复制邀请码和游戏地址的反馈显示在原按钮上。

首页与大厅共用游戏实例选择，双向同步；版本、加载器及模组摘要均从安装元数据读取。游戏运行时联机固定使用启动时的实例，退出后可切换；读取中的按钮会暂时禁用。原启动游戏、下载、设置和实例页面仍使用现有 Widgets，保留既有设计。技术结构见 [QML 界面说明](../technical/QML界面结构.md)。

大厅显示房间成员数，房间内另列游戏内人数；读取游戏状态失败或数据过期时显示未知。成员数包含启动器房主和访客，不等于游戏内人数。节点可设置房间容量与带宽准入，游戏主机仍控制实际人数上限、角色身份和存档；节点容量不能代替游戏服务端的内存、CPU、带宽与人数配置。

成员数按联机控制连接统计，不按节点转发的游戏连接统计，因此 P2P 与中继成员都会计入。游戏内人数由房主启动器约每 2 秒读取本机 Minecraft 状态并上报，与游戏走哪条线路无关；开启聊天同步时扣除启动器添加的虚拟玩家。节点只汇总可用房间最近 15 秒的有效上报：全部未知时显示「—」，部分未知时显示已知人数加「+」，不会把未上报或过期当成零。节点人数是房主提供的状态，不是独立验证过的玩家身份。

## 好友加入和本机联系人

1. 选择同一联邦中的任意可用节点；独立节点则需与房主选择相同节点。在大厅点“加入房间”，粘贴邀请码并加入。公开房间列表标明“直接加入”或“需要邀请码”，按钮统一为“加入”；需要邀请码时弹出输入框，错误房间的邀请码不能提交。默认使用首页实例；未选择时，可在加入页选择已安装实例，无需手填版本。
2. 配置不匹配时点击“同步安装”，选择全新下载或从已有配置补齐。安装完成会复核配置并留在房间，由玩家自行进入游戏；房主尚未开放世界时显示等待。世界可用后点击“进入游戏”，也可在 Minecraft → 多人游戏中进入自动显示的房间。没有显示时复制直连地址，在游戏的“直接连接”中粘贴加入。
3. 在首页点击“好友”，或进入大厅后点击右下角可拖动的“好友”浮钮，单独打开好友窗口。点“＋ 添加好友”，输入好友的用户名或完整账号 ID；所选节点作为入口，查询同一联邦网络的公开账号目录并绑定唯一匹配的账号，不要求双方注册于同一个节点。重名时使用完整 ID。好友收藏仅保存在本机，不需要对方密码或接入码。每行可编辑或移除；旧版邀请码收藏仍可直接加入。关闭好友窗口不会关闭大厅或房间连接。添加好友不会绕过房间的邀请码要求。
4. 大厅的已有房间入口可回到连接详情。点击左上角返回箭头并确认，停止转发和发现报文；取消不影响连接。关闭大厅窗口保留连接；关闭主启动器会关闭大厅和联机后台服务。

联系人只保存在本机，没有远端好友关系、联系人跨设备同步或可信在线状态。远端好友账号查询要求用户主动开放加密备份目录。节点网页提供账号注册、登录、启动器设备授权和加密个人设置。旧节点协议仍可服务旧版客户端；当前启动器只提供节点地址与浏览器登录入口。账号范围和安全边界见[账号与源站保护](../technical/节点账户安全.md)。房间邀请码是访问凭据，请通过可信渠道分享。默认本地游戏代理只监听 127.0.0.1，发现报文也只发到本机，不会把朋友的房间代理暴露给整个局域网。

主机退出世界后，Minecraft 的 LAN 服务会关闭，房间切换到等待状态。重进世界后重新对局域网开放；只有一个兼容世界时启动器自动关联并保留邀请码，多个世界或版本不符时才请玩家选择。网络中断后 SDK 会尝试重连，但正在进行的游戏 TCP 会话不能迁移；恢复后需要重新进入游戏。房间管理连接消失后保留 120 秒恢复宽限期；已转让管理的世界提供者离开时，在线的新房主保留准备房间。

## 提前准备、成员和协助排查

创建房间时选择自己的游戏配置即可，不必先开游戏或导出、上传整合包。朋友可以先进房间聊天和同步安装；房主随时可以启动游戏。房间记住创建时的实例，首页切换版本不会替换这个房间的配置。安装结束后等待玩家自己启动，世界未开放时可先进入主菜单。

聊天默认在第一位。“成员”页显示每人的准备状态、下载进度、线路和延迟；未测得的延迟显示破折号，节点延迟会明确标注。房主通过成员行的管理菜单移出玩家、解除本房间的加入限制或转让房主。转让需要对方接受，世界仍由原玩家提供。好友邀请从好友列表操作，房间不重复放置邀请入口。

“安装日志”页可以搜索、按分类及级别筛选、复制或保存。房主协助朋友排查时，先从成员菜单请求查看安装日志；朋友明确允许后才共享经过脱敏的日志，并可随时停止共享。转让房主、断线或离开会清除授权，新房主需要重新申请。已经被对方自行保存的副本无法远程删除。当前共享的是安装日志，完整游戏调试日志仍在玩家本机。

准备结果会出现在成员页，并按设置发送提示；真实设备声音验证和完整测试边界见[房间准备验收记录](../technical/房间准备流程.md)。

手动关闭主启动器时，即使 Minecraft 仍在运行，也会先退出联机：房主明确通知节点关闭房间，访客断开自己的成员连接。连续点击退出、退出房间后立即关闭启动器都共用同一次清理，不会提前打断关房请求。游戏进程可继续运行，启动器为读取游戏退出状态而暂留的后台进程不会保留房间。设置中的「游戏启动后隐藏，游戏退出后关闭启动器」在游戏运行期间只自动隐藏窗口，继续维持联机；最小化及关闭大厅窗口也保留连接。强制结束进程、断电或网络中断不能发出关房通知，仍按节点检测断线及恢复宽限期回收，不保证立即消失。

## 版本、核心和模组

加入前检查已知的游戏版本、协议版本、加载器及其版本、模组文件摘要。明确不一致时阻止建立本地代理；缺少信息时提示自行核对。可以读取当前安装实例的继承版本及 Forge、NeoForge、Fabric、Quilt 标识，摘要基于本地 mods 目录中的 jar 文件。

这是保守检查，不自动转换协议，也不保证所有服务端插件与客户端模组组合兼容。配置不匹配时可通过房间的“同步安装”补齐，完成后重新核对。资源包和光影是可选内容。客户端专用模组可能导致严格摘要不同；锁定实例、清单版本及同步边界见[房间准备方案](../technical/房间准备流程.md)。任意模组自定义脚本和外部配置不保证都能自动发现，实际允许的版本组合仍以游戏服务端和目标整合包验证为准。

## 房间聊天

加入成功后，进入“我的房间”查看当前房间详情，在“房间聊天”输入并发送，或按 Enter。消息按房间隔离，并由当前节点经加密聊天通道发送；进入房间的启动器客户端都能看到最近 200 条记录。大厅聊天始终可用。只有房主创建房间时主动开启“同步大厅与游戏聊天”，才会让指定名称的虚拟玩家加入房主开放的 Minecraft LAN 世界。关闭时不会添加虚拟玩家，断线重连、换版本和重新开放世界也保持关闭，所有加入者会看到“游戏聊天同步未开启，仅在大厅内聊天”。开启时，大厅消息会带“[大厅] 昵称”前缀出现在游戏聊天中；玩家的普通聊天会带“[游戏] 玩家名”标记回到所有加入者的大厅房间聊天列表。聊天区域显示“游戏聊天已同步”时，表示游戏桥已经连上；大厅发送状态以节点确认作为成功条件。若游戏桥未连接，消息仍在房间大厅里，状态会明确提示。

旧 Python 实现的聊天版本测试已随旧代码移除；历史记录见 [`chat-version-results.json`](../../../multiplayer-tests/chat-version-results.json)，不能作为当前 C++ 实现的验收结果。当前聊天由原生桥实现，使用原生仓库的游戏聊天测试及本仓库的 `tests/test_native_bridge_services.py` 复测。跨 Minecraft 版本的实际游戏验收仍需单独记录。

大厅房间聊天独立于 Minecraft 账号模式，正版和离线启动器玩家均可互发大厅消息。游戏内同步会让房主端的独立离线观察者加入 LAN 世界，因此仅支持允许未认证观察者加入的 vanilla/LAN 环境；`online-mode=true` 的认证专服、强制签名聊天和模组专用握手不受支持。观察者会占一个游戏人数名额，房主的白名单、人数上限和聊天设置仍适用，游戏版本与模组组合仍需匹配。聊天是普通消息，不会执行命令；不转发系统提示、私人消息、动作栏和被过滤内容，也不声称验证了其他玩家的签名身份。记录在节点进程内存中，节点重启或房间销毁后清除。

房主只是退出 LAN 世界或暂时关闭局域网开放时，房间进入“房主不在游戏内，请等待”状态，访客停止重连数据通道，房间聊天和邀请码保留；房主重新开放世界后可沿用邀请码，端口变化时从“重新选择世界”更新端口。房主点击房间顶部返回箭头并确认关闭，会终止房间、断开访客并清除当前会话记录和聊天历史；访客确认返回只退出自己的会话。节点保留短暂终止标记，以便断线访客重连时收到房间已关闭，而不会恢复旧记录。

## 玩家自建节点

按照 [节点部署与维护说明](https://github.com/vdjango/minecraft-tunnel-native/blob/main/docs/节点部署指南.md) 生成独立密钥、HTTPS 网页和配置，并启用浏览器设备登录。节点使用原生核心及配套管理服务，Linux 可由 systemd 托管。从大厅右侧节点菜单进入“添加与管理节点”，填写域名或 IP，完成浏览器授权后添加。已添加节点可直接在大厅下拉切换。节点网页公开展示状态，管理员密码与玩家访问密码分离。管理员互换联邦邀请后，玩家可从任意成员节点找房；房间所属节点承担中转。手动切换节点只影响后续操作。

节点配置包含服务访问凭据和固定服务器公钥，应来自可信管理员。不要泄漏服务器私钥或将配置上传公开仓库。节点管理员可以看到转发流量端点，也控制目录元数据；不要把未知第三方节点当作可信身份服务。当前主机和访客共用房间邀请码，邀请码持有者能在房间离线时以主机身份使用同一凭据；需要更强权限时应另行引入独立主机凭据与邀请轮换。

节点默认最多 512 个 SSH 连接、128 个房间、每房间 128 条游戏通道、全局 512 条通道、每访客连接 8 条通道。房间目录请求有大小、速率和会话数量限制。成功发现联邦后，启动器缓存备用入口；入口故障可切换，房间节点故障时房主尝试在备用节点重建，访客重新定位。旧目录约 10 秒过期，恢复还受连接超时和重试影响；已有游戏 TCP、会话及聊天记录不能迁移，需重新进入游戏。这些机制不能替代 DDoS 基础设施防护。

## 桥接验证

启动器会按发行目录启动 `buggcraft-bridge`，通过 JSON-RPC 调用 C++ 实现；玩家不需要安装 Python 或运行单独的 Python 联机命令。开发者先在 `minecraft-tunnel-native` 目录运行 `ctest --test-dir build --build-config Release --output-on-failure`，再在本仓库运行 `tests/test_native_bridge_runtime.py` 和 `tests/test_native_bridge_services.py`。后者会在隔离的原生测试进程中验证真实节点、房间、模组清单、聊天和社交签名。

节点配置、房间兼容性和游戏聊天开关均由启动器界面提交给桥接组件；`hookup` 目录只负责适配 JSON-RPC、保存界面状态和准备游戏启动参数，不实现 SSH、ICE、P2P 或中转传输。

Windows 客户端与 Ubuntu 服务节点使用自动化测试覆盖；macOS/Linux 客户端仍需在对应系统完成发布前验收。分发前还需检查仓库及依赖许可。
