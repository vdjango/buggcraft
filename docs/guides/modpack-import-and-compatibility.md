# 游戏与整合包导入、内容下载和加载器兼容

## 已有游戏目录导入

在「实例 → 版本列表」左侧点击「添加游戏文件夹」，选择已有的 `.minecraft` 目录并扫描已安装版本。目录直接登记使用，游戏文件无需复制；不再重复提供“导入游戏”按钮。

## 整合包导入入口

统一从「下载 → 游戏下载」右上角的「导入整合包」进入；实例页不再提供跳转入口。选择 BUGGPACK、ZIP 或 MRPACK 后，页面只展示文件、Minecraft / 加载器摘要和新实例名称。在当前选定 Minecraft 根目录中创建独立实例，不覆盖已有实例。
导入页左上角「返回」回到进入前的下载分类，保留搜索结果和浏览位置；点左侧「游戏下载」也可返回。
开始导入后自动切换到「下载 → 下载记录」，依次显示解析清单、下载校验、安装游戏与加载器、解压配置和保存实例。进度、取消、日志和失败重试统一放在这里。已完成的导入禁止直接重新安装，避免覆盖存档；需要另一个副本时用新名称再次导入。

点击任务的「日志」，默认显示「文件进度」：每个 JAR、模组和其他下载文件都有名称、进度条、已下载/总大小和下载、校验、复用、重试或失败状态；Minecraft 资源文件显示清单中的可读名称。正在下载和失败的文件排在前面，可滚动查看全部文件。「文字日志」保留阶段消息与错误原因。

当前支持三种格式：

| 来源 | 清单 | 配置与内置文件 |
| --- | --- | --- |
| Buggcraft `.buggpack` / ZIP | 根目录 `buggcraft.pack.json`，formatVersion 1 | files；支持精简与常规导出 |
| CurseForge ZIP | 根目录 `manifest.json`，manifestVersion 1 | 清单指定的 overrides |
| Modrinth ZIP / MRPACK | 根目录 `modrinth.index.json`，formatVersion 1；按清单识别，不依赖后缀 | overrides，再叠加 client-overrides |

普通游戏目录压缩包、HMCL/MMC 专有包不作为上述格式处理。MRPACK 的客户端不支持文件跳过，可选文件一并安装，server-overrides 不用于客户端；下载逐项核对大小、SHA-1 和 SHA-512。仅接受受支持下载域名的 HTTPS 地址，主地址失败时尝试清单中的备用地址。相应规则见 [Modrinth 格式规范](https://support.modrinth.com/en/articles/8802351-modrinth-modpack-format-mrpack)。

## 导出自己的整合包

在「实例」对应版本行点击「导出整合包」，选择「精简导出」或「常规导出」，然后保存 `.buggpack`。精简：文件更小，导入更快。常规：包含完整实例内容，适合分享和存档。两者导入时都会安装对应游戏和加载器，因此不承诺完全离线安装。日志、截图和启动器本地状态不导出；配置、模组、资源包、光影以及实例内的存档随包保留。

双模式真实往返验收已通过：客户端分别导出精简与常规包、导入为新实例并启动 Minecraft 1.21.8，检查资源加载和 JVM 退出码。测试入口为 `python -m pytest tests/test_game_launch_live.py::RealMinecraftUiTests::test_buggpack_export_both_modes_import_and_launch_real_game`；截图、游戏日志和报告位于 `E:\code\multiplayer-tests\incident-20261028\pack-roundtrip-fixed\test_buggpack_export_both_modes_import_and_launch_real_game\`。

技术约定与房间同步统一使用相对路径、文件大小、SHA-256/SHA-1。下载器和房间准备保存已校验来源，精简导出只引用未改变的已知资源；本地手动添加或已修改文件内置。资源包、光影不参与联机兼容阻断；可选下载失败可跳过，必需模组失败则不发布可启动配置。房间创建仅发布摘要，完整清单按需读取，无需每次在节点生成 ZIP。详见[节点协议](../../../minecraft-tunnel-native/docs/protocol/game-metadata.md)。

导出使用该实例实际的隔离目录设置。独立实例不会夹带共享目录下其他版本的模组或存档；未隔离实例会包含其使用的共享内容。房间准备优先使用「设置 → 通用设置 → 模组与整合包下载源」，它与游戏/加载器下载源分别生效。来源不可用时，仅已经建立 P2P 直连的会话可向房主请求文件；只有中继连接时禁止房主文件传输，显示更换来源或等待 P2P 成功后重试。可选外观文件失败不影响必需模组的安装。

## 模组、资源包、光影和整合包下载

「游戏下载」页的「模组」「资源包」「光影包」标签直接切换同一页面中的资源列表，可选择「自动 / Modrinth / CurseForge」。「自动」同时查询两个平台；一个平台不可用时仍显示另一个平台的结果。项目旁标明来源，同名项目不合并，不会把一个平台的文件替换成另一个平台的文件。

搜索和版本查询在后台执行，不阻塞启动器界面；不自动按当前实例的 Minecraft 版本或加载器过滤，文件版本由玩家选择，可手动搜索。安装栏会提示是否适合当前实例，该建议不会禁止安装。点击项目进入页内详情，可查看作者、来源、介绍、分类、许可、更新日期和支持的游戏版本，再选具体文件，任务进入「下载记录」，校验 SHA-1/SHA-512 与文件长度后安装到实例的 `mods`、`resourcepacks` 和 `shaderpacks` 目录。资源包与光影不按 Forge/Fabric 过滤。

模组的传递依赖不会自动解析，已安装的旧版模组也不会自动替换；请按项目说明补齐依赖并自行移除冲突版本。光影文件会放入 `shaderpacks`，启动游戏还需要兼容的 Iris、Oculus 等渲染模组。

「整合包」类型也使用同一列表，不要求先选 Minecraft 实例。CurseForge ZIP 和 Modrinth `.mrpack` 保存到所选 Minecraft 根目录的 `downloads/modpacks` 子目录；完成后可在下载记录点击「打开目录」找到文件，再使用游戏下载页唯一的「导入整合包」入口创建独立实例。下载文件本身不会标成已安装的游戏。项目列表和文件列表滚动到底部附近自动追加加载，不需要点击“加载更多”，不显示成功结果数量。详情页隐藏顶部游戏/资源分类，点击返回恢复。通过顶部切回下载页面会刷新，资源子页面返回保留浏览内容。
加载器支持 Forge、NeoForge、Fabric、Quilt；同一清单有多个加载器时直接拒绝，即使其中一个标记为非 primary。

## CurseForge 下载授权

未内置的文件通过 [CurseForge 官方 API](https://docs.curseforge.com/rest-api/) 批量解析精确的 `projectID` / `fileID`，按服务返回的文件大小与 SHA-1 校验。
支持模组、资源包和光影包，分别放入 `mods`、`resourcepacks`、`shaderpacks`；清单中包括非 required 的条目也一并安装，保持作者导出的完整集合。

默认使用 Buggcraft 的资源查询服务，无需填写密钥。公共密钥保存在服务器，不包含在安装包或接口响应中。查询服务会接收搜索词、游戏版本、加载器及所选项目/文件编号，不接收游戏账号密码。

文件由元数据中的精确地址确定；没有直链时，根据精确文件 ID 与文件名构造官方公开 CDN 路径，并对文件名进行 URL 编码。下载源设置同时适用于资源文件和整合包：非“官方”模式优先尝试 MCIM 国内文件镜像，再回退清单原地址和 Forge CDN 备用主机；Minecraft 本体仍走 BMCLAPI。MRPACK 中允许官方 `edge.forgecdn.net`、`mediafilez.forgecdn.net` 地址，并逐个路由清单里的主、备用地址。不会把模组 URL 直接拼到不支持它的 BMCLAPI 游戏接口。文件大小、SHA-1 及清单提供的 SHA-512 仍须全部通过。

在启动器任意主要页面拖入一个本地 `.buggpack` / `.zip` / `.mrpack`，直接进入唯一的导入页面并解析清单、建议实例名称；确认安装后才开始下载并跳转任务进度。普通资源 ZIP 或损坏压缩包会在同一导入页显示错误，不会创建半成品实例。一次拖入多个文件不启动批量导入。

资源下载与游戏安装共用校验下载器：流中断自动重试，并对带已知长度和哈希的文件尝试 HTTP Range 续传。大于 8 MiB 且下载源明确支持 Range 的单个模组、资源包、光影包或整合包文件，会尝试至多 4 路并发分段，受下载并发数限制，设为 1 时关闭分段；批量文件不再叠加分段。不支持分段、范围无效或连接不稳时自动退回普通流下载，最终仍须通过完整长度与 SHA 校验。服务端忽略 Range 时重下；无效范围和校验失败会清除临时文件，已安装文件仅在完整校验后替换。取消会删除未完成的临时文件。任务记录包含文件名、来源主机和尝试次数；应用日志还记录成功来源、大小和失败原因。镜像返回网页错误、403 / 567 或连接失败时切换备用源，并在本次启动器进程中暂停访问 MCIM 60 秒，避免队列中每个文件都再等一次。

MCIM 的映射依据其[接入文档](https://www.mcimirror.top/guide/start/getting-started)。镜像维护方要求登记启动器名称和真实 User-Agent；本启动器发送 `BUGG | {version}`，版本号与随包 `app-version.txt` 一致，[登记内容](../technical/mcim-registration.md)可直接用于维护方的启动器登记帖。2026-10-26 本机复测中，MCIM API 查询成功，但资源文件请求返回 HTTP 567；启动器自动改用 Modrinth 官方 CDN 并完成文件校验。MCIM 接入正常不代表每个文件镜像节点始终可用；遇到限流或故障时会自动切换，设置为 MCIM 也不影响回退。Forge CDN 的 `/files/` 地址先规范为等价 edge 路由再映射，未知站点不做猜测替换。

允许服务器分发的文件若遇到 CDN 鉴权，可使用 Buggcraft 的受限备用下载接口。作者关闭服务器分发的项目只尝试玩家直接访问的官方公开 CDN，不经本站文件代理。服务端备用接口会重新核对项目与文件对应关系及分发设置，不接受任意网址；同时最多两个文件，单文件最多 512 MiB。接口与部署说明见[资源服务](../technical/content-gateway.md)。

导入页面只填写压缩包与新实例名称，不提供 API Key 输入项。开发和自建服务场景仍可在启动前设置环境变量 `BUGGCRAFT_CURSEFORGE_API_KEY`；普通玩家无需设置。该环境变量只通过请求头发送至官方 API 和 HTTPS 官方 CDN；跨出官方 CDN 的重定向会移除该头，不写入设置、下载历史、实例元数据或 URL。

[CurseForge 官方下载鉴权说明](https://blog.curseforge.com/introducing-api-key-authentication-for-curseforge-file-downloads/) 指定 API/CDN 使用 `x-api-key`。
API 的 downloadUrl 为空、项目分发标记为 false 或历史文件 isAvailable 为 false，不直接判定整合包不可导入：仍尝试元数据对应的公开官方地址。实际返回拒绝访问、文件缺失或校验失败时才失败并保留具体文件信息，不跳过文件，也不把缺失模组的实例标成成功。元数据查询遇到临时网络错误会自动重试；Forge 的第三方下载调用设置连接和读取超时，官方不可用时按下载源设置切换镜像。

## 实例、缓存与失败处理

- 最终目录：当前 Minecraft 根目录下 `versions/<新实例名称>/`。包内的 mods、config、资源等都在这里，始终使用独立游戏目录，即使全局设置关闭隔离。
- 游戏本体、资源和加载器依赖复用根目录下的共享安装。整合包实例继承已安装的正确加载器版本，并保留原游戏 JAR 和本机库路径。
- 下载缓存：`.buggcraft-downloads/modpacks/<压缩包的SHA256>/files/`。重试重新校验并复用完整文件，损坏文件重新下载。
- 导入失败、取消或中断后，在下载记录点击「继续安装」直接恢复原任务，不返回导入表单，不新增相同记录；保留实例名、目录和原有错误日志。压缩包需留在原路径，并与首次安装记录的 SHA-256 一致；文件被替换时明确提示恢复原文件，新包应使用新的实例名称。恢复时重新读取清单并校验缓存，补齐未完成文件和安装步骤；已完成实例不重复导入或覆盖。
- 每个任务同时下载的文件数量由“设置 → 通用设置 → 下载并发数”控制，默认 32，可选 1、2、4、8、16、32、64，新建下载任务生效。游戏核心、库文件、资源文件共用动态补位队列；CurseForge 模组/资源与加载器安装可并行；Modrinth/Buggcraft 模组/资源与原版游戏文件预下载并行，加载器等待强哈希校验通过；房间内容与游戏安装可并行，共享同一任务的下载名额。单文件任务仅在支持时使用分段，多文件任务按文件并行。独立下载/安装任务最多同时运行 4 个，并发数不是全部任务共用的总连接数。共享缓存文件按路径协调写入，同目录的加载器生成阶段顺序执行，防止并发覆盖版本配置。依赖下载进度是当前阶段进度（0–100%），切换计量单位时重置，不代表整个整合包流程已结束。
- 全部下载、解压和加载器安装成功后，再发布最终实例目录。取消或失败时清理临时实例，不改动已有实例的 mods/config/存档；已下载缓存与共享游戏安装保留。
- 不覆盖同名实例。拒绝路径穿越、绝对路径、Windows 特殊文件名、符号链接、加密条目及大小写重复路径。最多 50000 个 ZIP 条目，展开后最多 8 GiB。
- 部分 CurseForge 导出包在 overrides 中重复携带清单文件；内容大小与 SHA-1 完全相同时去重，内容不一致仍报冲突。Windows 解压使用长路径访问，支持较长的模组配置文件名。
- `buggcraft-modpack.json` 保存来源平台、来源名称、清单版本、Minecraft、加载器、ZIP 哈希和建议内存，方便追溯；建议内存仅展示，不自动覆盖用户的内存设置。
