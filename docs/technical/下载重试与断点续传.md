# 下载失败、重试与断点续传

适用入口：游戏下载、资源下载、整合包导入、在线整合包安装、房间客户端同步。

## 使用行为

- 网络中断时自动重试并尝试可用的备用源；全部失败后，用户可从下载记录继续安装。
- 整合包重试沿用原任务，复用已校验的文件，保留未完成文件的下载进度。
- 模组、整合包下载和导入统一使用通用设置中的下载源顺序。通过“上移 / 下移”排列 CurseForge、Modrinth、Buggcraft；首个来源失败后尝试下一项，每个来源最多自动重试 6 次、间隔 3 秒。旧版单选设置保留为首位，后续顺序可独立调整。MCIM 默认不加入，仅明确勾选后使用；`mediafilez.forgecdn.net` 不改写为 MCIM。
- 自动模式由 Buggcraft 源站统一选源，使用已有的健康数据为文件清单返回缓存或重定向地址，启动器不再逐文件测速。默认按 Buggcraft、CurseForge、Modrinth 的顺序兜底；手动排列仍按用户设置执行。界面沿用“自动测速”选项名称，切回“按顺序尝试”恢复此前排列。修改模式或顺序会中断旧连接、让同一任务使用新顺序，并保留已校验文件及有效断点。
- 整合包清单的文件名用于搜索候选项目，跨站地址必须匹配清单中的 SHA-1 和文件大小；不会因文件名相同使用其他版本。CurseForge 查询先用项目名、文件名及代表性词组，再尝试去掉末尾复数 s 的词组和较长单词；例如 `L_Enders_Cataclysm` 会查 `Enders Cataclysm`、`Ender Cataclysm`、`Cataclysm`、`Ender`，不单独查 `L`。候选项目优先按名称相关度筛选，不先翻查无关热门项目的文件历史。查询仍使用游戏版本和加载器筛选；单次查询超时不再禁用整个查询服务，文件详情显示回退原因。并发下载时列表汇总实际使用的多个来源。
- 清单已有 Modrinth 下载地址和 SHA-1 时，寻找 CurseForge 同文件不再先重复查询 Modrinth 元数据；只有缺少 SHA-1、需要由 Modrinth 补全哈希时才先查询。最终文件仍以哈希和大小校验。
- 整合包的模组下载耗尽重试后集中列出待补齐项，支持仅重试失败项、打开下载页、复制/保存清单、后台校验手动下载的文件，或经用户确认跳过并继续。确认跳过时将清单保留在最终实例中；不会因网络失败自动跳过，也不会安装校验不符的文件。
- 房间页失败后显示“重试下载”；下载记录里的房间任务也可以重试。已离开的房间会提示重新加入。
- 房间下载缓存独立于临时安装目录；失败清理临时实例时，不删除已下载的文件及可续传的数据。
- 下载源优先；仅在已经建立 P2P 直连时允许从房主下载。中转连接不启用此备用下载。
- 下载返回网页、错误响应或损坏的数据时，不发布无效的版本信息、资源索引或整合包实例。界面说明失败的信息项及重试方式，详细错误记入日志。
- 整合包自身的清单损坏时，提示重新导出或重新下载，避免把 JSON 解析器异常直接交给玩家。

## 启动时的 Java 自动准备

窗口显示后立即启动后台 Java 检查，先验证启动器已登记、已下载的运行时及当前路径。自动模式根据当前实例的 Java 兼容范围设置真实可执行路径；已有可用 Java 时不再扫描整个系统。找不到兼容运行时才扫描系统路径，首次下载仍由游戏或加载器安装准备流程触发。

Java 文件检查、版本子进程及配置落盘均在后台完成，启动回调不刷新隐藏的 Java 页面、不弹出安装对话框。检查期间切换实例、手动选择或下载 Java，旧结果不得覆盖新设置。游戏启动和 Forge 安装前仍独立验证实际使用的 Java，因此不依赖系统 PATH 中存在 java。

## 数据与兼容

公共下载使用 `<文件名>.buggcraft-part` 和同名 `.json` 检查点，记录预期哈希和总长度。检查点不匹配时丢弃旧分片；成功后先校验再原子替换目标文件，并删除检查点。

服务器支持 HTTP Range 时继续剩余字节；服务器忽略 Range 时重新下载该文件。哈希或长度校验失败的数据不会用于续传。取消并发分段下载时只保留连续的前缀，避免拼接不连续的数据。

房间文件缓存位于 `.buggcraft-downloads/room-content/<SHA-256>/content`。复用前重新校验长度和 SHA-256。原生 P2P 暂无字节范围协议，仅复用完整并通过校验的文件；公共源的断点续传独立保留。

## 回归用例

以下测试操作实际下载器、导出器和安装器。HTTP 服务器在本机提供可控响应，模拟断线、错误内容和恢复；UI 用例通过 Qt 鼠标、键盘事件操作生产界面。

- [x] `test_download_transport.py`：自动重试耗尽后新建下载器仍可续传；无清单长度时记录响应长度；身份变化不拼接旧数据；取消并发分段下载后续传；损坏信息切换来源且不缓存错误响应。
- [x] `test_room_mod_installation.py`：清理失败的临时实例后复用已完成模组；公共下载中断后按 Range 继续；中转连接禁止 P2P 下载；下载并发限制不变。
- [x] `test_modpack_import.py`：损坏的自有格式清单显示明确提示，保留原有导出、导入和文件完整性验证。
- [x] `test_modpack_sources.py`：导出默认只使用 CurseForge，也可选 Modrinth 或混合，混合始终 CurseForge 优先；空直链按精确文件 ID 解析；edge 404 后检查 mediafilez；错误哈希及不可用文件随包保存；指纹缓存按内容复用。
- [x] `test_mod_identity.py`：Forge、NeoForge、Fabric、Quilt、旧版 Forge、多模组 JAR、占位版本、改名、非 UTF-8 配置、损坏或过大的配置均不依赖文件名猜测。
- [x] `test_download_ui.py`：下载中调整来源顺序，中断阻塞的流并按 Range 续传；保留同一任务和已校验文件；并发来源与回退原因显示正确。
- [x] `test_settings_ui.py::ClientUiSettingsTests::test_content_source_priority_reorders_persists_and_preserves_auto_mode`：鼠标操作上移、下移、自动模式及 MCIM 开关，重新读取配置核对顺序。
- [x] `test_modpack_missing_mods.py`：真实 HTTP 503、失败项重试、手动文件校验、CurseForge 元数据恢复、缺失清单保存，以及磁盘/校验/非模组错误不可跳过。

- [x] `test_room_preparation_controller.py::RoomPreparationControllerTests::test_room_history_retry_reuses_task_and_refuses_a_disconnected_room`：房间重试沿用原任务，已断开的房间拒绝重试。

运行入口：

```powershell
python -m pytest -q tests/test_download_transport.py tests/test_room_mod_installation.py tests/test_modpack_import.py tests/test_loader_catalogue.py tests/test_download_concurrency.py tests/test_room_preparation_controller.py
python -m pytest -q tests/test_download_ui.py tests/test_room_lobby_ui.py tests/test_loader_source_ui.py
```

默认使用隔离的 Qt 环境；设置 `QT_QPA_PLATFORM=windows` 可在 Windows 桌面查看自动操作，`BUGGCRAFT_UI_OUTPUT` 指定操作记录及截图的保存位置。测试资源不是真实 Minecraft，不能据此宣称已完成真实游戏启动或多人游戏验收。
