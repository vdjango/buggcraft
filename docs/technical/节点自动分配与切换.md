# 节点自动分配与切换

登录完成、每次启动器恢复已保存登录时，后台获取固定公钥的联邦节点并测速，选择可连接且有可用容量的最低延迟节点。测速使用应用层三次小消息往返的中位数，不使用 ICMP，不把 SSH 登录或房间列表加载时间当作延迟。节点全部满载时保留目录查询能力，创建房间仍受容量限制。

打开大厅的“切换节点”可以查看在线节点、地区、延迟和当前选择。点击节点后直接切换线路，复用现有账号授权，无需在每个节点重新登录。离线节点不显示。手动选择在本次启动期间保留；节点失联或无法接纳连接时仍允许故障回退。已有房间期间禁用手动切换，已有游戏连接不迁移。

“自动选择最快”会清除手动选择并重新测速；“重新测速”更新列表并保留手动选择。重新启动后再次按当前网络情况分配，避免长期使用上次的线路。登录验证已经取得的首次测速结果会复用，避免马上再测一次。

所有网络请求、节点发现和测速运行在联机工作线程；界面通过完成信号更新。旧任务通过独立代次标识丢弃，切换账号后的旧结果不能覆盖新结果。账号过期时先续期，再完成待执行的自动分配。

大厅、创建和加入房间统一使用自动连接，用户无需选择联机方式。房主与每位访客均先尝试 P2P，无法直连时由联机组件自动回落到节点中转；界面仍展示实际使用的线路。旧界面遗留的仅中转参数不再影响启动器的新连接。

需要配套的原生联机组件，能力列表须包含 `node.select`。旧组件会明确提示更新。此次只修改源码和本地原生组件，未发布安装包。

## 原生桥接口

- `node.add` 增加 `selection: "latency"`：首次探测直接按延迟分配，未传时兼容原来的综合选路。
- `node.routes` 增加 `auto`：清除手动选择并按延迟分配；`refresh` 指定是否强制重新测速。
- `node.routes` 的节点项增加稳定的进程内 `index`、`region`、`selected`；仍不返回地址或凭据。
- `node.select` 接收原有 `node` 句柄和节点 `index`，保留该句柄的账号身份，返回更新后的节点列表。

源码回归覆盖首次按延迟选择、下次启动重新分配、手动选择保持、失联回退、跨节点账号身份、过期结果丢弃及节点列表交互。测试均使用本地节点，无须外网下载。
