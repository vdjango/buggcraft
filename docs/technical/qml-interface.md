# 界面结构与迁移范围

2026-10-20：联机大厅完整迁为 QML，包括创建、加入、好友、房间连接详情和节点管理。原启动游戏、下载、设置、实例页面保留 Widgets 与已有布局；本轮没有迁移这些页面。

## 操作与页面

|页面|主要操作|下一步|
|---|---|---|
|大厅|邀请码加入 / 创建房间 / 开放列表加入|进入独立操作页面|
|创建第一步|在游戏内开放世界、查找世界、确认端口|真实状态探测成功后进入第二步|
|创建第二步|房间名称、是否公开|创建并显示邀请码与下一步指引|
|邀请码加入|粘贴邀请，默认使用首页游戏实例；可选择已安装实例|自动读取元数据，连接成功后显示游戏菜单操作|
|好友|加入、编辑昵称/邀请、添加|连接操作与表单各自独立|
|已有房间入口|仅在存在活动连接时显示，选择当前连接|进入当前房间详情|
|房间详情|分享邀请 / 游戏直连 / 离开|分清主机和访客的下一步|
|节点|导入、选择、导出、移除|只影响后续联机|

每页保留单一主要任务，避免创建参数、邀请码输入、好友列表与操作说明全部挤在一个区域。创建说明分为编号步骤，端口默认折叠，版本和加载器自动读取。大厅移除单项导航菜单；创建、加入流程隐藏大厅搜索和浮钮，仅保留返回入口与当前任务。

标题栏不再显示品牌图片；二级页的无边框返回箭头放在标题栏左侧，最小化和关闭在右侧。房间详情点击返回先弹出断开确认，取消保留连接；确认后房主关闭房间、访客退出。好友编辑使用同一位置返回好友列表。已有房间入口仅在存在活动连接时显示；空记录的控制器导航自动回大厅，取消与无效邀请不会生成记录，关闭和退出后清除记录。

2026-10-19 补充：创建和加入均使用 `InstancePicker.qml`，与首页版本选择双向同步，移除版本、加载器及其版本的手填控件。加载器、继承版本与模组摘要由 Python 自动读取。游戏运行时固定使用启动时的实例，退出后恢复首页当前选择；更换实例使尚未完成的世界探测结果失效，已建立的连接保留。原版状态返回的版本与所选实例不一致时，创建被阻止。没有安装实例时提示先下载或导入。

保留当前页面布局，复用首页 Minecraft 背景、蓝紫色边框和按钮、像素品牌字；正文使用字体文件真实 family 名 `Source Han Sans CN`，避免不存在的 `Source Han Sans CN Normal` 回退到像素字体。长列表的选择弹层限制高度并支持滚动。

2026-10-19 交互细节修正：首页版本弹层和共用下拉框区分当前值与悬停项；当前值使用紫色背景、左侧标记及勾选，悬停使用较浅背景，键盘焦点单独描边。首页每次展开从当前目录刷新版本文件，清除失效缓存；切换目录先同步路径，再同步版本，空目录清空选择并显示下载/导入指引。一次点击只激活一次；支持方向键、Home/End、回车、Esc，长列表滚动且限制在屏幕内。弹层外点击继续交给目标控件处理；空弹层拦截快捷键覆盖事件，防止大厅的 Esc 快捷键抢走输入。主窗口退出前先卸载 QML，避免 QObject 销毁时出现空上下文错误。

2026-10-21 大厅布局：顶部以独立状态栏显示节点选择、连接状态和刷新；第二行合并创建、加入、已有房间、房间数量和搜索，控件固定高度并垂直居中，不再重复显示“公开房间”标题，下面直接是房间列表。首次加载 20 条，滚动触底或点击继续加载，搜索由节点过滤全部公开房间，旧节点通过兼容路径分页筛选。需要邀请码的公开房间同样点击“加入”，以弹窗收集邀请码。房间详情隐藏大厅操作区；复制成功在原按钮反馈。好友从启动器首页或大厅右下角的 `FloatingFriends.qml` 浮钮另开独立窗口；浮钮支持拖动、边界约束、键盘打开和点击/拖动区分，仅在大厅列表页显示，避免覆盖创建表单、节点操作或聊天发送栏。统一像素品牌、首页暗紫色与清晰字号。

节点可用性是独立状态，初始为不可用；成功取得房间目录后才允许创建和加入。无配置、坏配置、连接检查未完成、目录请求失败及后台检查失败均禁用相关控件，Python 入口同步检查。15 秒后台检查只更新状态，不刷新表单或重置分页；切换节点、刷新或移除节点会使旧请求结果失效。正式测试见 `tests/test_room_node_availability.py` 和 `tests/test_lobby_layout.py`。

2026-10-20 房间聊天：连接详情页增加随页面伸缩的房间内消息列表和发送框。后台按活动房间保存有界消息状态；用户消息需节点确认才清空草稿，失败时保留可重试文本。SDK 以独立加密 SSH 子系统传消息，游戏桥只在房主端连接本机 vanilla LAN 世界。正式 `tests/test_lobby_layout.py` 检查紧凑大厅及独立好友窗；`tests/test_room_chat.py` 覆盖聊天隔离、重连历史、权限/限速；`tests/test_game_chat.py` 在真实本地 1.21.8 世界中覆盖四角色双向消息、10 轮和重连。

空安装目录不再自动弹出阻塞对话框：首页主按钮显示“选择游戏 / 请下载或导入游戏”，点击进入实例页，保留原页面布局。

## 代码

- `resources/qml/multiplayer/`：页面以及共用按钮、输入框、选择框、表面、说明文字、步骤组件。
- `WindowHeader.qml` / `HeaderAction.qml`：大厅和好友窗共用标题栏。一级页显示窗口名称；二级页使用无边框返回箭头与页面标题同排，正文不重复标题；最小化、关闭保持轻量图标，键盘焦点有可见提示。创建/加入使用底部取消及主操作。
- `src/buggcraft/ui/multiplayer_controller.py`：QObject 状态和操作接口，处理后台任务结果、连接状态、本机好友与节点；邀请密钥不进入公开列表或通用 QML 状态。
- `src/buggcraft/ui/dialog/MultiplayerDialog.py` 与 `FriendsDialog.py`：大厅和独立好友窗的 QQuickWidget 宿主；关闭大厅/好友窗保留连接，退出主启动器释放服务。
- `src/buggcraft/hookup/`：纯 Python 网络与存储；不依赖 QML 排版。

使用 [Qt 官方 QQuickWidget](https://doc.qt.io/qtforpython-6.8/PySide6/QtQuickWidgets/QQuickWidget.html) 在现有 Widgets 启动器中承载 Qt Quick，按窗口尺寸自动调整根组件。保留原有联系人配置路径及数据格式。

## 回归与打包

    python multiplayer-tests/ui_integration.py
    python multiplayer-tests/launcher_smoke.py
    python buggcraft/build.py --dry-run

前两个命令在工作区根目录运行。界面测试实际点击 QML 控件并通过键盘粘贴填写表单，覆盖输入纠正后错误清除、输入不被状态刷新覆盖；使用本地加密节点、真实 LAN 报文与状态探测/回显测试端，执行连续十次加入、64 KiB 数据校验及离开。此项不代替游戏角色验收。主窗口测试覆盖页面切换、原有几何布局、启动状态、Java 搜索中关闭及联机后台清理。

`build.py` 默认输出独立目录，可加 `--onefile`。按 [Nuitka 官方配置](https://nuitka.net/user-documentation/user-manual.html) 包含 QML 插件、Qt Quick 模块及资源目录，移除旧脚本中排除全部 Qt DLL/插件的参数。本轮只检查构建参数，尚未编译或验证签名安装包。

## 创建房间与聊天选项

公开范围与加入权限分别控制：私密房间不出现在列表并始终需要邀请码；公开房间展开“加入需要邀请码”开关。受保护的公开房间仅在列表展示资料，节点不向目录访问者返回加入密钥；统一的“加入”按钮打开带房间名称的邀请弹窗。旧节点未声明 `room-invite-policy-v1` 能力时，拒绝发布受保护的公开房间并提示更新，避免无效保护。

创建房间的第一步将“游戏配置”与“局域网世界”分成两块：配置与首页同步，世界区域仅放查找、说明和单选列表；手动端口采用文字入口，点击才展开。“先创建房间”固定在底部左侧，确认世界的主操作固定在右侧，不随世界列表滚动。第二步先填写房间名称与公开范围，再选择是否同步游戏聊天；默认关闭，开启时明确说明会增加一个占用人数名额的虚拟玩家，并显示英文名称输入与规则。关闭后保持大厅聊天，重连和重新选择世界不会绕过开关。界面与行为分别由 `tests/test_lobby_layout.py`、`tests/test_room_launch_flow.py`、`tests/test_room_chat.py`、`tests/test_game_chat.py`、`tests/test_game_chat_ui.py` 覆盖。
