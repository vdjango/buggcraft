# 房间准备、玩家进度与管理：功能方案及验收清单

日期：2026-10-28。准备房间、实例锁定、成员进度、安装日志、日志授权、踢出与管理权转让已实现；测试结果和仍需实机补验的边界见第 9 节。勾选仅代表对应描述的范围，不把夹具测试等同于公网验收。

## 1. 要解决的体验

房主选定自己的游戏实例即可创建房间。朋友进入房间后，直接同步安装所需游戏、加载器、模组等，不需要房主先导出、上传整合包，也不需要房主先启动 Minecraft。

房间是大家一起准备、等待和交流的地方。房主能看到每个人的进度，可以先进入游戏，也可以去做别的事情，完成或失败时收到通知。准备完成的玩家可以继续留在房间，不被强制启动游戏。

用户界面只说清楚当前情况和下一步，例如“朋友正在准备游戏”“还差 2 位”“已准备好”“世界尚未开放”。下载清单、校验值、协议字段等留在开发文档与可展开的诊断详情。

## 3. 完整使用流程

### 3.1 房主：选实例，开房，随时玩

1. 从联机大厅点击“创建房间”，选择已安装实例，填写名称和加入方式。
2. 默认入口是“创建房间，邀请朋友准备”；已有局域网世界时可选择“关联已开放的世界”。没有运行游戏时，创建不依赖世界端口探测。
3. 点击创建后，后台读取配置并生成房间清单。显示正在扫描的真实阶段；失败时允许重试，不发布缺少必要内容的配置。
4. 房间创建成功后，显示“游戏配置已锁定”和版本、加载器、模组数量。房间锁定的是创建时选定的实例，而不是首页当前选中的版本。
5. 分享邀请码或邀请好友。对方进入准备房间就能核对配置、同步安装、聊天和查看人员，不要求房主在线游戏世界已经开放。
6. 房主可随时点击“启动游戏”，从房间锁定的实例进入 Minecraft；其他人的安装继续进行，不阻塞房主。
7. 房主打开世界并对局域网开放后，验证世界与锁定配置匹配，再关联到当前房间。支持自动检测与手动选择，多个世界时明确选哪一个。
8. 玩家准备完成、安装失败或全部准备完成时，房主收到通知。可以留在游戏或最小化启动器，不必一直盯着大厅。

“锁定配置”不锁死房主的操作，也不自动禁止游戏启动。更换配置是显式操作：有人正在安装时先说明影响并确认；生成新清单版本后通知所有人重新核对，旧任务不得被误报为新配置已就绪。游戏世界运行期间不悄悄切换配置。

大厅按房间设置展示房间，不以是否启动 Minecraft 作为公开条件。公开房间在大家下载、安装客户端且世界尚未开放时显示“准备中”；关联已开放的世界后显示“世界已开放”。两种状态都保留加入入口：需要邀请码时验证邀请码，否则直接加入；私密房间不进入公开列表。“准备中”描述世界状态，不代表每位玩家都正在下载；个人安装进度在房间成员页查看。

### 3.2 其他玩家：先进房，准备好再玩

1. 通过大厅、好友邀请或邀请码进入房间，先出现在成员列表中。
2. 自动核对本地配置并展示差异。已有匹配配置时复用；需要补齐时提供“同步安装”和“选择已有配置”，确认后开始。
3. 下载和安装全程留在房间，展示阶段、总体情况、文件列表和日志。可收起详情、聊天、最小化或暂时关闭大厅窗口，任务仍继续。
4. 只有必要文件安装、校验和实例发布完成后，才显示“已准备好”。可选资源失败显示“已准备好，有可选资源未下载”，不误标成全部成功，也不阻挡联机。
5. 世界未开放时显示“已准备好，等待房主开放世界”；可以留在房间，也可以启动游戏到主菜单。不要对未开放世界反复尝试连接。
6. 世界开放后，显示“进入游戏”。已在主菜单的玩家获得明确连接入口；自动进入只在玩家明确选择后执行，不能强制启动或打断其他游戏。

### 3.3 房主不用干等

- 房主成员栏实时显示“未开始 / 核对中 / 下载中 / 安装中 / 校验中 / 已准备好 / 启动中 / 游戏中 / 失败 / 已取消 / 连接中断”。
- 顶部汇总“2/4 位已准备好”，将房主本人计入，并标出需要处理的失败或缺失资源。
- 单人就绪、全部就绪、安装失败和世界开放各产生一次状态通知；不要每次进度变化都弹通知。
- 大厅未打开或启动器最小化时发送桌面通知；成员页保留最近 30 条准备结果供返回后查看。系统通知点击跳回指定成员尚无专门实机证据，不计完成。
- 声音沿用设置中的提示音开关，关闭时仍有视觉通知；连续多人完成可合并，不能反复播放同一事件。
- 房主正在全屏游戏时也不抢焦点、不强行打开大厅；完成后有结果可查。

### 3.4 状态分别记录

房间是否存在、世界是否开放、每个人是否准备好是三件独立的事情。不得继续用一个“等待中”同时决定所有按钮能不能操作。

| 状态维度 | 状态示例 | 对操作的影响 |
| --- | --- | --- |
| 房间会话 | 创建中、在线、重连中、已关闭 | 在线即可显示成员、聊天和准备；重连保留任务结果并同步状态；已关闭终止关联任务 |
| 世界可用性 | 未启动、启动中、等待对局域网开放、可进入、提供者离线 | 决定是否可以进入世界，不阻止其他人下载和准备；房主启动不以所有人就绪为前提 |
| 每位成员的准备 | 未开始、核对中、下载中、安装中、校验中、已准备好、失败、已取消 | 由该成员实际安装与校验结果决定；游戏中和启动中另外记录，不能用“进房在线”代替准备完成 |

新的清单版本发布后重新核对必要内容；已安装文件可复用，但旧版本“已准备好”不直接沿用。可选资源仍在下载时，可将成员标记为“已准备好，正在补充可选资源”，不阻挡已满足必要条件的玩家进入世界。

## 4. 页面布局与交互

沿用启动器现有深紫背景、紫色主按钮、浅色文字、卡片边框、字体和间距。复用 `Surface`、`ActionButton`、`ChoiceBox` 等现有组件，不另起一套视觉风格。

### 4.1 创建房间页

- 主要区域：房间名称、实例选择、公开/邀请方式、配置摘要。
- 次要折叠区域：“已有开放世界”，用于选择局域网世界或填写端口。
- 主按钮：“创建房间”；按钮旁用一句话说明“朋友可以先进来准备游戏”。扫描、创建中显示明确状态并防止重复提交。
- “锁定配置”展示版本与实例名称，详细模组和资源清单可展开查看。

示意图是区域安排，实际沿用现有组件和窗口尺寸，不照着字符宽度实现。

- 聊天放在第一位并默认展示；成员和安装详情按需切换，避免在有限窗口堆满重复状态。好友邀请统一从好友列表操作，房间不再重复放邀请按钮。
- 721×505 和 1000×650 共用页签布局；顶部主操作保持可见，长名单和日志各自滚动。自己不在下载时不显示假进度条。
- 主操作由自己的状态决定：房主“启动游戏 / 查看游戏”，客机“同步安装 / 启动游戏 / 进入游戏 / 重试”。取消只取消自己的安装任务，不顺带退房或关房。
- 自己、房主、世界提供者有明确标识；玩家状态、P2P/中转和失败信息同时使用文字与颜色，不能只靠颜色辨认。
- 进度使用平滑过渡；通知做短暂强调；加载使用现有动效。聊天输入、日志阅读和成员菜单操作时不因进度刷新丢失焦点或滚动位置。
- 教学仍限制误点，新增房间操作不得绕过已有教学交互锁。

### 4.3 安装详情与日志

- 房间里提供完整安装任务面板：Java（需要时）、Minecraft 本体、依赖库、游戏资源、加载器、模组、资源包、光影、配置文件、最终校验。
- 总体进度只在工作量已知时显示准确百分比；未知大小时显示“正在获取文件清单”或阶段指示。切换阶段不伪造 100%，资源阶段完成也不能代表整个任务完成。
- 显示已完成/总文件数、已下载/总大小、实际速度、当前并行文件和当前步骤；无法可靠计算的剩余时间不显示数字。
- 展开日志复用现有游戏日志样式及搜索/过滤交互，数据使用安装任务事件。可按分类、信息/警告/错误过滤，可复制、导出，自动跟随可开关。
- 必要文件失败定位到文件和下一步操作；取消、重试与断线恢复有明确结果。重试只补未完成或校验不通过的内容。
- 房主能查看成员的阶段、速度、进度、简要失败原因及更新时间；默认不上传或展示对方完整本机日志、绝对目录、账号、令牌和接入码。

## 5. 房间成员与基本管理

### 5.1 成员列表与线路

- 使用真实房间成员身份和稳定成员 ID；包括未启动游戏的玩家，不从游戏服务器人数猜测。
- 每位成员显示名称、本人/房主标记、准备阶段、下载进度、已准备状态、游戏状态及最后更新时间。
- 连接方式按成员分别显示“P2P 直连 / 中转 / 正在连接 / 尚未测得”。一个房间允许不同玩家走不同线路，房主的 `auto` 不作为所有玩家已直连的证据。
- 延迟标明测量对象，优先显示客机到世界提供者的实际可用链路 RTT。控制节点 RTT 只能放在详情并标明“节点延迟”；未测得显示 `—`，不填 0 ms。
- 世界尚未启动时仍显示可测量的准备通道状态；若只能获得节点延迟就明确标注，不将其命名为游戏延迟。房主本人到自己不显示虚构网络延迟。
- 成员离开、网络断开、重新进入及 P2P/中转切换及时更新；失联进度变灰并显示“连接中断”，不让旧百分比一直冒充实时数据。

### 5.2 踢出玩家

- 房主在成员行菜单选择“移出房间”，确认后移除对应成员；普通成员无管理权限，不能靠构造 RPC 绕过。
- 节点校验房主身份、房间与目标成员 ID，向双方发送结果；停止该成员游戏会话、房间文件传输和进度上报，其他玩家不受影响。
- 被移出方清楚看到原因，安装停止，不删除已经安装成功的实例。未完成文件按任务取消规则清理。
- 公共邀请码仍有效时，被踢玩家不能马上原样重进：以该房间会话身份记录禁止重新加入；房主可解除限制。未绑定账号的接入明确说明识别边界，不承诺账号级永久封禁。

### 5.3 转让房主

- 成员菜单提供“转让房主”，接收方须在线且确认接受；取消、拒绝、过期或断线不改变原房主身份。
- 成功后所有成员的房主标记和管理权限一致更新；踢人、房间设置、邀请管理、关闭房间的权限一起转移，原房主不能继续使用旧权限。
- 把“房间管理者”和“世界提供者”分别建模。转让房间管理不自动搬迁 Minecraft 世界；原世界提供者继续运行游戏和必要文件服务，下载与游戏不应被转让动作断开。
- 确认文案明确“转让后由对方管理房间，当前世界仍由你提供”。原世界提供者之后退出时提醒世界将不可用；保留准备房间并显示等待重新开放世界。
- 更换世界提供者必须由新提供者明确绑定兼容世界；不承诺运行中的存档无缝迁移。准备清单同步更新时按配置版本处理，不静默替换正在玩的世界。
- 房主离线不凭空完成未经授权的转让；普通断线提供重连宽限。原世界提供者不在线且某些私有资源没有可用来源时，如实显示受影响文件。

## 6. 配置、下载与 C++ 桥联动

1. **统一清单**：整合包导入/导出与房间同步共用游戏版本、加载器、文件身份、来源和校验定义；房间自动生成小清单，不额外要求用户导出或上传压缩包。
2. **必要与可选**：游戏版本、加载器和房间声明的必要模组/公共配置属于准备条件；资源包与光影默认可选，允许不下载且不阻塞就绪。展示实际可选下载结果。
3. **稳定版本**：房间保存实例绑定、清单版本和指纹。共享配置冻结为快照引用；锁定后本地增删文件要提示重新锁定，不能偷偷改变别人正在安装的内容。正在下载的清单对应的实际文件若变动，明确失败或重新同步，不分发与清单不符的字节。
4. **分享边界**：只分享显式允许的公共模组配置；世界存档、截图、账号、服务器密码、令牌和启动器设置不自动进入房间共享。必要公共配置须列入同一清单和校验流程，不能只有模组文件一致而配置缺失。
5. **来源顺序**：本地已校验缓存 → 玩家设置的下载源及既有公开源回退 → 成功建立 P2P 直连后才可向世界/资源提供者取文件。继续遵守房主允许文件分享及限速设置；不通过中转传资源文件。
6. **无源资源**：没有公开下载源且不能直连时，显示具体文件缺失、原因及重试办法；必要内容未齐不能报“已准备好”。可选内容可跳过。不要为了声称“自动同步成功”绕过直连限制。
7. **无需先开游戏**：房间控制、成员身份、清单获取与准备进度不能依赖游戏端口开放；房间存在但世界未开放时，独立建立允许的准备连接。桥已有端口 0 入口仍需实测此链路，不能由参数支持推定所有功能可用。
8. **职责**：启动器负责实例安装、UI、任务日志和进度采集；C++ 桥负责会话、连接、P2P、中转、房间事件及节点通信；节点控制服务负责成员身份、管理权限、状态路由与联邦一致性。`web/tunnel` 的目录控制层不等于恢复旧 Python 联机传输。
9. **进度消息**：设计房间成员事件，包含房间、稳定成员 ID、清单版本、任务 ID、递增序号、阶段、字节数、状态和更新时间。节点绑定真实会话发送者，不能代他人上报；限制字段长度和频率，过滤凭据及本地路径。
10. **一致性与重连**：节点有可恢复的当前成员快照和有序事件；重连重新拉取快照。旧任务/旧清单的迟到进度不覆盖新任务，重复事件不重复提示，显示陈旧状态的时间界限需协议化。
11. **能力声明**：桥和节点新增准备房间、成员进度、管理权限转让等能力声明。旧节点缺能力时明确提示升级，隐藏不能执行的操作，不显示假成功，也不影响已有基本联机。

已实现的方法、字段、频率和超时以原生仓库 [room-lobby.md](../../../minecraft-tunnel-native/docs/protocol/room-lobby.md) 为准，Web 开发者页同步介绍 `room-lobby-v1`、授权与兼容边界。
