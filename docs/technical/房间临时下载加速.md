# 房间临时下载加速

房间同步、导入/下载整合包共用已校验文件、断点和缺失文件处理。单个必需模组失败不取消其他文件；房间最多六轮自动补齐，完成资源不重下，仍有缺失则不能发布或启动不完整配置。

房主开启“允许文件共享与临时下载加速”后，启动器只先提供文件信息。正常来源优先直下，缺失或持续过慢的文件按源站清单补齐。客户端不需要管理“上传客户端”，也不显示精确到期、倒计时、清理通知；通常 8 小时保留只作说明。缓存到期或源站临时不可用时继续选源和保留断点，下载者无需登录源站。

共享内容可被他人获取，包括未公开模组。界面明确提示敏感或不希望公开的内容请勿开启共享。上传权限仅由已认证节点核实，不能匿名任意上传。

节点用 `content_cache_grant` 返回 HTTPS 源站地址和房主短期令牌；不支持此操作的旧节点继续原有流程。独立导入默认查询官方 `https://mirror.bugg.icu`，可通过 `BUGGCRAFT_RESOURCE_ORIGIN` 更换公开源站；加入已配置节点的房间后也会学习该地址。整合包修复只查询已有 SHA-1、大小匹配的缓存，不凭文件信息生成不存在的文件，也不取得上传权限。

自动房间下载排除 Modrinth、MCIM，不在请求路径逐个测速。Modrinth 手动入口说明速度极慢，MCIM 标明不推荐。CurseForge 已知同哈希文件不会再额外查询 Modrinth；`mediafilez.forgecdn.net` 不替换成 MCIM。

整体规划、服务端部署、空间预算、后台页面、跨房间 TTL 和验收结果见资源源站项目 `docs/房间客户端文件兜底实施规划.md`。本项目源码用例：`test_room_cache.py`、`test_room_mod_installation.py`、`test_room_preparation.py`、`test_modpack_missing_mods.py`、`test_content_routes.py`。

2026-11-01 验证：包含 220 个模组、单项失败后继续下载及只重试缺失项；真实本地 HTTP 取消续传、公开读取与哈希匹配；旧节点与原生桥兼容。合入现有房间体验改进后，大厅布局、整合包缺失处理、源站客户端和下载错误展示共 96 项测试通过。测试在打包前执行，主分支产出直接晋升开发版 `v1.0.2-alpha.1`，不在打包后重复运行游戏或资源下载测试。
