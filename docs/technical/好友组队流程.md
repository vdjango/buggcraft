# 好友通知与组队

首页“好友”展示待处理数量，新消息触发一次高亮；打开好友窗口后首页停止高亮，对应页签继续提示，切到该页后停止。新的申请或邀请会重新提示。普通好友申请使用紫色，联机邀请和加入申请使用粉色，后两者优先。声音由项目脚本独立合成，设置中可关闭；轮询相同事件不重复播放，连续通知合并提示。

好友列表区分在线、房主、联机中和等待世界开放。可加入的房主旁显示“申请加入”，申请后显示“等待同意”；房主在“加入申请”页同意后，申请人收到联机邀请并可直接加入。拒绝、过期、房间关闭和网络失败均有对应状态或提示。

创建房间前可以依次邀请多位好友，按账号分别排队；房间和世界就绪后逐人发送，单个请求失败不修改其他好友的邀请状态。节点邀请也按 `(房主, 好友)` 分别保存。

## 节点配套

通知角标、提示音和多人待发队列兼容旧节点。房间状态和申请加入依赖相邻 `minecraft-tunnel-native` 仓库中以下更新：

- `web/tunnel/social.py`：带房间信息的签名 presence，`request_join`、`accept_join`、`decline_join`，申请存活 120 秒，邀请存活 300 秒。
- `web/tunnel/directory.py`：验证真实房主或成员身份，通过现有联邦路由转发私密房间的申请。
- `bridge/social.cpp`：连续签名操作使用递增的毫秒时间，避免同一秒内的重发被旧状态覆盖。

节点通过 `capabilities.room_presence` / `capabilities.join_requests` 声明支持。旧节点不展示无法执行的申请入口，收到房间密钥仍需有效邀请；好友状态不包含房间密钥。

本地验证包含多个原生进程同时加入并传输游戏数据，以及跨节点私密房间的申请、批准和邀请获取；这不等于远端生产节点已部署。
