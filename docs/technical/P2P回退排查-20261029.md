## 证据与结论

输入为 `p2p转中转-RIZ2.zip`（62 项）和 `p2p转中转-房主.zip`（24 项），以及三张截图。归档中的说明文字只作为现场材料。未改动正在发布的主工作区、发布工作流或生产节点。

原生心跳旧实现每 5 秒发一次探测，但只接受最新序号的回复。回复超过 5 秒、跨过下一次探测时会被丢弃；持续发生可在 20 秒后把仍有回复的连接判死。这是源码与确定性回归可复现的缺陷。旧日志未逐条保存被丢弃的心跳，因此不能断言每一次超时都是该缺陷造成。归档网络类型为 unknown，也不能从单个 NAT 标签推断任意两个人都能打洞。

信令关闭旧实现会主动关闭客户端 PeerConnection，服务端发出的 `left` 也会令房主关闭对应连接，即便已有游戏数据通道健康。该问题与归档的 `signaling-closed` 回退路径一致。

## 修复

- 原生桥保存有界的未完成心跳探测记录，接受仍有效的迟到回复，拒绝重放、未知及过期回复；按已测 RTT 调整失活窗口，范围 20–60 秒。默认低延迟下仍为 20 秒，单向断链仍会回退。
- 信令短断保留已连接的 P2P；用非阻塞通道状态机恢复信令，单次建立超时 5 秒，失败后间隔 3 秒重试。游戏连接不因信令重新就绪而重复协商。真实直连失效仍由心跳和传输状态处理。
- 心跳超时记录增加 `rtt_ms`、`replies`、`probes` 和实际超时窗口；信令关闭记录 `p2p_preserved`。
- 原生节点路由切换时保留最初导入的个人身份。旧实现可能被拓扑中的匿名节点凭据覆盖，进而由本地桥抛出 `A personal launcher credential is required`。这条消息本身不能证明用户接入码过期。跨联邦路由仍校验固定节点公钥；网络发送的认证信息剥离 `~` 后的本地签名私钥。
- 对明确的个人凭据缺失、过期、无效及节点认证拒绝，启动器显示一次恢复弹窗；“前往更换接入码”进入节点页并给出网页登录、领取、粘贴、确认更新的指引。大厅和缓存好友列表均保留更换入口，成功同步或更新身份后清除警告。普通网络超时不会冒充接入码过期。
- 房间目录不可达显示中文刷新/切换在线节点的指引，与个人凭据问题区分。

## 延迟含义

截图中的“节点 1092 / 1192 ms”在旧原生实现实际来自整次 `room.list` 操作，包含 SSH 连接、认证、路由刷新和房间查询，既不是纯网络 RTT，也不是玩家 A → 节点 B → 房主 C 游戏的延迟。

修复后，桥程序在认证和探测通道准备完成后连续发送三次回显请求，以往返时间中位数作为 `node_latency_ms`，并以 `node_latency_method=application-echo` 标识；`connect_ms` 仍保留整个操作耗时。房间连接期间每约 4 秒更新节点回显延迟。无法取得有效样本时显示不可用，不使用房间列表查询总耗时兜底；真实的 0 毫秒样本仍可显示。大厅单独展示到节点的延迟，加入房间后通过游戏线路测量到房主的往返延迟；中转连接包括中转节点和房主之间的链路。该测量使用应用回显，不使用 ICMP。

原生 `game_rtt_ms` 使用本地转发端口上的 Minecraft status ping，若该游戏支持状态探测，才会随实际数据路径经过直连或中转；`peer_rtt_ms` 是 P2P 应用心跳，`control_rtt_ms` 是节点控制请求。它们的对象不同，不能互相替代。中转时完整路径是 A → B → C → B → A，通常还包含处理与排队；P2P 数据直接在 A、C 之间传输，节点负责协调。
