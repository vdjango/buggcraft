# 可选账号、无主心跳与源站保护

更新：2026-10-21。匿名联机和账号体系互相独立：只在启动器添加 A，A 属于联邦时即可缓存备用入口、发现其他节点房间；不用注册，也不用登录其他节点。尚未成功连接过 A 的全新启动器没有备用缓存；入口全不可达时无法凭空发现网络。

## 独立与联邦

独立节点不向其他节点同步，可发放自己的匿名接入码、可自行决定开放用户注册。联邦节点经管理员邀请加入，发现和同步同网络节点。公开联邦表示参与该网络的目录同步，不表示向互联网公开数据库或允许任何未知节点加入。

控制台可退出联邦，换用新的入网密钥并停止原网络同步。其他节点等待原签名心跳过期后不再列出该节点；已被其他运营者保存的目录或加密副本无法远程收回。退出后本地已有用户副本也仍保存，管理员需按实际政策管理。

## 账号的使用

管理员默认关闭注册，可在网页设置开放；关闭只停止新注册，已有账号继续登录。登录和注册使用独立页面。用户可输入用户名或完整账号 ID；不同节点用户名重名时，必须使用完整 ID。网页可以保存加密的昵称、备忘和身份密钥，下载加密恢复文件，并领取个人启动器接入码。

注册时浏览器生成 P-256 身份密钥，以 PBKDF2-SHA256（600000 次、随机盐）从密码派生 AES-256-GCM 密钥，每次加密使用新的 96 位随机 IV，绑定账号 ID 与设置版本作为附加认证数据。密码及明文身份密钥不上传。账号登录采用一次性、60 秒过期的挑战签名，绑定节点身份、来源和账号，不把可重放的密码验证材料作为登录证明。

注册默认不备份：全网仍同步公开用户名、账号 ID、公钥、注册节点签发的凭证和用户签名的版本/副本策略，目录不包含加密包；账号只能在注册节点登录。可主动选择 1–8 个额外加密备份节点，选中的节点另存加密包。不保存或同步用户密码、密码摘要、明文私钥、浏览器会话或管理员密码。

跨节点登录先按用户名或完整 ID 查询目录，再通过固定公钥的 SSH 从可用副本取回密文，密码只在浏览器解锁身份并签名，不转发给注册节点。非持久备份的登录节点仅保留最长一小时的内存密文。它仍能接触密文；备份数量是正常节点的持久存储策略，不能限制恶意运营者自行复制。

换电脑、换浏览器也能按同一流程登录：从在线注册节点或已完成的加密副本下载身份包，重新输入密码解锁，不依赖旧设备。浏览器不把密码、私钥或解密资料写入 localStorage/IndexedDB；解锁后的资料与密码仅留在当前页面内存用于签名、重新加密，退出时清除引用。登录 Cookie 是短期会话凭证，不能替代备份或密码。密码独自不能重建随机生成的身份密钥，所以没有任何在线副本时仍需恢复文件。

副本数量表示“注册节点 + N 个额外节点”。每个节点按账号与在线节点身份确定目标，无需主节点；注册节点失效也补足它的一份。旧目标收到新目标已持久保存最新版本的心跳确认后才移除移交副本。故障、分区和移交期间可能暂时多于或少于目标数量，网页显示实际在线确认数。没有任何现存副本时无法自动恢复。

同步策略与加密设置一起由用户签名，其他节点不能自行提高数量。关闭备份需要注册节点在线；正常副本随后删除，保留已发布身份的签名撤回记录，防止旧授权重新生效。公开过的用户名目录、运营者已复制的数据无法强制收回。旧版账号停止自动导出密文，登录后选择策略并加密保存才开启新的同步。

若没有副本但自己保存了恢复文件，可到仍信任原注册节点的联邦节点导入文件，以原密码解锁并证明私钥，然后选择至少 1 个备份节点并保存，重建持久副本。恢复文件、密码及所有副本同时丢失时无法找回；文件落后于已知版本时拒绝覆盖。

个人接入码最长有效 7 天，同时包含用户授权签名和节点签名，绑定账号、签发节点和网络；节点仅有自己的私钥不能伪造其他用户的授权。同联邦成员校验两者，不需要分发其他节点的全局 token。旧格式个人码需重新登录领取。接入码被窃取者可在有效期内冒用，应妥善保管。个人连接请求目录时返回个人凭证形式的备用配置。管理员本地禁用账号会拒绝其后续个人连接并关闭现有个人 SSH 连接。全局匿名接入码仍按原有策略使用，不受账号禁用影响。

启动器添加好友时，在已选节点按用户名或完整账号 ID 精确查询。只返回公开用户名和账号 ID，不返回密文、密码、登录凭证或网络地址；入口节点合并当前可达联邦成员的公开身份目录，查找好友不要求开启加密备份。未备份账号仍只能在注册节点登录。同名账号不会自动任选，需使用完整 ID。好友收藏仅写入本机；添加好友不授予房间权限，加入房间仍需符合公开设置或取得邀请。旧版昵称和邀请码收藏继续保留，可按原邀请码加入，但不能作为账号身份验证。

聊天账号由节点从已认证 SSH 连接生成，客户端传入的账号和昵称不能冒充，游戏桥接消息也不冒充账号身份。启动器按绑定 ID 标注好友。请经可信渠道核对好友 ID。当前信任中转节点对消息的身份标记，还没有客户端之间逐条签名的消息协议；账号证明控制该身份密钥，不证明现实身份。匿名用户依然可以联机、使用分布式目录，但不能自动验证“就是这个好友”。

当前启动器通过网页领取个人接入码接入账号，不在启动器保存账号密码；到期后重新领取。好友关系通过签名事件在可达节点间传播，联系人显示在当前设备；好友名单尚未随账号密码箱跨设备同步。账号加密备份只涵盖身份密钥、昵称与备忘。

当前每节点最多注册 128 账号，联邦目录和副本最多 512 账号；后台全量有界交换适合当前小规模网络，不声称适合无限账号。设置更新采用用户签名和单调版本，冲突时确定性收敛；并发修改可能覆盖，不是实时多人协作数据库。尚无密码更改、密钥吊销广播、密码找回或全网封禁。忘记密码无法代为解密；旧加密备份仍可能被其他人保留。

## 数据库被复制时的实际边界

复制节点数据库的人能看到公开账号 ID、用户名、公钥和加密包，不能直接从密文读取私密设置。弱密码仍可能被离线猜测。不要使用网站通用密码或把重要机密放入备忘。节点有自己的 SSH 私钥、匿名 token 和入网密钥，这些由节点管理账户掌握，客户端加密不会保护被完全攻陷节点的运行密钥。

节点运营者能修改网页脚本，因此可以窃取用户在该网页输入的密码。请只在可信节点登录。账号协议已做集成测试，尚未经过独立安全审计；客户端加密不保证恶意网页安全。后续可由签名发布的客户端完成解锁和签名，并使用系统密钥存储。

## 无主心跳如何维护

所有节点独立运行同步任务，约每轮结束 2 秒后再次探测已知节点；实际间隔还包含网络超时。每台节点生成自己的签名状态，其他节点验证来源及新鲜度，重复转发旧签名不会延长租约。活跃节点约 10 秒过期，不需要主节点或选举。

网页区分“直连正常”“其他节点见到心跳”“暂时不可达”“离线或尚未连通”和“已隔离”，显示本机观察到的心跳年龄。节点故障或网络分区时，不同节点可能暂时得出不同结果：不可达不等于证明机器关机。维护入口和游戏转发使用本地判断，不等待全网统一宣布故障。

当前最多 32 节点，通过有界全互联拉取与签名转发工作；不是完整 SWIM、Raft 或强一致故障检测器。节点扩大时需改成增量同步、随机探测和间接探测，不能把目前的全量轮询无限扩容。

## IP 隐藏与抗 DDoS

公开网页及公开状态不返回连接地址。控制台成员列表显示名称和身份指纹，启动器节点选择器显示节点名称；加入或创建房间后锁定选择，退出全部房间后恢复。接入码是可解析的连接配置，不是对使用者保密的地址加密；JSON 导出、目录拓扑和运行中的网络连接仍包含实际对外入口。加密传输不隐藏 TCP 目标地址。

真正隐藏源站需要独立的公网 TCP 代理/防护入口，并使源站只允许可信代理网络访问。网页另外需要 HTTPS 代理域名；只代理网页不能保护游戏 TCP。联邦其他节点也可能观察到探测连接的源 IP，若要向这些运营者隐藏源站，还需要受控出口隧道、专用中转或覆盖网络。域名本身不能隐藏其解析出的服务器。

本次没有可用域名、代理或第二台中转服务器，因此只预留入口配置，不封锁现有网站和 SSH，也不宣称源站已隐藏。同一服务器的三个测试节点仅用于多节点验证，不增加故障域。当前公开使用过的测试 IP 不能靠换成域名消除历史暴露。

生成节点时可分别设置监听端口和公告的代理入口：

    python deploy/init_node.py --directory config/protected-node --public-host web.example.com --port 3334 --web-port 18443 --entry-host tcp-proxy.example.com --entry-port 443

已有节点可在 server.conf 的 [relay] 添加：

    entry_host = tcp-proxy.example.com
    entry_port = 443

这只修改公告地址，代理本身需要另外部署和验证。纯 TCP 透传保留原有 SSH 公钥校验。不要把普通 HTTP 反向代理当成游戏 TCP 代理；也不要在未知代理协议下向 SSH 连接插入 PROXY 头。替换实际入口后，已有启动器缓存可能仍保留旧地址，需重新分发配置、清理或更新历史缓存。

多节点降低单点影响，但同机多进程不能抵御该机器公网链路被打满；公开真实源站后也可能绕过代理攻击。需要不同故障域、独立入口、带宽防护和源站访问限制。没有“绝对无惧 DDoS”的保证。游戏中转节点失效仍会断开已有 TCP，房主重建、访客重新进入游戏。

## 节点管理与第三方启动器接入

节点网页的管理入口改为独立 `/admin` 页面；名称、在线状态与心跳分开显示，入口地址不展示。联邦成员不能远程踢出其他成员；隔离/恢复只由操作所在节点的管理员决定，只改变本机规则，不向其他节点发送封禁命令。

操作流程为选择目标、查看本地影响、填写原因、输入完整节点 ID、再次验证管理员密码；服务端另行检查会话、CSRF、目标与输入，不依赖页面按钮保护。操作记录仅本机保存，最多 100 条，不包含重新验证的密码；网页显示最近 20 条。服务器运营者可修改本机记录，这不是全网裁决或不可篡改账本。隔离不撤销已发出的玩家凭据，其他节点仍可连接对方。

当前联邦成员共享邀请权限，入网密钥泄露时，对方可能换身份加入；需要可信运营者协调建立新网络并轮换访问凭据，不能通过“隔离一个 ID”宣称阻止了全部恶意行为。

节点首页顶部和「其他启动器接入」区块均可进入 `/developers`，无需登录。文档覆盖玩家接入码、固定 SSH 公钥、目录/好友查询、游戏转发、账号挑战与 HTTP 会话；附 `/launcher-example.py` 可运行只读示例和 `/protocol.md` 协议下载。第三方启动器使用用户提供的普通或个人接入码，不需要管理员账户或联邦邀请。

## 网络级好友查找

在启动器选中联邦节点并搜索好友时，节点合并本地目录及当前可达的已知成员，不会在本地命中后跳过其他成员。朋友无需注册在同一节点，也无需开启加密备份即可被公开用户名目录查到；未备份账号仍只能在注册节点登录。网络分区可能使查询暂时不完整。同名时使用完整账号 ID。

查询只返回用户名和账号 ID，不返回密码、加密包或 IP。网络分区时可能找不到尚未同步的账号，恢复连通后可重试。发送申请后需对方同意才成为双向好友；好友状态由签名事件同步，申请和邀请会过期。加入房间需有效好友邀请且房间可用。

## 在启动器使用账号

1. 在注册节点网页打开「用户账号」。首次使用时，管理员需已开放注册；注册后保存加密恢复文件。
2. 用用户名或完整 ID 和账号密码登录网页。已开启副本时，可在同一联邦的其他节点路由到在线副本并登录。
3. 点「领取个人启动器接入码」，在启动器大厅的节点菜单中选择「添加与管理节点」，粘贴并验证。启动器只接收接入码，不接收账号密码；同一节点再次添加时会更新本机保存的凭据。
4. 个人码最长有效 7 天。在其他设备可直接粘贴该码，也可重新登录网页领取。到期后重新登录领取；丢失个人码不会丢失账号，账号恢复仍依赖密码和现存副本或恢复文件。

普通节点接入码用于匿名身份，个人码用于账号身份。两种方式都可查找同一联邦的房间；只有个人码能让房间聊天标注已认证的账号 ID。退出网页登录不会撤销已领取的个人码，请像密码一样保管，勿发给朋友或写入公开日志。

## 2026-10-21 首页与账号流程复查

首页顶部、首屏操作区及「其他启动器接入」区块均提供文档入口，无需登录。好友窗口显示当前为匿名接入、已保存个人码等待验证，或已通过连接验证的个人码接入；重复添加同一节点会替换凭据，不增加重复节点。验证失败时不保存新码。退出网页会清空页面中的接入码、密码字段与解密资料引用。

本轮通过 25 项服务端检查、50 项账号与联机协议集成检查、56 项好友/控制器/QML 检查。真实四进程浏览器测试覆盖注册、非副本节点按用户名登录、加密设置写回、个人码接入 SDK 和好友查询；桌面与手机均无脚本错误。测试过程的请求与持久副本未发现测试密码或明文备忘。Windows 故障模拟曾出现测试回显连接被重置的异常日志，回显程序已处理这类预期断开，备用入口恢复用例再次通过。

三个远程测试节点已更新并重启，成员数均为 3；逐个通过首页入口、管理员登录、独立控制台、接入文档与手机横向溢出检查。部署保留原设置，并核对既有服务的进程及运行状态未变；临时本地测试集群已关闭。
