# 语言资源与维护

启动器界面使用 Qt Linguist：C++ 的 tr/QCoreApplication::translate 和 QML 的 qsTr 提取到 assets/i18n/ts/bugg_<语言代码>.ts，构建时 lrelease -compress -nounfinished 生成 QM，LanguageService 安装唯一 QTranslator 并触发 QQmlEngine.retranslate。en_us.json 仅是开发翻译工具的历史种子词表，不进入运行时资源，也不作为新的界面翻译入口。加入新界面文案后先 lupdate，再运行 tools/update_translations.py --sync-local，校验/审校全部语言的翻译与 %1、%2 等占位符，最后重新构建。

languages.json 仅维护语言自称、地区及 Minecraft 语言代码，不含界面译文。名称参考旧版 minecraft-languages.json 和本地 Mojang 资产索引；具体游戏版本的可用语言以该实例资产索引为准。QM 作为独立语言附件发布，主程序只内置清单，不内嵌 QM。首次选择由 LanguageService 下载校验并缓存；再次离线复用。界面选项只列本版本已生成 QM 的语言，显示地区以区分同为 English 等名称的变体；Minecraft 自定义代码不能直接当成已翻译界面语言。

简体中文是源文案；其余 104 个 TS 保留原有译文；本轮新增 4 条下载提示补齐英文，其他语种标记 unfinished，由 Qt 回退中文，不能宣称全部文案已翻译。文件选择器中的扩展名掩码（如 *.png）必须逐字保持，翻译同步工具会强制恢复原掩码。覆盖检查不能替代母语审校，发布前应重点检查设置、错误、下载及联机流程中的术语与长文案溢出。路径、账号、玩家名、实例名、品牌和协议 ID 不翻译。Qt 原生对话框的系统文案还受系统/Qt 平台语言影响。

按需包、生命周期、失败/取消和发布协议统一维护于 [语言与即时设置](../../文档/24-语言与即时设置.md)。构建产物在 build 对应目录的 language-assets；不得将它们重新塞进便携包。
