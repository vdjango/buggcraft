# 游戏目录与多源适配

## 调用方向

`GameInstallPage → InstallCatalogSession → GameCatalogService → GameCatalogProvider + HttpClient`

目录与下载分开：目录统一“有哪些版本、是否兼容、默认选哪个”；将来的下载器接收明确安装计划，不重新猜版本或在页面拼接来源 URL。模组搜索的 CurseForge/Modrinth 与游戏元数据源不是同一类接口。

## 来源协议

适配器输入 `CatalogQuery`，输出请求 URL；解析只接受有结构的 JSON/XML，返回同一种 `CatalogResult`。HTML 错误页、错误对象、损坏 JSON、缺少必要字段都视作失败；空数组表示该候选无兼容版本，有限继续下一候选。请求和工作线程都携带逻辑请求 ID，取消后删除活动记录，迟到结果直接丢弃。

默认优先级 BUGG → BMCLAPI → 官方；设置只维护这一份排序，不再按资源类型分开选择。SourceSettings 负责移动/校验、异步恢复和原子保存，app 统一连接 GameCatalogService.select_sources。每次查询由工厂按查询能力解析实际候选、去重；调整顺序清理旧活动请求，InstallCatalogSession 收到通知后重查。能力矩阵和内容接口补齐规则以 [04-下载源与任务引擎](04-下载源与任务引擎.md) 为唯一依据。

### 本地缓存和更新时机

CatalogCache 在程序启动时异步读 `.buggcraft/catalog-cache.json`，不提前请求所有加载器。进入安装页时由同一端口检查目录：先显示本地快照，本进程首次使用在后台更新；成功 10 分钟内直接复用，失败冷却 1 分钟。再次进入安装页或切换组合仍走同一有效期规则；刷新图标/重试绕过冷却。缓存包含来源完整排序、目录种类、游戏版本，切源不混用；最多 64 项/8 MiB，工作线程编解码和 QSaveFile 原子保存，缺失/损坏不阻断在线查询。

InstallCatalogSession 持有各组合的呈现记录和选择，仍在进行的其他加载器不因切换而取消；切回同组合复用在途请求，结果只更新它所属组合。缓存快照通过新增可选 cached 信号先发，不改变 finished 一次最终通知的契约。后台更新保留有效列表和用户所选版本，失败也不抹掉可用结果；空缓存才显示获取状态。用户离开页面不取消，退出统一取消所有活动组合。

源负责提供这次请求的元数据或文件访问通道。BMCLAPI 的 Fabric 查询必须请求 `https://bmclapi2.bangbang93.com/fabric-meta/v2/versions/loader/{mc}`；失败由现有协调器按队列尝试下一源，适配器自身不能偷偷请求官网。官方候选实际来源标官方。清单内发布者 URL 是资源身份信息；未来文件下载仍经过统一策略映射，不能直接当唯一下载地址。

BUGG 实际协议来自源站现有 mirror.py 与旧客户端 bugg_mirror.py：游戏 `/mc/game/…`，Fabric `/fabric-meta/…`，Quilt `/quilt-meta/…`，Forge `/maven/net/minecraftforge/forge/maven-metadata.xml`，NeoForge `/neoforge-maven/releases/net/neoforged/{artifact}/maven-metadata.xml`。Forge/NeoForge 返回 Maven XML，不能套 BMCLAPI 的 JSON 列表解析。BUGG 服务当前可返回 307 到缓存对象或上游，这属于 BUGG 服务端路由，界面来源仍标 BUGG；客户端额外候选只来自统一能力计划。

BMCLAPI Quilt 使用其 `/quilt-meta/v3/versions` 汇总快照，同时核对 hashed 中是否存在所选游戏版本，再读取 loader 列表；不能把不存在的联合查询路径返回 404 当成“不支持 Quilt”。镜像尚无该游戏的映射时返回合法空列表，由协调器继续下一来源，全部为空才显示无兼容版本；不拿全局加载器列表假报兼容。

游戏目录和加载器快照分别保留实际来源，安装页正常状态不再常驻展示技术来源文字。`source_changed` 在发起该源请求时通知；耗尽保留各候选错误，全部有效为空时才报告无兼容版本。传输层统一区分无进展超时（默认 15 秒）、总超时（默认 45 秒）、主动取消；超时不再显示误导性的 Operation canceled。所有等待异步进行，页面保持可操作。

## 固定业务接口、可替换适配实现

启动器上层固定使用 `GameCatalogPort.query/cancel/finished`、CatalogQuery/CatalogResult；SourceSettings 的优先级通过装配层注入，不把服务地址或协议传入页面。新源只调整能力登记与 infrastructure 中的适配/注册；不改安装选择状态、页面、HTTP 客户端、取消或重试流程。现有 JSON/XML 解析、版本排序和兼容规则继续共用，不复制一份解析器到每个源。

未来内容域使用独立稳定端口，计划能力为 search（关键字、类型、游戏/加载器、分页）、project（平台与项目 ID）、versions（精确兼容条件）、files（文件 ID/可信哈希）、identify（本地哈希查身份）；统一结果应保留平台身份、兼容版本、可信哈希、分页与实际来源。来源只适配协议，业务不解析远端 JSON。该端口尚未实现，不提前堆空类或模拟成功。内容调用必须先消费同一 resolve_sources，不能另写 CurseForge/Modrinth 排序。新增来源不改变这些用例；确需新增业务能力时另做显式版本化契约评审。

接口失败、取消、无结果的语义由契约测试约束；源适配器不得把超时当空列表、把全局加载器列表当兼容、把官方结果标为镜像、写磁盘或另起网络请求。

## 版本与兼容

- Minecraft 仅展示正式发行版，默认使用 manifest.latest.release；列表保留发行顺序。
- 原版没有加载器版本。Forge、NeoForge、Fabric、Quilt 是一个单选值，不可能同时入选。
- Forge 官方 Maven 按完整 Minecraft 前缀过滤，不能把 1.21 与 1.21.1 混用。
- NeoForge 按官方版本规则映射：1.x 的次版本/补丁 → NeoForge 前两段；26.x 起完整三段 Minecraft（缺补丁补 0）→ NeoForge 前三段；1.20.1 使用其历史 forge 工件。排除 snapshot/alpha 的非对应构建，不能靠 startsWith("21.1") 匹配 21.10。
- Fabric/Quilt 使用带 Minecraft 版本的官方查询路径，并核对 intermediary/hashed 版本。加载器按数值版本排序、去重，默认最新稳定；没有稳定版时展示“预发布”。
- 修改 Minecraft 或加载器种类时，切到对应组合的缓存和选择，不把旧组合结果放进新列表；用户只能提交当前结果中的 ID。请求失败和有效无兼容版本是不同状态，前者可重试，后者应换游戏/加载器。
- 默认实例名统一由 `InstallCatalogSession.suggested_name()` 生成：例如 `1.21.1-fabric-0.20.1`，跟随游戏、加载器及其版本变化；原版为 `1.21.1`。用户手动编辑后保留自定义名称。

## 实际 API 与组件复用

已实现 C++ 类、结构、方法签名、参数、返回值、信号和私有协作点集中在 [22-原生类与方法参考](22-原生类与方法参考.md)，不把规划接口混进实际 API。

安装页两个下拉框都使用同一个 `SelectField`，其弹层继续使用 Qt ComboBox/Popup/ListView、现有 InputField/ListRow/InteractiveSurface。搜索、虚拟化、悬停、选中、禁用和提交由该组件维护；页面不得另造版本列表。选择游戏页的实例行保持自身关闭悬停底色的配置，不把它误套给下拉版本选项。

安装页只保留版本、加载器、必要的加载器版本、安装操作；自动名称通过“修改名称”按需展开，不默认增加表单。ListRow 默认直接切换单色悬停，SelectField 也关闭颜色渐变；没有给安装页复制一份列表。选择游戏的“管理当前游戏”直达既有实例详情，顶栏下载任务图标紧邻设置并共用于两个主题。

## 生命周期与验证

网络由 Qt 异步驱动，JSON/XML 解析在 QtConcurrent 工作线程。UI 立即出现，可返回首页、拖动和折叠。窗口拥有会话，页面销毁不丢选择；退出取消网络、失效解析订阅，不同步等待线程。回首页复用 ToolDeck 的路由栈与 Main 导航，退出身份授权沿用既有取消规则。

检索了现有版本表单、ToolDeck.beginInstall/openPage/goBack、IdentitySession/LaunchSession、PageStateStore、ListRow/InteractiveSurface，以及旧版 game_sources.py。原生工程不存在网络或游戏目录实现，因此补上述所有者；不复制 Python，不另造页面专用请求器。实际安装仍明确未接入。
