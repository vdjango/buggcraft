## HTTP 传输 HttpClient

源码：`src/platform/http/http_client.h/.cpp`。只做网络机制，不决定源或游戏版本。对象拥有 QNetworkAccessManager；请求和定时器归对象树，取消无阻塞。

`HttpTimeouts`：`idle_ms` 默认 15000，`total_ms` 默认 45000，单位毫秒；构造时小于 1 的值归为 1。

| 方法/信号 | 参数 | 返回/副作用 |
| --- | --- | --- |
| HttpClient(parent=nullptr, timeouts={}) | QObject* 父对象；HttpTimeouts | 构造，不联网 |
| get(url, blocked_redirect_hosts={}) | const QUrl& HTTP(S)；const QStringList& 禁止跳转的域名后缀 | quint64 单调请求 ID；立即异步发 GET。最多 8 MiB、8 次跳转；拒绝 TLS 错误、HTTPS 降级及带凭据的跳转。子域名也受禁止列表约束 |
| cancel(request_id) | quint64 传输 ID | void；先移除订阅再中止；主动取消不发 completed，未知 ID 无效果 |
| completed(request_id, body, error) | quint64、const QByteArray&、const QString& | error 为空时 body 为响应，否则 body 空；超时与取消区分；无效 URL 也异步失败 |

BMCLAPI 接受服务端指派的 HTTPS 分发节点，禁止跳回 mojang/minecraft/forge/fabric/quilt/neoforge 的发布者域名；不能简单锁死主域名而阻断 BMCLAPI@Home 节点。BUGG 允许已部署源站分配缓存对象/上游重定向。规则由适配器提供，HTTP 仅执行。

源码：`src/modules/catalog/infrastructure/game_catalog_provider.h/.cpp`。接口和实现均无 QObject、无 I/O；不可变适配器可在线程池执行 parse。

| 方法 | 参数 | 返回、失败 |
| --- | --- | --- |
| id() const | 无 | QString 来源标识 |
| blocked_redirect_hosts() const | 无 | QStringList；该源禁止重定向的域名后缀 |
| request_url(query) const | const CatalogQuery& | QUrl；不支持的种类为空 URL，传输异步报告失败 |

## 目录协调 GameCatalogService

源码：`src/modules/catalog/application/game_catalog_service.h/.cpp`，实现 GameCatalogPort。transport 为非拥有指针，必须比服务活得久；每个请求持有不可变 providers 队列，纯解析任务延长各适配器寿命。

| 方法 | 参数 | 返回、行为 |
| --- | --- | --- |
| GameCatalogService(transport, order=supported_download_sources(), parent=nullptr, cache_path={}) | HttpClient*；QStringList；QObject*；QString | 构造订阅、异步读本地缓存，无网络；默认 BUGG → BMCLAPI → 官方；空路径只在内存缓存 |
| query(request_id, query) | 同公共端口 | void；同 ID 先取消旧代数，下一事件循环开始；解析交给 QtConcurrent |
| cancel(request_id) | quint64 | void；删除活动和传输映射，撤销网络；迟到解析被忽略 |
| select_sources(order, bugg_base={}) | const QStringList&、QUrl | void；更新来源快照，取消活动请求，发 source_selection_changed |
| attempt(request_id)，私有 | quint64 | void；发本队列当前候选、登记传输、发 source_changed；耗尽时汇总各源原因 |
| accept(request_id, transport_id, result)，私有 | quint64、quint64、const CatalogResult& | void；核对当前 ID，非空成功通知；失败或无兼容结果在既定队列继续，取消不继续 |
| refresh(request_id, query) | 同端口 | void；复用 start 并强制后台更新，已有快照仍先发 cached |
| start(request_id, query, force_refresh)，私有 | quint64、const CatalogQuery&、bool | void；唯一查询建档，下一事件循环 resume；同 ID 旧代失效 |
| resume(request_id)，私有 | quint64 | void；等待异步读盘；有效期内复用结果，否则先发 cached 再 attempt；快照监听者取消后不续发 |
| complete(request_id, result)，私有 | quint64、const CatalogResult& | void；统一移除活动、记录成功 10 分钟/失败 1 分钟冷却、成功入缓存、最终通知 |

Operation 内 query、source_index、transport_id、generation、errors、providers 是一次请求状态。耗尽且全部合法为空时成功空列表，否则汇总错误。析构取消活动请求；worker 只持值，不持窗口，不在 GUI 等待解析线程。所有信号沿用公共端口。

## 本地目录 CatalogCache

源码：`src/modules/catalog/infrastructure/catalog_cache.h/.cpp`；由 GameCatalogService 值成员持有。Record 为 key:QString/result:CatalogResult；不保存凭据或安装文件。所有实例方法在 GUI 线程访问内存；文件和 JSON 编解码仅在工作线程。

## 文件流水线性能补充（2026-11-10）

`GameOperations.export_pack(id,destination,compact,saves)` 接口不变；只进入原白名单文件夹与选中的 saves，单文件回调 collect_file 仍走安全路径、SHA-1/256 和原紧凑引用规则，再交给 archive_write。不扫描未选内容，无新缓存或所有者。取消/失败仍抛现有异常，原子输出不提交。

私有 `GameOperations.report(progress,detail)` 在本任务 worker 调用：每次检查取消，同种确定/不确定中间进度最多约 10 Hz；首次、模式变化、progress>=1 不等待。所有任务终态沿用 GameRuntime，不受合并影响。

`HttpRequest.sha1` 为空时不创建无人使用的 SHA-1 状态；非空仍边接收边计算并核对，不改变最终大小、响应上限、TLS、重定向、失败/取消及原子落盘。无新的公开方法、网络端口、线程或依赖。

## 2026-11-11 冷源与诊断

HttpRequest.first_byte_ms 控制请求发送后的首数据等待；HttpClient.transient_failure(id) 区分已知 HTTP 状态下的未完整传输。ResourceClient 复用既有有限重试。GameRuntime.export_diagnostics(url) 在 worker 中复用归档，diagnostics_status 为 UI 快照，输入绝对目标路径、已有目标拒绝覆盖、失败给 notice/error，取消随原任务域。platform/diagnostics 是脱敏/有界日志唯一所有者，网络代码不另行落盘。DesktopEnvironment.fullscreen_foreground(window) 在 GUI 只读检测；Windows 外部全屏行为尚未通过本轮自动验收，其他平台范围见第 46 号。
