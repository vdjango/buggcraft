## 新增入口的契约

- `EdgeDock.dockNearest()`：GUI，取当前窗口工作区，选上/左/右距离最近边缘，沿用 reposition 动画后折叠；无屏幕几何时不移动。启动收起与游戏运行共用。
- `WindowController.selectTheme(value)`：GUI，接受 panel / small / classic / large；只有尺寸变化，不复制页面；选择持久化由应用装配转交 GameRuntime。
- `GameRuntime` 任务队列：GUI 收命令，worker 串行执行磁盘/下载/Java；queued/running/cancelling/done/failed/cancelled/interrupted 独立状态。取消排队任务不取消其他任务。退出记录未完成状态，下次可重试，禁止假装仍在下载。
- 整合包拖入：只接受本地可识别归档，后台读取格式与版本，确认后入同一安装队列；没有通用导入按钮。导出必须使用保存对话框，不能覆盖源实例内容。
- 实例内容：GUI 只接收分类快照；扫描、启停改名和删除在 worker，并限制实例子目录及符号链接。实例页不直接执行磁盘操作。
- 节点：登录状态归服务；未登录不泄露/伪造房间和好友。登录、退出、刷新与建房/加入均异步，离开页面不销毁会话，退出应用异步释放。
- 元数据：`instance_descriptor(metadata)` 是已安装实例版本、加载器及加载器版本的唯一解析入口，供目录扫描和导出共用；纯函数，无 I/O，旧实例按 Maven 库坐标推断，不能各自实现一套识别规则。
- 房间心跳：`MultiplayerService.heartbeat` 复用引擎的 session.list/game.discover/room.retarget，等待中的房主在局域网开放后自动绑定端口；晚到结果必须同时匹配登录代次和会话 ID。引擎意外退出使界面立即回到未连接状态，不保留失效句柄。

## 整合包格式与入口

对照旧版 `buggcraft/src/buggcraft/core/modpacks.py` 与 `windows/main_window.py`：主窗口拖入单个本地 `.zip`、`.mrpack` 或 `.buggpack`，按归档内部唯一清单识别；不增加常驻“导入”入口。CurseForge ZIP 使用 `manifest.json`，Modrinth mrpack 使用 `modrinth.index.json`，Buggcraft 包使用 `buggcraft.pack.json`。拖入先异步检查与显示名称/游戏版本，再由用户确认进入队列；扩展名不能代替清单校验。

导出统一为 `.buggpack`（ZIP 容器、`formatVersion=1`），记录游戏与加载器版本、文件路径、大小、SHA-1/SHA-256 及是否内嵌。完整包直接包含实例的模组、资源包、光影与配置；精简包仅在已知下载链接和摘要/大小均匹配时引用外部文件，否则仍内嵌。存档由用户单独选择是否加入；绝不覆盖原实例。导出清单再经自身导入检查的回归测试验证。

## 状态与生命周期

便携默认 `.buggcraft` 位于可执行文件旁；新选的自定义缓存必须是启动器目录内的空文件夹，通过小型启动定位文件的相对路径找到，移动整个目录后仍可定位。迁移不复制访问令牌至明文配置。配置恢复完成前禁止启动、变更实例与安装；初始化状态直接显示在现有进度组件中。旧任务恢复为 interrupted，可重试；已完成记录保留。保存失败提示，不静默丢失。已选择的外部游戏目录不随启动器一起打包，需一并迁移或重新指定；系统绑定的账户令牌在其他电脑上可能需要重新登录。

选择游戏列表内部滚动，安装/目录操作固定底部。滑动提示只在第一次进入展示一次，不生成虚构实例。小号、常规、大号复用同一内容，联机/好友按可用宽度展开；面板保持紧凑。

## 浏览器授权后等待问题（2026-11-09）

## 加速缓存实链路与进度补验（2026-11-09）

发现实际入口缺陷：create_room 只暂存 instanceId/game，原生 describe 又不回传本机 allow_mod_transfer，导致房间快照丢失勾选值，update_acceleration 判定关闭，缓存 worker 没有启动。这解释了此前勾选后没有上传和进度；仅有协议实现或模拟源站测试不能证明实际入口可用。

已修复为建房/configure 成功后由 MultiplayerService 保存已确认开关，同一会话只合并响应实际存在的字段，失败不提交。RoomContentCache 仍是唯一清单/上传所有者；复用旧版本机 room_settings 保留权限的语义，不引入 Python 产品依赖。现有 host/publish 增加真实状态、整批字节进度、源站计数和确认缓存的文件名；上传收据校验通过才计数，上传后立即复查计划。后台复查保持原状态，不每次闪回加载。授权失败复用同一工作线程的既有轮询及取消，不另建重试服务。

接入实际节点与源站的路径为节点 content_cache_grant → mirror.bugg.icu 的 /room-cache/plan → 源站要求的 /room-cache/files/{sha256} PUT → 复查计划 → 同一有效房间内 GET。实测文件 `mods/imfast-NEOFORGE-1.21.1-1.0.3.jar`，4,193 字节；源站明确请求上传，随后确认 cached=1/total=1、pending=0，下载返回 HTTP 200 且 SHA-256 一致。真实 configure 关闭后移除缓存进度，重开后重新取得有效缓存结果，最终离房并释放租约。线上用例仅复制既有受保护凭据到临时测试目录，不写出令牌、设备私钥或改变用户设置。

缓存范围为源站明确请求的 mods/resourcepacks/shaderpacks 文件；公开源可下载的文件不重复上传。不含存档、账号、整个客户端压缩包。样本返回 cloud_pending=1/cloud_ready=0，因此本次只确认源站可用实体缓存，不能声称远程长期归档已完成；离房释放引用后文件可由源站清理。512 KiB/s 策略仍由源站执行，客户端未加入测速阈值或低速回退。本轮未修改、部署源站或节点项目。
