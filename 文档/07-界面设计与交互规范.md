# 界面设计与交互规范

启动首页的准备流程原位呈现：底部游戏/账号选择区淡出，替换为本次游戏名、当前准备步骤、简要说明与细进度条，右侧按钮变为“取消启动”；运行后收起进度条，按钮变为“停止游戏”，可按需查看日志。停止中禁止重复提交；取消、退出后恢复原选择，失败在原位显示原因和重试/返回选择。保留背景、顶部导航和窗口尺寸，不进入独立准备页、不弹全屏遮罩。切换采用 150–180 ms 淡入淡出和最多 6 px 位移，不连续回弹。具体状态契约见 12，服务边界见 06。

## 风格：极简但保留 Bugg 识别度

重新设计全部界面和组件。常规启动页采用整幅风景背景与轻量顶部导航，游戏名称在左下，账号和启动操作在右下；其他功能页继续使用白色画布和少量淡紫强调。另保留按需展开的紧凑面板。背景、强调色、字号、间距、圆角和图标大小都从 QML DesignTokens 单例取值，不在内容区域硬编码重复值。首页不堆信息卡、活动和公告；Bugg 品牌保留，交互重新设计。

当前原型令牌：面板背景 #FDFCF9，常规画布 #F7F8FA，主文字 #34323B，次文字 #8B8793，强调 #7561C9；间距基元 4/8/12/16/20/24 px。小工具栏使用 30–34 px 控件，常规页面扩大字号、间距与表单控件。正式版仍须验证中文、键盘焦点与高 DPI。面板固定宽 410，常规页面固定 960 × 600；同一主题切页不跳宽度，贴边折叠时缩成拉手；最新实测见 [15-首页交互原型与预览](15-首页交互原型与预览.md)。

设置内可切换「悬浮面板 / 常规页面」，共用同一个置顶、不占任务栏的窗口和工具条。常规主题使用顶部导航「启动、广场、联机、好友、设置图标」，内容在下方滚动。导航使用短下划线表示选中，不使用独立菜单底座或悬空阴影。工具栏不弹悬浮文字提示，辅助名称继续供屏幕阅读器使用。组件使用方法见 [16-QML组件库使用规范](16-QML组件库使用规范.md)。

常规页面采用 960 × 600 的横向比例。收起与关闭在右上角；右上角「收起为工具条」保留可恢复入口。标题空白处支持拖动。启动页以背景承载画面，保留当前游戏名称、版本、账号入口和启动按钮；顶部导航融入背景。点游戏名称进入选择页，选中后直接返回；安装、导入、管理与下载任务放在选择页。账号未选择时明确显示选择入口，不展示假的登录状态。背景使用随包本地图片，异步解码，不联网加载，也不使用常驻粒子或重型背景效果。

## 页面层级

2026-11-08 按用户最新要求：主入口为“启动、广场、联机、好友”和设置图标。下表描述业务功能归属；广场保留内容搜索与分类，任务进度在相应工作流内查看。

| 页面 | 第一屏必须回答 | 重要状态与入口 |
| --- | --- | --- |
| 首页 | 当前实例、版本、启动按钮 | 实例名进入选择；Java/任务异常按需反馈，正常时不堆状态 |
| 下载 | 游戏/模组/资源/整合包切换、搜索和导入 | 下载任务入口、来源排序、实际下载源 |
| 任务 | 进行中/等待补齐/完成/失败 | 文件级速度、失败原因、取消、继续补齐 |
| 联机 | 当前节点与延迟、房间/好友、创建/加入 | 实际 P2P/中转状态、邀请复制、成员准备 |
| 实例 | 目录、版本、加载器、Java | 重名决策、移除/永久删除区别 |
| 设置 | 账号、缓存路径、下载来源、Java、更新 | 仅展示能解释的配置，不放协议字段 |

根页面显示主菜单；二级及更深页面隐藏并禁用主菜单，最上方改为返回、当前标题和必要的副标题，右上角保留窗口控件。内容不再重复放标题和返回栏，滚动内容时顶部返回保持固定；返回根页恢复主菜单。两种主题使用同一条规则，顶栏切换为 140 ms 淡入淡出。

游戏身份页在常规主题内居中，左侧身份状态、右侧集中列出登录方式，紧凑面板则使用单列。第三方登录明确标为「第三方登录（待更新）」并禁用；皮肤行与登录区域额外间隔 12 px，标为「待更新」、隐藏箭头并禁用，不暗示已有皮肤管理。窗口右上角使用专用收起图标；收起后显示完整菜单工具条，保留用户主题与当前子页，点击原入口恢复原主题/页面，不能留下仅返回和子页标题的空工具条。

身份摘要的头像、名称和说明在同一列水平居中，名称过长省略显示。离线名称确认后退出整个身份流程，自动回到进入身份选择前的页面；首页进入就回首页，设置账号进入就回账号页，不再要求用户手动返回。分别保留本会话已成功选择的微软身份与离线名称：切离线不会删除微软身份，再切微软直接选用并回入口，不重复进入授权页；离线编辑预填上次确认的名字。首页与设置摘要订阅同一份 C++ 身份状态。首次微软登录演示获取授权码→等待→模拟完成授权→自动回入口，全程明确为模拟。返回/取消不更改旧身份；等待时禁用重复提交，第三方和皮肤仍保持待更新。无身份不得开始启动准备，按钮和启动入口共用 C++ preflight 检查。

导航保留当前主入口及子页面返回栈；点击顶部返回或 Esc 先返回上一级，取消操作不丢弃中间页面。身份确认成功则复用 goBack 退出身份流程，返回该流程入口。切换主入口清除旧子页面栈，切换主题保留当前页面和输入；切页重置滚动位置。任务状态由呈现模型持有，不因页面卸载而消失。真实安装、登录、切账号等业务流程仍待服务接入，不可把示例界面当成已迁移完成。

## 关键交互组件

- ActionButton、SearchField、ChoiceList、SourceOrderList、ProgressRow、StepTimeline、ErrorBanner、ConfirmDialog、Toast、EmptyState 由 Bugg.DesignSystem QML 模块统一实现。业务页面通过 C++ QAbstractItemModel/视图模型传数据，不复制按钮与弹窗外观。
- 现行 QML 只作为功能盘点的参考：核对旧页面有哪些必要操作、状态和文案，禁止把旧按钮、面板、输入框、下载行的实现或样式复制进新项目。新项目从 DesignTokens、ActionButton、Surface 等基础组件开始重新编写；**复用发生在新组件建成之后**，所有页面都使用同一份新组件。
- 下载行同时显示文件名、实际来源名称、速度/等待数据、完成字节和进度；来源在列表就可见，完整 URL 仅留在展开详情/日志，不让用户猜。
- 删除对话框先让用户选择“移除记录”或“永久删除本地文件”，后者突出显示路径和不可恢复性；默认动作不能暗中清空整个游戏目录。
- 建房“文件共享加速”给清单检查→源站判断→请求实体→上传→完成/部分失败五步，文件数与耗时可见；可取消但不冻结窗口。
- 加入房间安装时显示“已完成 X/Y，补齐 N 个”；必需文件缺失禁用启动并说明原因，可选资源缺失可继续但需确认。

## 响应性与无障碍

窗口可见后立即可拖动，页面事件处理目标控制在一帧内；网络、哈希、Java 扫描、目录遍历、压缩包解析不进入 GUI 线程。点击取消立即更新视觉状态，再异步清理后台资源；关闭弹窗不调用阻塞 wait。控件有键盘焦点顺序、可见焦点、屏幕阅读器名称；颜色不是唯一错误提示，错误必须有文本。使用 ListView 虚拟化与 C++ 分页模型，避免 3,000 文件逐项构造 Item 卡住界面。

## 验证方式

先画新导航和页面线框，再用可点击的真实 C++/QML 原型走完“首次启动、建房、加入同步、失败补齐、导入、删除”六条路径，最后锁定视觉令牌。QML 组件通过 qt_add_qml_module 收编，并由 qmllint、qmlformat 检查；对每个页面留下 100%、125%、200% 缩放截图和键盘操作记录。测试启动后马上拖窗、取消并切页、5–10 人房间长列表。没有真实可操作原型前，不宣称 UI 已“全部重新设计完成”。详见 [全新 QML 界面与组件清单](14-全新QML界面与组件清单.md)。
