# 联机、在线资源与译文验收

本轮接入资源译文，并验证启动器侧登录、房间与资源流程。按用户后续要求停止游戏内测试；本轮启动的两份 Minecraft 已关闭，未关闭用户原有启动器或 IDE 的 Java 进程。Windows 11 / Qt 6.8.1 / MSVC Release 实测，不代表 macOS/Linux 已实测。

## BMCLAPI 与译文

下载优先级与译文独立：即使只选择 BMCLAPI 优先，中文简介和正文仍向设置中唯一的 Bugg 基址请求。没有第二个译文地址选项，没有硬编码 translate 域名，也不把译文请求发送给 BMCLAPI。Modrinth/CurseForge 原元数据、兼容匹配、依赖计划和下载保持原职责。

列表先呈现原文，随后后台批量显示可用中文简介；详情显示匹配的中文正文，支持“查看原文/显示中文”。未就绪、过期或失败继续显示原文，不阻塞安装。原文使用旧版相同 mc-text-v1 SHA-256；核对资源、字段、原文哈希、当前状态、语言与 profile，正文制品还核对原始响应 SHA-256。匿名授权只存在 C++ 服务内存，不进入 QML、任务或磁盘配置。

检索了旧版 core/translation.py 与新版 ContentProvider、ContentCatalogService/Session、HttpClient、content_description。新版原先缺少资源译文协议；现在扩展原查询服务，不引入第二套网络/下载服务。将原 get 的网络等待/取消提取到 exchange，内容与译文共用。解析复用原安全图文解析和 RichDocument。

每批最多 20 个项目，GUI 不做网络和文档解析；缓存沿用 8 MiB/64 项，匿名会话按源保留和过期，ensure 冷却表最多 64 项。待处理每 5 秒查询，最多 12 轮，隐藏/离开内容页、换源、关闭即停止；换筛选/项目取消旧请求，迟到结果不覆盖新内容。实例文件页和广场共用的内容路由均可激活译文，不依赖主工具索引。

## 页面看图核对

实际打开原生窗口并查看截图；复用 render_native_window_routes 生成 build/verification/content/translation-{ready,original,pending,error,summary-only}-{classic,panel,small,large}.png。四尺寸详情状态图逐张查看；另查看广场目录的常规/面板截图以及两端聊天、成员、同步完成截图。简介与正文分别记录译文状态，简介就绪/正文待处理时明确“简介已翻译，正文准备中”，不统一误标整篇已翻译。

- 常规/小窗/大窗：正文为主要阅读列，右侧安装列独立；原文与译文切换在简介下方轻量显示，不混入安装选择。发现增加提示行后正文高度挤出底部，已减去该行与间距，重截图核对底部留白。
- 面板：介绍/安装仍分开，原文切换可见，底部安装入口完整，图文可滚动，未在四类页签/源/筛选同排追加按钮。
- 待处理和错误：保留原始图文与安装选项，仅状态文字变化；不把网络错误堆成安装阻断页。
- 房间：聊天和成员为独立页签；同步完成在游戏页明确“配置已匹配，可以启动游戏”，普通界面没有 IP/端口。聊天输入与窗口底部有留白。
