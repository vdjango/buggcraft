# 启动、下载、联机与诊断闭环整改

2026-11-14。本轮覆盖用户提出的 14 项；实施、验证与线上状态分别记录，不以规划替代功能。

| 项目 | 唯一所有者与实现约束 | 验收目标 |
| --- | --- | --- |
| 1 参数与文件去重 | minecraft_metadata / GameOperations，复用摘要与包内事实；同路径、同内容与同模组身份分别处理 | 重复 JVM 单值参数最后值生效；集合参数合并；不同路径同内容不重复入 classpath；冲突版本明确报错 |
| 2 冷缓存与测速 | ResourceClient → 源站现有镜像路由、测速与缓存生命周期 | 所有下载入口共用分流；未命中立即转最快已测上游，后台缓存独立；MR/CF 同摘要多源纳入排序 |
| 3、4、8 窗口 | WindowController / EdgeDock | 删除启动贴边偏好与初始化动作；上箭头直接折叠；展开恢复所选外观，无中间面板 |
| 5、6 联机状态 | 原生桥 Session / network_profile → MultiplayerService 快照 | 大厅右下角玩家文案；成员含房主的线路与准备/启动/世界状态、真实下载进度 |
| 7 离房 | ToolDeck 返回栈 + 既有 leave_room | 房间根页返回先确认；子页返回不误退房；取消不改变会话 |
| 9 启动失败 | LaunchSession / HomePage | 失败后直接切换游戏、身份，保留查看错误入口 |
| 10 正版续期 | MicrosoftAccount + ApplicationLifecycle | 恢复和凭据获取时按到期续期、旋转 refresh token；无固定刷新任务；取消/登出使迟到结果失效 |
| 11 好友自己条目 | FriendsPage 消费 MultiplayerService 网络快照 | 自己永远置顶，点击查看自己资料；邀请列表不混入自己 |
| 12、13 日志反馈 | diagnostic_log / GameRuntime / MultiplayerService；控制服务现有鉴权与 SMTP | 日志页可放大，统一反馈弹窗；脱敏日志包含运行环境与实例/模组事实；固定官方接收地址；正式身份鉴权；持久确认及邮件通知；未授权可导出 |
| 14 首次协议 | 应用生命周期与便携偏好；共用弹窗控件 | 版本化确认，阅读到底才能同意；拒绝退出；说明开源性质、第三方消费和法定责任边界、日志隐私；明确成年确认 |

新增接口必须登记输入、输出、失败、线程与取消；文件/网络/摘要仍在既有 worker，不在 QML 或 GUI 执行。正式账号认证和用户主动提交反馈独立于自定义联机域；不得向自定义服务发送官方诊断。

验证采用直接相关原生测试、编译、QML 边界与改动页面 410/960 两尺寸查看；真实跨机联机、微软远端授权、生产邮件等未执行的范围单列。固定交付入口仍是 `预览首页.cmd` → `build/bugg.exe`。

## 实现结果

| 用户条目 | 已落地行为与问题原因 |
| --- | --- |
| 1 | 继承元数据和最终命令统一归一化。单值 JVM/游戏选项保留最后值；可重复选项按语义保留。classpath/module-path 先规范化路径，对同大小候选再计算摘要，剔除不同路径的相同文件；相同名字但内容不同的库保留。启动准备会将 mods 中同内容重复 JAR 改为 `.duplicate-disabled`，不删除原文件，也不把不同版本的同 ID 冲突当成重复消掉。 |
| 2 | 源站原逻辑可能把冷请求交给未确认持有文件的节点，或沿用旧测速等级。现在缓存命中照常提供；冷请求选择同摘要多源或现有镜像的近期健康、实际速度，立即重定向，上游准备独立运行。Minecraft 客户端、资源、库、四类加载器 Maven 与 MR/CF CDN 均纳入原有分时采样，新观测立即参与后续请求。没有测量数据时沿用配置及健康回退，不伪称已找到全网最快地址。游戏下载、内容安装和整合包沿用同一个 ResourceClient，没有每入口另写一套下载器。 |
| 3、4、8 | 删除启动时贴边选项及其恢复逻辑；初始化直接采用所选外观并暂时停用布局动画，EdgeDock 先取正确工作区。上箭头一次完成折叠，展开恢复 panel/small/classic/large 原外观。游戏启动后的行为只在真正进入 running 时触发一次。常规设置保留启动行为，只有选择吸附才显示吸附入口设置。 |
| 5 | 大厅网络参考移至右下页脚，显示“直连条件较好”等玩家用语。复核旧 Python 探测与现有桥：同一本地 UDP 端口比较观测；同一服务器 IP 的多个端口不足以判断映射稳定，不同公网出口也不能直接断言严格 NAT。低证据情况保留较弱的可达参考；页面不显示 UDP/STUN 专业标签或保证成功率。旧实现只作参考，未成为产品运行依赖，没有新建临时分支。 |
| 6 | 复用真实成员快照，房主也发布当前游戏进度。成员行分别显示准备/下载/启动/运行/世界开放及直连、中转、本机，下载阶段显示实际进度条。页面测试中注入的状态仅为测试夹具，不进入产品。 |
| 7 | 房间根页返回先说明后果：房主退出会关闭房间、断开其他成员，但不关闭本地游戏；成员退出会离开联机会话。“留在房间”不调用离房；确认才执行既有离房流程。房间子页正常返回。 |
| 9 | 启动失败的首页直接提供“切换游戏或版本”和“查看日志”，不必先重新启动、再停止游戏。 |
| 10 | 复用 MicrosoftAccount 已有恢复与获取凭据生命周期，按到期时间提前续期，同一轮多个请求合并，持久化旋转后的 refresh token；取消、登出丢弃迟到结果。没有新增周期刷新任务。补齐授权阶段与失败日志，避免输出凭据。 |
| 11 | 好友列表添加永远置顶的“自己”；点击查看网络参考及直连/中转历史，主列表不再被自己的网络横幅挤占。搜索保留自己，邀请列表不加入自己。 |
| 12 | 日志页新增放大窗口和底部反馈；移除独立反馈页及其设置路由。复用结构化日志明细，筛选输入统一紧凑尺寸。收集启动器消息、任务/安装/下载错误、游戏输出和崩溃报告、桥日志、网络接口、当前与所选实例的游戏/加载器及所有根模组声明与依赖清单；不上传模组二进制、存档、账号存储。收集与归档在 worker，取消沿原任务域。 |
| 13 | 固定官方 `https://node.bugg.icu/v1/feedback/submit`，与用户自定义联机域无关。需要官方 Bugg 账号身份及本次同意，经原生桥复用受管授权。验证附件摘要并收到持久回执才显示成功，账号+编号幂等；可导出后经 Issue 手工提交。统一服务私有保存诊断 90 天，现有维护生命周期发送邮件，失败记录原因并退避重试。普通接口 64 KiB 不变，只有认证反馈支持 8 MiB ZIP、12 MiB 请求体和有限并发。 |
| 14 | 首次使用必须阅读版本化约定到底，两个按钮为拒绝退出、已满 18 周岁并同意。内容说明免费开源、志愿维护、第三方服务器消费、兼容性、备份及反馈隐私。按成年用户范围明确表达，不以协议虚构排除法律不能免除的责任，也不把“未成年人在监护下使用”与“必须已满 18 岁”混在同一个确认中。未同意时不开始账号/联机/更新服务。 |

日志保留采用有界策略：内存网络日志 2 MiB、单日志尾部 1 MiB、最近 8 份桥日志和每实例最近 3 份崩溃报告。在线 ZIP 超过 8 MiB 时明确转为手工导出；这里的限制针对诊断附件，不是整合包总容量或模组数量限制。内容清单遍历所选实例的全部根模组，逐文件记录无法解析的原因。普通导出拒绝覆盖已有文件。

## 线上状态

源站主站和成都边缘已应用 `usability-routing-20261114-125750` 这批路由改动；这是现有发布目录内的有备份定向更新，不把部署批次名误作物理目录名。`bugg-source/data/usability-20261114-deployed-hashes.json` 核对源码、安装包或源码入口、`source.tar.gz` 的 7 个改动文件一致。

统一服务发布为 `/opt/buggcraft-control/releases/usability-20261114-124314`，原有 17 个账号、14 个邮箱、9 个设备保留。已修正公网 Nginx 对认证反馈附件的专用请求体限制；没有开放公网管理员接口。部署、代理及 SMTP 配置证据位于 `buggcraft-control-native/validation-artifacts/usability-*.json`。

`bugg-source/data/usability-20261114-public.json`：两个源站域名文档返回 200，资源请求直接 307；官方反馈未认证请求返回 401，超过旧 64 KiB 的带无效身份请求也到达后端认证，管理员路径仍为 404。资源域名当前为 redirect 模式，该公网结果证明立即重定向，cache 模式冷未命中由本地真实用例验证，不能混称公网 cache 模式验证。Windows 对 translate 域名的本地 DNS 有旧记录，验收使用当前 IP 并保留原域名 TLS 校验；边缘域名正常 DNS。

## 首次须知尺寸补修（2026-11-14）

用户实际首次启动报告窗口被撑大。复现确认 Main 的 awaiting_consent 分支把紧凑窗口从正常 800×520 强制变为 800×680，之前仅在日志页触发协议的截图没有覆盖真实首页的首次呈现。`build/first-run-layout-before.txt` 保留这一失败结果。

修复复用 FloatingShell.pageExtent、ModalSurface 与 ChoiceDialog：常规外观不再为须知额外改变高度，面板使用既有页面高度；阅读弹窗受窗口边界约束，正文可收缩并滚动，拒绝与确认按钮始终留在框内；重新打开从顶部阅读。须知采用现有中性色，避免首页图片透过正文影响阅读。未改协议文案、确认持久化与联网前的生命周期门槛。

相关原生界面场景通过（`build/first-run-layout-after.txt`），涵盖 800×520、960×600、410×600 和 480 高工作区的 800×450。`build/verification/first-run-layout/` 的四组顶部/底部共八图均实际查看：无窗口或弹窗越界、按钮无截断，读到底后确认可用。qmllint 与组件边界门禁通过。仅编译相关目标并更新本地 v1.1.0 单文件入口，未运行游戏、未正式发布；产物摘要与原位置见 `build/first-run-layout-package.json`。

## 其余实测边界

本轮未使用真实微软账号走外网授权，已验证完整协议夹具和受保护令牌旋转；未向生产收件箱发测试邮件，已验证本地真实 TLS SMTP 并核实生产 STARTTLS 与收件配置；未执行两台真实公网玩家的直连/中转游戏会话。网络参考是观测，不能承诺玩家之间必定直连。

未将这些检查描述成所有游戏、显卡、加载器和光影的运行矩阵。此前 26.3 光影地形渲染异常仍需对应实际日志、核心与显卡组合判断，不能因文件约束通过就认定画面正常。本报告完成当前 14 项改动与上述范围验收，不替代交付清单里其他历史待验收项目。

交付清单中已变更文件对应的历史证据保留原摘要并归档到 superseded_evidence，相关旧结论恢复待验收；没有直接替换历史摘要冒充原范围重测。本次 13 个清单项对应用户 14 条（窗口三条归并），使用本轮实际证据独立验收。
