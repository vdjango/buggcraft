# 2026-11-10 多路径性能优化

本轮在实例扫描之外，修改了整合包导出遍历、任务进度交付、HTTP 接收处理三条实际流水线。复用原 GameOperations、GameRuntime、HttpClient 和文件模块，没有新下载器、任务状态机、生产依赖或后台线程。前一轮实例扫描见 [28 文档](28-2026-11-10实例扫描性能优化.md)，单次读取多摘要见 [27 文档](27-2026-11-10性能与界面验收.md)；这些旧结果不重复计为本轮收益。

## 检索、职责和实现

开工读取 AGENTS、唯一 bugg-cpp-qml Skill、03/09/12/18/19/20/26 及下载/整合包领域契约。检索新版 export_pack、report、update_task、HttpClient.request/consume、ResourceClient.fetch、archive_write、Java 探测、背景/进度动画；只读对照旧版 core/modpacks.py、downloads.py。先补接口/领域契约，再改原所有者。

- **整合包导出**：原实现递归整个实例，再按顶层名称丢弃日志、natives、未选中的 saves。现在从原白名单根目录进入，只单独检查 options.txt/optionsof.txt；未选存档等不遍历。原 collect_file 路径仍核对安全路径、SHA-1/256、外部引用条件，再由 archive_write 流式原子归档。没有把目录修改时间当作内容摘要缓存。
- **任务进度**：原逐文件整理/归档每次都投递 GUI，GameRuntime 随之发送任务快照。现在原 GameOperations.report 在所属 worker 合并连续中间值，间隔 100 ms；首次、确定/不确定模式变化、进度达到 1 立即交付。每次调用先检查取消；成功、失败、取消仍由 GameRuntime 的真实完成回调发布。只新增工作对象内的计时/最近模式字段，没有 GUI 定时器或跨任务缓存。计时器初始化与重置使用 start；[Qt 的 restart 契约](https://doc.qt.io/qt-6.8/qelapsedtimer.html#restart)不允许对未启动计时器调用 restart。
- **HTTP 接收**：原来所有响应都计算 SHA-1，即使 HttpRequest.sha1 为空、最终无人比较。现在仅在提供预期 SHA-1 时创建/更新摘要。已有 SHA-1、大小/上限、TLS、重定向、超时、取消、原子提交规则保留；调用方的 SHA-256/512 校验也保留。没有增加客户端低速判断或改变源站缓存策略。

生产改动位于 game_operations.h/.cpp、modpack_operations.cpp、http_client.h/.cpp。均为 Qt/C++ 跨平台代码，未增加平台专用 Intrinsic；继续 Release `/O2 /Ob2 /DNDEBUG`，不全局启用本机 AVX。方法索引及 04/06/12/19/22 已同步。

## 前后实测方法

`tests/performance/workload_test.cpp` 调用实际 **GameRuntime.export_pack 队列→任务终态**，包含工作调度与 GUI 事件交付；HTTP 场景调用实际 **HttpClient.request→response**。测试端 PayloadServer 只是有界 localhost 数据源，不实现产品下载、导出或摘要规则。复用 `compare_native_benchmarks.py`，由原扫描驱动扩展参数，而非另写一套比较器。

修改前保留 `build/workload-before.exe`。最终修改后为 `build/workload_test.exe`，均静态链接各自版本的业务实现；计时场景逻辑一致，新增正确性用例不在计时函数内运行。前后程序 SHA-256 在原始报告中。9 组成对样本交替先后，每次进程内做一次预热再取一次样本；准备文件、预热、输出校验在计时外。暖 OS 缓存，未清物理磁盘缓存；没有构建、其他测试或测试游戏同时运行，用户桌面与原有进程仍在。

导出数据：20 个或 1,000 个确定生成的 1 KiB 文件；排除目录场景另有 saves/logs/natives 共 12,288 个不应导出的文件。此为可复现夹具，不冒称用户真实整合包。每次比较前后**完整清单**（排序后的文件路径、大小、SHA-1/256、版本/加载器和嵌入信息）摘要，检查归档条目数量及一个样本文件。另有正确性测试逐条读取小夹具的全部导出内容和两种摘要。

HTTP 使用 8 MiB 内存响应、64 MiB 原子文件落盘及 64 MiB 带 SHA-1 对照。每次在计时外对全部输出做 SHA-256 比较。测量包含本地服务端供数、Qt 网络、接收处理及写入，**不是 CPU 独占微基准，也不是公网下载速度**；未提供 SHA-1 的请求原本就无预期值可核对，没有以关闭已有验证获得收益。

环境：Windows 11 x64（10.0.26100），Intel Core i9-10850K，20 逻辑线程，Qt 6.8.1，MSVC 2022 Release。未测 macOS、Linux、ARM64、冷缓存、游戏 FPS、GPU 占用、GUI 帧时或启动器总启动时间。

最终配对数据见 [机器可读原始报告](29-多路径性能原始数据.json)。以下只使用最终构建的 9 组样本，不把初步测量混入结果。

| 场景 | 修改前中位数（最小—最大），ms | 修改后中位数（最小—最大），ms | 耗时变化 |
| --- | --- | --- | --- |
| 导出 20 文件，另有 12,288 个未选文件 | 180.744（159.783—239.039） | 32.700（22.258—49.831） | 减少 **81.91%** |
| 导出 1,000 文件，无排除目录 | 975.058（915.592—2466.855） | 1215.638（920.226—2594.084） | **增加 24.67%**，没有证明总耗时改善 |
| 导出 20 文件，无排除目录 | 35.109（22.138—64.637） | 30.668（22.177—72.322） | 减少 12.65%，范围重叠，不认定稳定收益 |
| HTTP 8 MiB 内存响应，无预期 SHA-1 | 33.701（31.871—48.775） | 21.706（19.271—27.386） | 减少 **35.59%** |
| HTTP 64 MiB 原子落盘，无预期 SHA-1 | 283.973（250.734—373.184） | 170.650（149.349—211.767） | 减少 **39.91%** |
| HTTP 64 MiB 原子落盘，带 SHA-1 对照 | 262.862（231.146—389.968） | 278.571（248.678—353.763） | **增加 5.98%**，范围重叠，无收益 |

没有剔除慢样本。1,000 文件场景的时间跨度大，最终中位数更慢；本轮不能认定它的总耗时获益，也不能只把首轮较好结果挑出来。保留进度合并的依据是实际投递工作量减少：该场景 `tasks_changed` 从每次 **2,003 次** 降到中位数 **17 次**（14—31），减少 **99.15%**；两个 20 文件场景均为 43→6。计数包含排队/运行/终态，不只是 report 回调。**事件数下降不是 GUI 帧率提升或 CPU 节省的测量**，本轮未做这种归因。

带 SHA-1 的对照保留相同摘要工作，未观察到稳定提速。多数游戏资源本来带 SHA-1，不能把无摘要场景的 HTTP 收益推广到全部游戏资源下载。小导出和千文件导出的差异方向在初步/最终两轮之间变化；报告保留最终结果与全部初步日志，未按期望值挑选数据。

## 空闲占用和页面核对

使用 `measure_idle_windows.py` 启动独立便携配置的原生程序，空账号/实例、无自选背景；常规首页仍有内置背景轮播。每种状态等待 10 秒，连续采 8 个 1 秒窗口，CPU 的 100% 表示占满一个逻辑核，内存为该进程工作集，不是完整便携包大小、GPU 显存或跨进程共享内存总量。Qt 使用默认后端，没有强制软件渲染；未能从日志确认具体 RHI，不宣称测了特定 GPU 后端。

已亲自查看原生面板首页、两种尺寸任务空状态截图。第一次常规首页截图实际位于联机登录页，该组无效，保留原始记录且不计入首页结果；仅重新采集该状态，对独立测试窗口禁用输入以避免误切页面。纠正后的常规首页截图已亲自查看：内置背景、空实例/账号和安装入口正确。其余三组截图与标签一致。原始采样及被作废场景说明见空闲数据附件。

空闲数据只作审计，没有前后对照，**不宣称本轮降低了空闲 CPU 或内存**。采样二进制的 SHA-256 保留在附件；之后仅修正文件任务进度计时器的首次初始化，该代码在这些空闲状态没有执行。

| 实际核对的状态 | CPU 中位数 / 最大值（单核口径） | 峰值工作集 |
| --- | --- | --- |
| 面板启动页，空实例 | 0.0% / 0.0% | 109.66 MiB |
| 常规启动页，内置背景轮播 | 0.8% / 3.1% | 110.68 MiB |
| 面板任务页，空列表 | 0.0% / 0.0% | 106.56 MiB |
| 常规任务页，空列表 | 0.0% / 1.6% | 103.65 MiB |

[空闲占用原始数据](29-空闲占用原始数据.json) 包含每秒 CPU、工作集、私有字节和作废组说明。CPU 有计量精度/短时突发，0.0% 不等于绝对没有 CPU 工作。只测了这些空状态，未覆盖活动下载、房间、超大列表、贴边折叠或长时间内存增长。

另外运行既有 `test_task_history_control_emits_only_and_keeps_active_rows`，并用图像工具逐张查看 `build/ui-compact-review/tasks-{history,active,empty}-{panel,classic}.png` 六张图：两种尺寸均有独立标题/计数、运行/排队/完成条目，进度不遮挡取消，清空后保留活动条目、无可清记录时禁用，空态居中，面板中没有横向截断或操作挤压。这些是明确 UI 夹具，真实任务/进度行为另由原生队列测试验证。本轮没有修改页面/QML。

## 其他路径审计

| 路径 | 本轮结论 |
| --- | --- |
| 实例扫描/共享语言索引 | 前轮已消除同一扫描重复解析，收益与单实例回退见 28；没有再建全局缓存 |
| 单文件多种摘要 | 前轮 file_digests 已合并读取，见 27；不重复实现密码算法 |
| 游戏启动文件准备 | 下载缓存命中仍完整核对；validate_libraries 主要检查必要库存在，并非又做一轮完整哈希，未凭猜测删除 |
| 下载/房间同步 | ResourceClient 已有受控并发、故障来源回避和流式原子写入；本轮只优化共用 HTTP 与进度出口，房间传输/摘要/取消回归通过 |
| 整合包压缩/解压 | archive_write 已流式有界，不把整包读入内存；本轮删除的是无关目录遍历，没有替换压缩库或降低安全预检 |
| Java 环境探测 | 当前在后台按候选串行运行 java -version；本轮仅检查代码，尚无独立前后实测，不宣称已加速。候选去重、取消、并发预算应先测量再改变 |
| 背景/图像/QML | 背景异步双层解码并限定 sourceSize，轮播受 active/visible 控制；进度动画只在活动/可见时运行。未全局增加 layer 缓存，未盲加 SIMD |
| 空闲常驻占用 | 原生单进程采样见附件，只反映指定空状态；没有用零值采样宣称绝对零 CPU |

## 复现

先在生产修改前用同一测试夹具构建保留 workload-before.exe，再构建修改后 workload_test.exe；前后配置一致。只显式运行一次 prepare_export_fixtures 准备固定数据，日常 CTest 不创建大夹具、不跑性能样本。

```powershell
$env:PATH = 'E:\code\.tools\Qt\6.8.1\msvc2022_64\bin;' + $env:PATH
$env:BUGG_WORKLOAD_FIXTURE = 'E:/code/bugg/build/workload-fixtures'
build/workload_test.exe prepare_export_fixtures
python -X utf8 tests/performance/compare_native_benchmarks.py `
  build/workload-before.exe build/workload_test.exe build/performance-workloads-final `
  --pairs 9 --test-function measured_workload --report-env BUGG_WORKLOAD_REPORT `
  --time-field workMs --scenario-fields files,bytes,excluded --extra-metrics progressEvents `
  --build-description 'MSVC 2022 Release /O2 /Ob2 /DNDEBUG, Qt 6.8.1' `
  --timing-description 'Export: actual GameRuntime queue through terminal task; HTTP: request through actual response; verification outside timing'
```

原始逐组 JSON、QTest 日志和驱动汇总在 `build/performance-workloads-final/`，驱动日志 `build/performance-workloads-final.log`。首次测量随后发现计时器初始化需修正，旧测量保留在 `build/performance-workloads/`，不纳入最终表格；没有删除较慢样本或选择最好的一轮当报告。
