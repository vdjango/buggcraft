# 游戏实例与整合包

2026-11-12 跨项目待实施方案：[制品依赖约束与客户端兜底](../../bugg-source/文档/46-制品依赖约束与客户端兜底方案.md)。源站复用已有制品采集器，客户端拟在原安装 worker 中按具体 JAR 事实统一校验/求解，暂存通过后提交；不继续扩大 core_release 的跨平台专用补丁。现有生产代码尚未具备此通用能力。方案已用现有采集器验证发布/加载器/内容隔离，并在隔离 NeoForge 26.3.0.101 世界中验证明确候选组合的光影开关效果；不代替最终自动安装验收。

原生安装页已接真实 Minecraft/Forge/NeoForge/Fabric/Quilt 目录及安装执行：下载文件、准备 Java、执行加载器处理器、验证输出后提交实例。统一目录端口与兼容规则见 [21-游戏目录与多源适配](21-游戏目录与多源适配.md)，当前执行所有者及验收见 [真实安装启动与生命周期流程](23-真实安装启动与生命周期流程.md)。本地整合包导入导出、房间同步已接入 GameOperations；在线四类新增目录适配，整合包继续委托 import_pack，见 [在线内容接入](31-2026-11-10在线内容接入.md)。

## 实例是核心实体

InstanceId 与显示名分开；实例记录包含游戏目录、Minecraft 版本、加载器类型/版本、Java 选择、隔离目录、运行参数和状态。目标 versions 下每个“游戏版本 + 加载器 + 加载器版本”组成**一个最终实例目录**；安装原版作为加载器步骤时不额外留下第二个同名最终实例。中间成果放任务暂存区，验证完成后原子提交。

## 重复名称/目录决策

游戏下载、整合包下载、导入 ZIP/mrpack/buggpack、房间同步都调用 InstanceNamePolicy：先规范化与比较（包含不区分大小写的目标文件系统），再展示“使用另一名称/取消”；已有实例只有显式选择“替换”并完成备份确认才可覆盖。下载任务的目标路径被占用时先保留旧实例，不能一边下载一边污染它。删除实例默认删除对应本地文件，但确认框高亮“永久删除本地文件”；另提供“仅从列表移除”，二者不可用模糊语句混淆。游戏目录删除与实例删除是不同操作。

## 游戏安装流水线

选择游戏版本 → 校验加载器兼容性 → 确定唯一实例名 → 取得 JavaExecutable → 下载版本元数据/游戏核心/库/资源 → 安装加载器 → 验证生成的版本 JSON、JAR 和依赖 → 提交实例 → 可启动。Forge/NeoForge 处理器用 GameOperations.ensure_java 返回的**存在且可执行**路径，不能退化为系统 PATH 的 java；处理器异常映射到任务错误，不产生空壳“已安装”。Fabric/Quilt/API 和独立下载目标同样走统一的任务与来源策略。

自动 Java 在每次启动器初始化时后台检测便携运行库与系统候选；每次安装/启动再验证兼容主版本，缺少时按 Mojang 运行时清单下载并校验，供本次处理器和游戏共用。窗口先显示，不等待扫描。Java 下载与游戏资源复用 ResourceClient/HttpClient，不另写来源重试。手动路径选择尚未接线，不能把 Java 路径列表当作已生效的手动设置。

## 整合包规范化

2026-11-10 性能契约：现有 GameOperations.export_pack 只枚举允许导出的顶层内容目录及 options.txt/optionsof.txt；未选择存档时不进入 saves，也不进入 logs、natives 等非导出目录。仍逐个文件执行 safe_path、摘要和现有 archive_write 原子写入；选中 saves 时正常包含存档。没有取消校验或目录防护，不创建第二套导出器。

GameOperations.report 在所属 worker 内限制连续中间进度最多约 10 次/秒，首次、确定/不确定阶段切换和完成值始终传递；每次调用在节流前检查取消。任务结束、失败与取消仍由 GameRuntime 完成回调发布，不用进度值冒充提交成功。此限制不新增 GUI 定时器、后台任务或页面状态。

三种入口：本地导入、远端下载、房间客户端同步；前两种读取受支持的 .mrpack、.zip 和 .buggpack，解析为同一个 PackPlan（实例信息、文件任务、覆盖文件、游戏/加载器需求、必需性），再由 InstallCoordinator 执行。房间同步读取房主文件清单并生成同一种文件补齐任务，但不伪装成整合包上传。

格式解析器单独实现：MrpackParser、CurseForgeZipParser、BuggPackParser；按文件签名与清单确认格式，不能只信扩展名。紧凑导出记录经验证的外部哈希/URL，常规导出携带授权范围内的实际文件；所有导入需防 Zip Slip、压缩炸弹、大小与路径越界。无效包给出具体原因，不创建半成品实例。不同格式的路径和模组列表在 PackPlan 中归一，清单缺失/URL 过期进入 FailureQueue。

## 启动与运行

LaunchSession 复用 preflight 验证身份，GameRuntime 取得凭据后委托 GameOperations.prepare 校验实例、Java、加载器文件和参数，再创建真实游戏进程。GameProcess 监视和停止本启动器创建的 PID，日志写入实例目录；当前只允许一个活动安装/准备及一个游戏会话，不声称已实现多开或完整诊断服务。任务归 GameRuntime，切页不销毁。

启动进度在启动首页原位显示，不打开“启动准备”子页。空闲时展示游戏摘要、账号和启动按钮；准备时锁定本次实例/身份快照，底部替换为当前步骤、说明和进度，按钮为“取消启动”；运行时为“停止游戏”，停止中禁用重复操作。失败留在原位显示原因并允许重试，取消或进程退出恢复选择。步骤可以包含身份、Java、文件和创建进程，但进度必须来自服务事件，未知进度不编造百分比。进程真正创建并被会话管理器接管后才进入运行态，点击停止不等于进程已退出。

切换页面、收起窗口和切换主题不取消启动，也不重置进度。呈现模型由窗口会话持有；QML 只投影状态并发送启动/取消/停止意图。Java 扫描、授权刷新、文件检查和进程等待均不可阻塞 GUI。原生 LaunchSession 已接 GameRuntimePort；“确认游戏身份”消费 IdentitySession 的已确认状态，按钮可启动状态和 start 入口复用同一 preflight，无身份不得进入后续准备。选择身份完成直接回流程入口，不自动启动游戏。

## 验收重点

同名实例导入与下载、取消后重开、已有 .minecraft 不动、Forge/NeoForge 没有系统 Java PATH、旧版配置路径、移动整个目录、游戏成功启动与退出、房间必需模组缺失时阻止启动。对旧实例做只读回归；未验证迁移成功之前不得删除旧目录。
