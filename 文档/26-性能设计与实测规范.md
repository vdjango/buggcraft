# 性能设计与实测规范

本规范是编码前的强制约束，适用于 Windows、macOS、Linux。性能与功能正确性一起设计，不在功能完成后才处理卡顿。

## 编码前检查

- 在所属服务确定输入规模、时间/空间复杂度、阻塞位置、并发数量、缓存上限与失效条件。先检索和复用现有能力，不为了优化建立第二套状态机。
- 同一文件需要多个摘要、元数据或清单时合并读取；流式处理大文件，复用有界缓冲，不把整包装入内存。不能以缓存绕过完整性验证；命中条件须对应真实内容。
- 网络、文件扫描、摘要、解压、Java 探测在既有工作线程执行，GUI 只消费快照。合并高频进度事件；取消、退出和切页沿用现有所有者，不引入忙等、无界线程或逐帧轮询业务。
- 图片先在解码器允许时缩小，复用 Qt 图像和绘制能力；后台/折叠暂停无意义动画，列表限制可见范围。`layer.enabled` 需比较纹理内存和更新频率，不能当成无代价的全局开关。QML 使用 `qt_add_qml_module` 的编译缓存；生产不强制软件渲染，测试同时覆盖软件和可用的 GPU 后端。

## 编译与指令集

Release 使用 CMake 工具链的优化配置（本机 MSVC 为 `/O2 /Ob2`），不要给 Debug 或第三方依赖无差别注入激进参数。编译优化、LTO 和浮点模式改变也要验证行为、构建成本及产物。

通用发布不使用 `-march=native`，不全局设置 `/arch:AVX2`、AVX512。x64 与 ARM64 分别构建；ARM 使用相应基线/NEON 能力，不能包含 x86 Intrinsic。优先复用 Qt、密码学、压缩和原生网络库已经提供的运行时硬件分派，不自己实现密码算法。

只有测量证实为 CPU 热点且有收益时才引入手写 SIMD：保持同一语义的基线实现，目标函数/独立编译单元按平台开关，运行时确认 CPU **与操作系统**支持后再选 SSE/AVX/NEON 路径。测试支持与不支持的分派，比较尾部、对齐和边界输入。`restrict`、SIMD pragma 只能用于已证明不别名/数据独立的循环。不能把理论 8 倍吞吐写成产品性能提升。

## 性能报告

报告列出场景、原生入口、输入规模、系统/CPU/Qt/编译器/优化参数、基准命令、次数、缓存状态及后台负载。比较同一机器、同一数据、同一构建配置的前后实现，交替运行降低顺序偏差；数据准备不计入计时。记录中位数和范围或分位数、相关吞吐、读取字节/打开次数、必要时峰值内存/GUI 响应。

结果必须经过相同输出和取消检查；原始机器可读数据与报告一起保留。优化后不明显就如实写出，不用减少读取量冒充相同比例的时间减少，不用局部微基准冒充启动/下载/游戏 FPS 的提升。macOS/Linux 未测则明确未测；不以 Windows 单机测量覆盖其他平台。可复用的基准放 tests/performance，正确性继续由原生单元与契约测试覆盖。

## 官方依据

- [GCC x86 编译选项](https://gcc.gnu.org/onlinedocs/gcc/x86-Options.html)：`-march=native` 可生成其他 CPU 无法运行的指令，不能作为通用包默认配置。
- [MSVC /arch（x64）](https://learn.microsoft.com/en-us/cpp/build/reference/arch-x64?view=msvc-170)：默认基线 SSE2；更高指令集需要对应 CPU 支持。
- [Qt 6.8 QML 性能建议](https://doc.qt.io/qt-6.8/qtquick-performance.html)：测量热点、异步处理、控制绑定与绘制成本。
- [Qt 6.8 QML 缓存](https://doc.qt.io/qt-6.8/qmldiskcache.html)：复用构建缓存，不能在生产入口无条件禁用。
