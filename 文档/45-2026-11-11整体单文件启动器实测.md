# Windows x64 整体单文件启动器实测

用户目标是整个启动器只有一个文件，包括 Qt、联机桥和非系统运行库。此前“单文件桥”只覆盖桥，不满足这个目标。本轮已构建可直接运行的 `bugg.exe`，不是自解压安装器。安装组件只安装这一个文件，语言仍按需下载，保留一张内嵌背景。

## 实现与复用

- `BUGG_SINGLE_FILE=ON` 要求 Windows/MSVC、静态 Qt 和静态 CRT；默认仍关闭，其他平台沿用原构建。精简 Qt 6.8.1 重新编译为 `/MT`，去掉旁置 MSVC DLL。
- GUI 正常运行；同一个 EXE 带 `--native-bridge` 时，在创建 QGuiApplication 前进入既有原生 RPC。NativeBridge 仍使用异步 QProcess、原优先级队列和关闭屏障，游戏字节仍由原生转发线程处理。保留崩溃隔离和超时终止能力，无第二套引擎。
- 独立桥和完整启动器共同链接 `buggcraft-bridge-cli`，入口归 `bridge::run_cli`；SDK 仍直接复用 engine。没有将同步 RPC 移到 GUI，也没有把 JSON 控制通道改成游戏数据通道。
- curl 使用既有 HTTPS 精简配方；OpenSSL 3.5.2 保留汇编、AES/SHA 和运行时硬件选择。原有编码 ISA 分派与基线路径保持，不全局启用 AVX2/本机指令集。
- 单文件 QML 只从内嵌资源加载，避免误用旧目录残留的 QML。测试和 Qt Test 未进入最终链接目标；测试程序、PDB、源码和构建工具均不进入玩家安装组件。
- Qt/应用/桥依赖许可内嵌，`bugg.exe --licenses` 可输出；重链接对象和源码材料另存为开发附件，不增加玩家运行文件。

## 功能与运行库验收

Windows 11 x64，Intel i9-10850K，MSVC 19.44，Qt 6.8.1 静态 `/MT`。Qt 官方源包和 OpenSSL 源包按 SHA-256 校验；OpenSSL 开启汇编，未使用 no-asm。构建工具 Perl、NASM、Python、jom 仅用于开发，不是产品运行依赖。

1. `launcher-single-file` 安装到全新目录时只有 bugg.exe。PE 普通/延迟导入闭包只含 Windows 系统库；不依赖 Qt、OpenSSL、curl 或 MSVC 的旁置 DLL。运行时 PATH 限制为 System32/Windows，从 System32 工作目录打开。
2. 面板、常规窗口及软件渲染启动成功。实际查看 panel.png、classic.png、classic-software.png：面板游戏选择/安装主操作清楚，常规主题单背景、导航和空账号状态正常，无文字截断。第一次截图仍处于初始化，等初始化完成后重新打开并复查；未把加载状态图当作最终页面通过。运行模块记录未见非系统 DLL。
3. CTest 4 项通过：encoding_units、native_units、embedded_protocol_tables、qml_component_boundaries。runtime 7 个选定行为通过（含初始化/清理共 9 个 QTest 结果），content 3 个行为通过（共 5 个结果），无失败/跳过。覆盖完整 EXE 的 RPC 与退出、队列优先级、按需语言下载/错误/取消/离线复用、HTTP 原子提交和窗口生命周期。
4. 最终完整 EXE 完成 8 项真实原生网络回归：无压缩转发/EOF、受限密码套件、混合 P2P/中继、压缩尾部排空、身份 pin/帧边界、文件哈希失败/取消、文件与游戏数据并行、有界控制消息与连续游戏数据。测试使用原生节点与 TCP 游戏夹具，校验真实 Minecraft 初始握手、载荷和 EOF，没有启动真正的 Minecraft 世界。
5. 经实际 node.add → ControlClient 完成 7 项 HTTPS/IPv6 检查：私有 CA、拒绝不可信证书、拒绝错误主机名、禁止跳转、响应上限、HTTP 错误和 IPv6 回环。测试路径是本机回环，不能代表公网、跨运营商或 Linux/macOS 已验收。未关闭系统防火墙，未记录任何未经观察的弹窗点击。
6. 本机 Defender 扫描返回 0、未检出威胁。Authenticode 状态 NotSigned；未签名、未发布，不能保证其他杀毒产品或 SmartScreen 不提示。正式发布仍需正常代码签名和相应平台验收。

原始记录在 build/single-file-study：ctest-tests.log、runtime-qtest.txt、content-qtest.txt、network-tests.log、tls/tls.json、ui-checks.json、defender.log、signature.json。Qt QTest 的 content 输出存在已有 DelegateModel 警告，本轮没有将其表述为“无警告”。

## 同源码性能对照

相同 MSVC 原生引擎对象、OpenSSL、Qt 和原生节点；独立桥与完整 EXE 交替各 3 次、每次 30 秒。3 名玩家、每人 2 条 64 KiB 连续流、不限速、转发压缩 off、固定 AES-GCM，保留正常指令集分派。负载含真实协议入口与哈希/EOF 校验，但游戏数据为合成负载，不测试 Minecraft TPS、真实世界卡顿或公网丢包。每轮完整保存 CPU/RSS/逐玩家 RTT、二进制摘要；不是纯内存复制速度。

| 指标 | 独立桥：中位数（范围） | 完整 EXE：中位数（范围） |
| --- | --- | --- |
| 应用回显吞吐 MiB/s | 125.52（124.11–127.96） | 123.39（121.60–124.84） |
| 原生进程 CPU 秒/GiB | 22.78（22.40–23.59） | 23.86（23.23–23.99） |
| 每轮最慢玩家 P99 ms | 4.747（4.663–6.561） | 4.632（4.566–5.084） |
| 节点与联机子进程合计峰值 RSS MiB | 141.78（136.33–142.62） | 162.13（161.77–162.43） |

本轮完整 EXE 的吞吐中位数低约 1.7%，CPU/GiB 高约 4.7%，多进程峰值 RSS 高约 20.35 MiB；P99 范围重叠。单文件是分发便利和依赖闭包优化，不能宣称提升转发速度，也不能将这点本地波动换算成玩家延迟改善。两种布局均保留独立进程，未比较直接 in-process SDK；后者需要单独解决同步 RPC、取消、崩溃隔离和 GUI 生命周期。

GUI 在相同软件渲染、同源码条件下，各预热 1 次，再交替测 5 次。测量窗口首次可见，10 ms 轮询，不是首帧、可操作时间或冷磁盘启动：独立布局中位数 174.49 ms（152.42–187.24），完整 EXE 152.12 ms（149.25–163.97）；窗口出现时 RSS 中位数 55.07 / 55.86 MiB。未清空系统文件缓存，不作普遍启动提速结论。

完整原始数据：[benchmark.json](../build/single-file-study/benchmark.json)、[GUI 测量](../build/single-file-study/gui-measurements.json)、measurements/*.json 和资源采样。旧报告中的禁用指令集结果不冒充此构建的结果；本轮改变的是静态链接和入口复用，不新增 SIMD 算法。

## 复现与发布边界

在 x64 MSVC 开发环境中，先用 `tools/build_size_qt.cmake` 和 `STATIC_RUNTIME=ON` 构建独立精简 Qt；准备同工具链 `/MT` 静态 OpenSSL。然后运行：

```powershell
cmake -DQT_ROOT=<静态Qt目录> -DQT_SOURCE_ROOT=<对应Qt五模块源码根> `
  -DOPENSSL_ROOT=<静态OpenSSL目录> -DWORK_ROOT=<独立构建目录> `
  -DOUTPUT_ROOT=<空输出目录> -P tools/build_single_file.cmake
```

若套件没有 LinguistTools，可额外传 Qt6LinguistTools_DIR 指向同版官方构建工具。本轮准确配置/编译命令在 build/single-file-study/app-commands.json 与 qt-commands.json；测试入口为 check_functions.py、check_network.py、benchmark.py、measure_gui.py。final-build.log 确认最终源码下 `ninja: no work to do`。

`developer-relink-inputs.zip` 包含应用/原生静态对象、清单与 relink.cmake；实际使用所给材料重新链接完整 EXE并通过原生入口版本检查，relink.log 记录结果。Qt 库由外部 QT_ROOT 指定，可替换为修改后同 ABI 的 Qt；准确源包 SHA 在配方中。source-materials.zip 另含应用和原生依赖源码。开发附件与玩家单 EXE 分开；这些是本地材料，不代表已公开发布源码、上传语言附件或正式完成签名。

单文件不表示零写盘：用户设置、游戏文件、下载、缓存及按需语言仍使用既有目录；运行时不会释放 Qt DLL 或第二个桥文件。Windows x64 已按上述范围本地验收，其他系统/架构没有因此自动成为“已完成”。
