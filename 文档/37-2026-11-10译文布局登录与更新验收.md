# 译文、页面布局、授权恢复与原生更新验收

本次范围是资源列表译文及开关、详情元信息侧栏、联机服务设置、任务统计精简、浏览器授权后连接恢复，以及 2.0.1 原生启动器接入现有下载站。此前官网重做、节点全面原生迁移等工作区清单项没有在本报告中宣称完成。遵照用户要求，本轮没有启动 Minecraft 游戏。

## 实现与复用

资源列表之前漏接广场主入口的可见性，导致译文会话没有激活；Main 现在同时覆盖广场根页和内容子页。ContentCatalogSession 仍复用既有批量译文服务、原文哈希核对、缓存和取消。设置→语言增加默认开启的“资源中文翻译”，由 GameRuntime 原偏好机制保存。详情“查看原文”只影响当前详情，返回列表仍显示已匹配的中文简介，不把项目名、作者名伪造为中文。

移除详情顶部整块图标/简介/译文区域，图文正文从顶部开始；作者、简介、原站、译文状态和切换归唯一 ContentInstallOptions，常规右侧与面板安装页复用。任务列表直接从顶部开始，“进行中/排队”和清空记录归底栏，清空仍只移除终态任务。

NodeLogin 保留浏览器设备签名授权，不收集用户名密码。现有统一服务使用浏览器持有的 P-256 密钥完成挑战签名，没有可直接接入的密码登录接口；没有添加虚假的密码表单。服务地址配置移入设置→联机服务，登录区下方齿轮进入同一页面。有效授权后的连接失败提供“账号已授权 / 重试连接”，同 origin 重用原 profile，不重复开启浏览器。授权过期、撤销、错误挑战、网络失败和取消仍走原续期/授权状态机。

新版此前只有更新占位页，缺少更新状态所有者，新增应用级 LauncherUpdateService 是这一缺口的唯一实现。检查复用 HttpClient；下载复用 ResourceClient；摘要/归档/路径/复制复用 file_digest、archive_entries、archive_extract、safe_path、copy_file；关闭纳入 ApplicationLifecycle 原 shutdown/busy/drained。archive_extract 仅增加默认关闭的 UNIX 执行位保留参数，更新包开启，游戏解压调用不变。没有新增全局线程池、轮询器或 QML 网络、文件逻辑。

当前版本由 CMake 统一定义为 **2.0.1**，应用版本、HTTP User-Agent 与游戏参数 launcher_version 均使用同一值。首帧后异步检查，发现更新显示通知和设置提醒，用户点击后下载，再点击重启安装。下载、哈希和解压在一个可取消 worker；GUI 不等待进程。更新助手为暂存目录里的原生程序副本，通过 `--apply-update` 在 GUI 初始化前运行；等待旧进程退出后备份/替换，文件事务失败恢复旧文件，再启动同一安装根目录的程序。固定 CMD、游戏目录和用户配置不属于更新内容。

## 线上根因与部署

浏览器授权已成功，失败发生在受管节点分配：上海节点和身份适配的 `control-ca.pem` 保存了旧的域名叶证书，当前证书链不匹配，严格 TLS 校验使心跳中断；节点的 `proof_endpoint` 又使用域名，而中心可达性证明要求与游戏 endpoint 相同的数字 IP。

修复保留严格证书校验，更新两处信任根，补齐当前链使用的 DigiCert Global Root G2；将 proof_endpoint 改为 `81.68.225.236:443`，Nginx 同一节点虚拟主机接收该 Host。`nginx -t` 通过后 reload，重启对应 node/identity。中心现有服务不改监听口，资源源站不改。实际检查上海节点为 active、心跳序号 41、health_until 有效；北京旧节点健康已过期，不计作可分配节点。

修复前备份保存在上海服务器：

- `/var/backups/buggcraft-control-trust-20261110-221109`：原 node/identity 信任文件。
- `/var/backups/buggcraft-node-proof-20261110-221500`：原 server.conf 和 Nginx 配置。

下载站仍使用 `https://download.bugg.icu/api/launcher/update`，增加 `runtime=cpp`，只推荐该平台的 `Bugg-native-{platform}.zip`；没有第二个服务入口。旧客户端不带参数，继续使用原产物协议。原生包复用鉴权上传、审核、发布、资产下载和服务端 SHA-256，新增 ZIP 根清单、平台、路径和体积检查；耗时校验在线程中完成。协议覆盖 Windows x64/ARM64、Linux x64/ARM64、macOS x64/ARM64。

部署只更改 release-platform 的 app.py 和 launcher_releases.py；部署前比较线上文件摘要，备份 `/var/backups/buggcraft-releases-native-update-20261110-230000`，使用同一服务重启。最终 launcher_releases.py SHA-256 为 `72142669c51661efffbd8291c3018a16b74a9ef73dd1d8b5eac3edfd1843a2f8`。六个平台的线上更新检查均 HTTP 200，当前 2.0.1 无更新。没有发布虚假的 2.0.2；测试中的更高版本仅存在于隔离夹具。

部署记录：`build/update-node-deployment.txt`、`build/update-platform-deployment.txt`、`build/update-public-feed.json`。

## 交付与边界

最终仍是 `预览首页.cmd → build/bugg.exe --theme classic`。CMD SHA-256 保持 `83a46be27713cdb50f62aaea07acd31cabfde39102d1fecf3eb205f6d0faab51`；本轮最终 EXE SHA-256 为 `cee8d163d2465d47ae049f85ff29d3b665455ccfb4363e6553aac6cc45215bbe`。其他 DLL 摘要和文件大小见 `build/update-final-artifacts.json`。没有换启动入口、没有结束用户已经运行的启动器或 IDE Java，没有启动游戏。

尚无高于 2.0.1 的原生正式包发布；后续发布需通过现有后台鉴权上传 API 提交对应平台完整依赖 ZIP 及版本标记，通过审核后自动检查即可取得。现有网页备用导入选择器仍面向旧构建文件，原生发布使用本轮已验证的上传 API；本轮没有修改下载站网页或 CI 构建流水线。源码和下载站协议已接通，Windows 下载/校验/替换/重启/失败恢复在隔离环境实测；没有把它描述为已经在用户安装目录执行过版本升级。

本轮按性能设计规范控制请求去重、有界元数据、单 worker、取消和页面可见性，避免 GUI 同步 I/O；这不是性能提速专项，没有编造提升百分比。既有跨路径性能报告仍见第 26～29 份文档。
