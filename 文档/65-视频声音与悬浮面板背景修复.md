# 视频声音与悬浮面板背景修复

本轮只处理首选视频后取消静音、悬浮面板误播背景和收起面板透明的问题。沿用原播放器、窗口外观状态与背景设置，不引入第二套媒体会话或计时器。

## 原因与修改

- 原 `DesignTokens.pageBackdrop` 直接读取“应用到所有页面”偏好，悬浮外观及吸附过程中背景已隐藏，透明配色却仍可能启用；`WindowFrame` 也会保留透明底。现在 `FloatingShell.pageBackdrop` 发布实际应用状态，窗口和公共令牌共用，面板不消费页面蒙层和白字配色。
- `WindowController.theme` 经 Main 向 FloatingShell 传入 `mediaAllowed`。悬浮面板清空实际媒体来源，销毁原视频 Loader 并停止轮播；背景偏好保留，切回页面外观恢复。普通窗口隐藏、吸附或游戏运行仍暂停同一播放器，不因瞬态重建来源。DockHandle 复用原 InteractiveSurface 的不透明中性色。
- 原 AudioOutput 仅在创建时取得默认输出设备，静音切换只写 muted，音量固定为 1。现在绑定 Qt MediaDevices 的当前默认输出，静音及音量同步更新，不重设媒体 source，不重建播放器，也不改系统音量。

## 检索与验证方法

已检索 BackdropMedia、BackdropCarousel.reload、FloatingShell、WindowFrame、DesignTokens、DockHandle、WindowController、背景偏好保存及原媒体回归。原有两层轮播和播放器即可复用，不新增业务所有者。只保留当前两层媒体，设备变化使用 Qt 原生事件，没有新增轮询或目录读取。

增加的音频诊断工具只用于开发：生成带已知音轨的小型 MP4，在实际原生 EXE 中通过设置文件选择器首次选择视频，再点击首页声音按钮；WASAPI 仅统计音频输出电平，不保存录音，不进入产品包。旧版在当前机器及该标准 AAC 样本中也能首次出声，未稳定复现用户现场的首次失声；因此不把设备跟随和音量同步推断为已经证明的唯一根因。用户后续确认使用蓝牙音箱，未确认是否在启动器打开后重新连接或切换过输出。

- Qt 6.8.1 / Windows 11：单文件原生 EXE 构建成功，已同步固定入口 `build/bugg.exe`，与 `D:/BuggBuild/launcher-single-file/bugg.exe` 的 SHA-256 相同：`2c357f7915f2aa0973d951474c0bd10572310cb114352aa5d5231b29f806c96a`。依赖审计仍只有 Windows 系统 DLL，没有新增运行依赖。
- 两个直接相关的原生回归 `backgrounds_cover_pages_with_double_blur_and_progress_touches_top`、`video_background_survives_preference_and_task_updates` 全部通过，没有跳过。覆盖首次选视频、声音开关不重建来源和播放器、任务/偏好更新不中断、面板清空来源和销毁音频输出、收起入口实色，以及返回普通窗口恢复播放。日志：`build/media-audio-panel-test.txt`。
- 在修正后的真实单文件 EXE 中，打开后通过设置的原生文件选择器首次选择视频，再回首页取消静音，未重启。WASAPI 输出初始静音均值为 0，首次取消静音均方根均值约 0.00679，再次取消静音约 0.00677；静音后的边界帧之外无持续输出。测量记录：`build/verification/media-audio-panel/after-first-selection/audio-levels.json`。此项证明该机器和 AAC 样本的实际出声，不只检查按钮或属性。
- QML 格式、qmllint、组件边界门禁、`git diff --check` 通过。

## 蓝牙音箱补充核查

上一轮真实 EXE 的默认输出是 ToDesk 虚拟音频，不能算作蓝牙验收。用户确认后，复用同一生产 `BackdropCarousel` / `BackdropMedia` 及 Windows 原生媒体后端，单独把测试程序输出设为可用的 HUAWEI Sound X 蓝牙音箱，并通过该设备的 WASAPI loopback 测量；不改系统默认设备，不连接麦克风，不保存录音。

开发命令为 `python research/probe_background_audio.py bluetooth-output.json --output-device HUAWEI`。结果保存在 `build/verification/media-audio-panel/bluetooth-output.json`：初始静音输出为 0；首次取消静音均方根均值约 0.08835，再次取消静音约 0.08811；媒体位置继续推进，无需重启。该结果覆盖实际蓝牙输出上的生产媒体组件，不冒充完整 EXE 经系统默认设备自动切换的实测。

同时核对所用 Qt 6.8.1 源码：Windows 默认输出变化及设备活动状态变化会发出设备变更通知，`MediaDevices.defaultAudioOutput` 随之更新，现有 `AudioOutput.device` 绑定交由媒体后端重新路由。没有增加蓝牙专属列表、轮询或重播逻辑。本轮无需再改产品代码或重新构建；蓝牙断连、休眠唤醒及用户原始失声尚未实机复现。
