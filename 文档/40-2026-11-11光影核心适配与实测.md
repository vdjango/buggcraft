# 光影核心适配与实际文件验证

用户要求安装光影前先准备支持核心，并亲自验证支持情况。本轮扩展现有原生目录、安装预检、任务与单文件事务，源站只增加候选清单；没有新建下载器、来源设置、依赖解析器或启动游戏。保留用户之前“不打开游戏，之后单独测试”的要求，以下证明下载、声明与安装路径，不把它等同于运行中的光影效果或 GPU 兼容验证。

## 用户流程

广场选择目标游戏与光影版本后，按目标 Minecraft/加载器解析 Iris 或 Oculus 及官方必需依赖。已有原版游戏缺加载器时，显示“为当前游戏补装光影支持”，确认后复用 installWithContent 的原位分支，保留实例 ID、存档、设置与客户端文件，只补加载器依赖；不要求重装游戏。没有安装目标时才走原有新建实例流程。具体目标变化后安装线程重新匹配。无兼容发布文件明确阻止安装，示例为 1.21.1 Forge。

预检只在原 worker 扫描活动 JAR 的 ZIP 目录，识别核心后才流式计算摘要；通过官方 hash→version 验证旧核心的确切版本/加载器。已改名的兼容核心保留原名，不叠加另一版本；禁用 JAR 不算已启用核心，多个核心提示冲突。已有 OptiFine 实例不自动叠加 Iris/Oculus；本轮不新增 OptiFine 安装器。

核心与必要依赖通过原 ResourceClient 的受控并发下载，各文件继续有任务明细。全部必需项成功后才提交光影 ZIP；失败/取消不把光影标成安装成功，已完成核心留作重试。普通模组仍保留用户要求的主模组先安装、依赖失败不回滚行为。

## 官方具体文件

依据 [Iris 官方说明](https://www.irisshaders.dev/)、[Oculus 官方项目](https://www.curseforge.com/minecraft/mc-mods/oculus)、[Modrinth 具体版本接口](https://docs.modrinth.com/api/operations/getprojectversions/)。项目级加载器标签只用于候选，实际安装必须满足具体文件的 game_versions、loaders 与摘要。

开发验证脚本实际下载文件，校验 SHA-1 和大小，并读取 fabric.mod.json、META-INF/mods.toml 或 META-INF/neoforge.mods.toml 与核心 class 入口。原始声明、摘要、依赖和 URL 在 build/verification/shader-support/official-files.json。另有原生产品服务实际安装记录 native-live.json，不用 Python 测试脚本代替产品实现。

| 实际核对目标 | 核心 | 必要依赖 |
| --- | --- | --- |
| 1.20.1 Fabric | Iris 1.7.6 | Sodium，按 Iris 指定版本 |
| 1.20.1 Quilt | Iris 1.7.6；发布文件声明支持 Quilt，JAR 使用 Fabric 元数据 | Sodium，按指定版本 |
| 1.21.1 NeoForge | Iris，按该加载器具体发布文件 | Sodium，按指定版本 |
| 26.3 NeoForge | Iris 1.11.7 | Sodium 0.9 系，按指定版本 |
| 1.20.1 Forge | Oculus 1.8.0 | Embeddium，按目标兼容版本 |
| 1.20.1 NeoForge | Oculus 1.8.0 的官方具体文件声明 | Embeddium；声明和归档检查通过，未单独运行此目标 |
| 1.21.1 Forge | 无匹配文件 | 阻止安装，不装 Fabric/NeoForge 核心 |

Iris/Oculus 的必需依赖以平台发布声明为输入，包内证据用于独立复核；不声称对任意第三方模组实现完整版本区间求解。优先发布者标记为 release 的候选；发布名包含 Beta 时仍原样显示，不伪称稳定版本。

## 实现与性能边界

检索并扩展 ContentProvider.resolve/versions/get、ContentCatalogSession.status、GameOperations.check_content_install/install_content、GameRuntime.inspect_content_install、LocalContentIndex、archive_entries/file_digest、ContentInstallOptions、旧版内容与安装流程。新增的跨模块 worker 方法及字段登记在第 12/18 号文档。

不在 GUI 线程扫描 JAR、哈希或请求元数据。仅检查 mods 中活动 .jar，识别后才哈希该核心；后续同文件复用原大小索引与摘要检查，不全量哈希无关资源。来源、超时、取消、并发预算、缓存和线程退出仍归原服务。通用 Windows/macOS/Linux 构建基线不变。本轮是正确性与安装接线，不宣称整体提速或 FPS 增益；未在 macOS/Linux 运行。

## 验收记录

Windows 11 x64、Qt 6.8.1、MSVC 2022 Release。固定入口保持预览首页.cmd → build/bugg.exe。测试在临时游戏目录完成，没有打开 Minecraft，也未关闭用户已有启动器。

- `build/shader-live-final.txt`：真实原生安装与改名复用通过，5 个目标分别下载核心、Sodium/Embeddium、MakeUp 光影；每项均核对落盘摘要，原始文件与依赖在 `build/verification/shader-support/native-live.json`。1.21.1 Forge 的无兼容核心路径也验证为失败。
- `build/shader-content-final.txt`：全量内容测试 35 passed、0 failed、7 个显式外部/性能场景 skipped。首次回归发现的源地址白名单未包含新同源路由、ListView 亚像素估算导致严格浮点断言失败，已分别修正为实际单入口约束和小于 1 逻辑像素的原位更新门槛；没有取消滚动回退检查。
- `build/shader-regression.txt`：sessions、catalogs、runtime、qml_component_boundaries 四组通过。`build/shader-qmllint-final.txt` 无输出。
- 源站 `data/validation/chengdu/shader-gateway-tests.log`：10 passed、1 个显式 PostgreSQL 场景 skipped；匿名清单不访问下载上游、非法参数拒绝。两域名实际 no-store/400/管理匿名 401 见 `shader-public-check.json`；Ruff 与生成索引检查通过。
- `build/shader-runtime-ui-focus.txt`：5 passed，补充实际 GameRuntime 的异步检查接线，确认已有改名核心的 shaderSupport 返回界面；重复/禁用核心、严格依赖失败/取消和原位更新均通过。
- `build/shader-ui-verified.txt`：同一生产 Main/ToolDeck 使用真实 Modrinth MakeUp 页面，410、800、960、1180 四尺寸的安装页、核心复用、错误、缺加载器与兼容游戏引导通过；测试验证安装按钮下沿仍在窗口内。常规/面板每个状态的截图均实际打开查看，另查看小/大尺寸。核心状态注入只在显式 UI 测试中，真实文件与已有核心验证来自上述原生安装测试，不把注入状态当业务证据。
- 实看首轮发现重复的兼容/依赖摘要挤高右栏，面板也超出首屏；已复用原组件精简光影元信息与纵向间距、翻译操作改同一行，重拍 `build/verification/content/live/shader/shader-core-*.png`。图文主体继续独立滚动，四种尺寸按钮可见；原模组/资源包表单保持既有信息。
- `build/verification/shader-support/native-entry/entry-result.json` 是告警前的历史运行记录。其 exe 哈希 `91da5cd199e0c2dbb8dee5043b2d787569fe7594083ac700bd7e509d28905041` 后被 Defender 隔离，不能再作为安全交付证明。详见第 41 号排查记录；没有恢复隔离文件。固定入口 CMD 保持不变，SHA-256 为 `83a46be27713cdb50f62aaea07acd31cabfde39102d1fecf3eb205f6d0faab51`。

## 当前游戏原位补装补充验证

- `build/shader-inplace-tests.log`：成功、加载器元数据失败、取消均通过，检查原实例 JSON、客户端、存档和设置保留。成功路径只有加载器 profile 和其库的两次 HTTP 请求，没有客户端或资源索引下载。
- `build/shader-inplace-live.log`：原生实际安装五个目标通过。首个 1.20.1 原版实例原位安装 Fabric、Iris、Sodium 与 MakeUp 光影，`native-live.json` 的 `installedIntoExistingVanilla` 和 `clientWorldSettingsPreserved` 均为 true。临时客户端文件用于确认保留行为，不代表已启动游戏；其余四个目标核对实际核心和光影摘要。
- `build/shader-inplace-ui-final.log`：当前实例 ID 必须传入补装页，标题必须为“补装光影支持”；原生页面四种尺寸录制。`build/verification/content/shader-core-inplace-*.png` 与同目录 required/reused/error/needs-loader 截图均需实看；页面明确保留已有内容，隐藏新实例命名入口。
- 最终 `build/shader-inplace-content-final.log`：36 passed、0 failed、7 个显式外部/性能场景 skipped；实际外部核心下载由单独的 live 测试完成。`build/shader-inplace-gates-final.log` 的 sessions/catalogs/runtime/qml_component_boundaries 四组通过，`build/shader-inplace-qmllint.log` 无输出、退出 0。首次未配置 Qt DLL 搜索路径的门禁启动报 0xc0000135，补齐工具运行环境后重跑全部四组通过，没有删除检查。
- 缺核心时先完成必要核心及其依赖，成功后才提交光影 ZIP；核心失败可重试已成功补装的加载器。已有其他加载器不被暗改，正在运行的实例提交和出队均拒绝修改。

源站发布 `20261111-shader-runtimes-r5`，上海与成都相同网关摘要 `41b44a90389a7eedffe503ffc1ff272443d521619911b1a3774ba395f3f6c922`；由线上 r4 隔离复制，原前端和存储保留。可将 current 回退 r4 并重启原服务；回退后新光影安装会明确缺清单，不静默绕过核心检查。
