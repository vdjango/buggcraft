# 2026-11-10 性能与界面验收

本轮在新版 C++/Qt/QML 内完成，不引入旧版 Python 运行依赖。唯一开发 Skill 已补入性能设计强制规则，并通过 Skill 校验器；项目入口和总览链接到 [性能设计与实测规范](26-性能设计与实测规范.md)。规则适用于 Windows、macOS、Linux；本轮实际运行环境仅为 Windows x64，不能据此宣称另两平台已测。

## 性能改动与测量方法

检索 `file_digest`、`verify_pack_file`、`export_pack` 和旧版整合包清单实现后，确认新版同一文件的不同摘要曾分别打开、读取。旧单摘要 API 无法表达一次计算多个摘要，故在既有 `platform/files/game_files` 扩展 `file_digests`；旧 API 委托它，整合包导出和验证复用同一实现。SHA-1/256/512 继续使用 Qt，不新增密码学依赖或手写 SIMD。

改动将同一文件合并为一次顺序读取，复用一个 1 MiB 缓冲；仍逐项计算全部要求的摘要，不省略验证，不缓存整包。输入错误、读错误和取消均失败，不发布部分结果。该优化针对可确认的重复 I/O；没有采集 CPU 火焰图，不声称已证明其他 CPU 热点。

Release 原本已是 `/O2 /Ob2 /DNDEBUG`，本轮没有把原有编译优化冒称新收益，也没有全局加入 `/arch:AVX2` 或 `-march=native`。生产入口移除了强制禁用 QML 编译缓存的环境设置；此项未做独立启动耗时 A/B，故不报告其提速比例。

测量入口为 [file_digest_test.cpp](../tests/performance/file_digest_test.cpp) 的 `paired_performance_report`，对照函数保留修改前的独立读取实现，仅存在测试中。每项 9 组成对样本，交替先后顺序；同一文件、Qt、构建和机器，预热后测量，数据生成和输出比较在计时外。每次输出均与对照完全比较。未清空操作系统文件缓存，因此这是暖缓存结果。

机器为 Intel Core i9-10850K、20 逻辑线程，Windows 11 x64，Qt 6.8.1，MSVC 2022 Release。最终基准运行时没有构建、界面套件或测试游戏并行；用户日常桌面与编辑器仍在运行，不宣称机器绝对空闲。原始样本、配置和计数说明见 [性能原始数据](27-性能原始数据.json)。

| 场景 | 优化前中位数（最小—最大） | 优化后中位数（最小—最大） | 耗时减少 | 应用读取量 / 打开次数 |
| --- | --- | --- | --- | --- |
| 128 MiB 文件，导出 SHA-1 + SHA-256 | 908.778 ms（903.410—931.716） | 828.476 ms（810.645—870.573） | **8.84%** | 256 → 128 MiB；2 → 1 |
| 128 MiB 文件，验证 SHA-1 + SHA-256 + SHA-512 | 1402.158 ms（1395.657—1426.991） | 1273.269 ms（1259.851—1304.510） | **9.19%** | 384 → 128 MiB；3 → 1 |
| 400 × 64 KiB 文件，导出 SHA-1 + SHA-256 | 414.561 ms（402.202—501.337） | 278.290 ms（269.211—335.341） | **32.87%** | 50 → 25 MiB；800 → 400 |

读取量和打开次数是应用操作产生的逻辑计数，不是物理磁盘吞吐测量。数据仅代表上述摘要阶段，**不能解释为整包导出、整体启动、下载速度或游戏 FPS 提升相同比例**。未测冷缓存、macOS、Linux 和 ARM64；没有虚构这些平台的结果。

复现方式（先构建 Release 的 `file_digest_test`；Windows 需将当前 Qt 的 bin 加入 PATH）：

```powershell
$env:BUGG_PERFORMANCE_REPORT = "$PWD/build/performance-digests-final.json"
& ./build/file_digest_test.exe -o ./build/performance-digests-final-test.txt,txt
```

正确性覆盖空文件、短文件、1 MiB 块边界、多块文件、三种摘要与重复算法，以及取消、缺失文件和不支持的算法。原生整合包导出、房间同步摘要不符、取消与原子发布测试也通过。测量套件 5 passed；原始测试日志为 `build/performance-digests-final-test.txt`。

## 功能与复用

- 好友页复用 `ListRow`、`FriendActions`、`RoomChat`：常规窗口左侧 232 px 联系人栏，右侧标题/操作/会话区铺满；私聊明确显示“待实现”，输入禁用，不伪造消息。面板恢复搜索。自己的信息改为明确的“我的好友码”，省去重复用户名。
- “联机通知”“好友申请”两个常驻服务会话复用 `MultiplayerService` 的同一通知快照，按最新接收时间排序；分别计未读和标记已读，不创建第二套通知服务。邀请和加入申请归联机通知，好友申请独立。没有刷新按钮，更新沿用原 heartbeat。
- 大厅面板恢复搜索，最多显示 3 个房间并分页。加入等待复用 `ProgressItem` 和真实 `roomBusy`。建房允许已有游戏运行；`launch_progress` 保留建房前状态，房间和创建页在 preparing/running/stopping 时锁定实例。
- 四种外观共用 `DesignTokens` 的控件高度、字号、图标和列表密度；不复制面板专用按钮/输入框。语言项按控件的界面方向统一对齐，保留文字自身双向排版。
- 渐变复用 `BackdropPalette` 和 `InteractiveSurface`：直接采用背景平均色，版本最左侧 15%、房间摘要 10%，向右消失。保留已有首页内容布局，面板不硬塞房间摘要。
- `EdgeDock` 复用已有折叠定时器和指针采样；重复离开不重启计时，拖动结束重新判断位置与指针，修复跨边缘后长期不收起。空白区域拖动与输入控件拖动保持互斥。
- `GameRuntime.clear_task_history` 只移除终态记录和重试规格，保留排队/活动任务及文件，沿用现有持久化。页面仅发命令。测试清理补齐“建房前游戏已启动、尚未收集窗口”的失败路径，只清理本次测试子进程。
- 内容入口沿用实例详情的“模组与资源”管理模组、资源包、光影包；整合包沿用游戏库的导入及实例导出。它们有明确实例归属，不放进好友/联机或另建一套文件管理器。本轮没有新增尚未接入的在线内容商店。

## 真实联机与边界

使用两个隔离的本启动器客户端，原生 C++ 服务及实际 bridge/core，对接隔离 TLS 节点夹具；浏览器批准由测试夹具完成，没有要求用户反复打开过期链接，也没有改系统信任。身份为 NativeHost/NativeGuest 离线游戏身份。房间、成员、聊天、独立实例同步和游戏启动均由产品原生实现负责，Python 只做测试设置与操作。

在 `build/native-current-clients` 的原生流程中，已验证先启动 Minecraft 再创建房间、加入邀请、聊天、私有文件同步（SHA-256 相同）、复用与全新安装，以及两个真实 Minecraft 1.20.1 窗口。随后实际开放房主世界，成员从彩色【BUGG联机】局域网条目进入；房主日志出现 `NativeGuest[/127.0.0.1:59348] logged in`。现场截图 `verified-host-world.png`、`verified-guest-world.png` 与 `world-verification.json` 留在同目录。该次操作中重启过测试游戏，旧句柄使自动化收尾无法作为整条脚本通过的证明，不能隐瞒这个区别。

最终另用 `build/native-final-clients` 完整重跑原生桌面流程，退出码 0；`build/final-multiclient.log` 和该目录 `results.json` 记录 10 项验证：游戏运行中建房并锁定实例、邀请加入、跨客户端聊天、私有文件 SHA-256 一致、房主收到成员准备状态、复用配置创建独立实例且原实例不变、全新安装、安装/启动互斥、两个真实 Minecraft 窗口、双方离开/关闭房间。此轮不把前一次手动世界验证冒充自动脚本步骤，两份证据分别保留。

实际查看最终 `host-chat-received.png`、`host-member-status.png`、`host-members-ready.png`、`guest-sync-complete.png`：聊天内容确实抵达另一客户端，成员状态从检查文件变为已就绪，配置匹配后仅提供启动操作。为使真实聊天可被系统辅助功能及测试读取，在已有消息正文 `UiText` 上声明 StaticText/名称和作者描述，未创建第二套聊天状态。测试中发现 UIA Toggle/Expand 没有触发自定义控件的用户信号，改用真实点击；UIA 文本读取采用 Accessible 名称。修正均在测试输入层，没有让测试替代产品业务。

最后通过系统进程列表核对：本轮两款测试游戏及隔离启动器均已关闭，无测试 Java 进程遗留。清理只匹配本次测试的进程树和测试目录，不关闭编辑器 Java 或用户原有启动器。

离线身份的自动快捷加入仍有边界：Minecraft 普通服务器 QuickPlay 不设置 LAN 标志，会触发无效会话；手动选择同一 127 地址的局域网条目可进入。本轮离线房间启动不传普通 QuickPlay 参数，保留 LAN 广播，并提示打开多人游戏选择【BUGG联机】；微软身份仍沿用既有刷新凭据和 QuickPlay。没有注入游戏 Agent/模组，**离线自动直接入场尚未完成**，也未以离线测试宣称微软线上会话已验证。

源站缓存继续复用既有缓存服务协议和真实进度；低速回退由源站决定，没有在启动器新增 512 KiB/s 本地测速规则。本轮原生缓存用例验证只上传源站请求的文件及未配置/空清单状态；不能据此宣称公网源站的全链路性能已经测量。
