# 下载源与任务引擎

当前真实游戏目录接线见 [21-游戏目录与多源适配](21-游戏目录与多源适配.md)。目录 query/cancel 与文件下载是不同用例，所有网络复用 HttpClient。在线四类通过 ContentCatalogService/Session 查询，安装复用 GameRuntime→GameOperations→ResourceClient。详见 [在线内容接入](31-2026-11-10在线内容接入.md)。

## 2026-11-11 下载修复契约（已实现并完成针对性回归）

ResourceClient 仍唯一拥有来源、校验及批次调度；设置并发按核心、库、assets、模组、资源包、光影包、Java 等资源组分别限制，同批不同组同时推进。prepare_files 合并已知游戏文件与整合包资源，处理器仍等待必需文件。临时网络/429/5xx 有界重试，已校验文件复用。HttpClient 对已知大小/摘要的大文件支持三个 Range 分段，严格核对 206/Content-Range，合并后完整校验再原子提交；不支持则回退普通下载，取消撤销全部分段。

## 一份优先级、按能力适配

用户只调整一份“下载源优先级”，默认 BUGG → BMCLAPI → 官方。没有按游戏/加载器/模组分别设置的第二套状态，也不提供自动择优开关。上移/下移调整顺序，全部来源保留，不因界面选择漏掉能力。

`contracts/download_sources.*` 是来源能力登记与补齐规则的唯一所有者。每个源登记能力和缺项补齐源；`resolve_sources(order, capability)` 按优先级生成实际来源队列，无 I/O、不重试，同一实际源只保留第一次出现。目录服务消费统一 CatalogQuery/CatalogResult；后续内容服务消费统一内容查询/结果契约，不让页面处理不同源的 JSON。

| 所选源 | Minecraft / Forge / NeoForge / Fabric / Quilt 目录 | CurseForge / Modrinth 内容接口 |
| --- | --- | --- |
| BMCLAPI | BMCLAPI | 官方；BMCLAPI 不提供此能力 |
| BUGG | BUGG | 同一源基址的 `/v1/catalog/curseforge` 与 `/v1/catalog/modrinth` |
| 官方 | 对应发布者官方接口 | 对应平台官方接口，按平台认证要求调用 |

默认顺序下，游戏目录实际队列为 BUGG → BMCLAPI → 官方；CurseForge/Modrinth 为 BUGG → 官方。若用户把 BMCLAPI 放第一，内容队列为官方 → BUGG，后面的官方被去重；这正是“BMCLAPI 不支持时默认走官方”。同一官方候选失败不在队尾重试一遍。

“缺能力”由登记表确定；超时、404、损坏数据、限流和鉴权失败是实际请求错误，交给现有服务在已生成队列中继续。有效空列表/无兼容版本也是当前候选未找到，继续下一候选，但不能把全局 Quilt 列表假报为兼容。队列全部有效为空才返回无兼容；全部失败或夹杂失败且无成功结果时保留明确原因。取消立即中止队列，不触发下一源。

文件批次的连接健康归 ResourceClient：HttpClient 以 unreachable(url) 明确报告 DNS、连接、TLS 或传输超时，同一任务内该 origin 冷却 60 秒，后续文件优先尝试队列中下一个可用候选；到期恢复原优先级。404、摘要错误、磁盘错误和用户取消不判定整个源离线；没有其他候选时仍尝试当前候选。目录的请求级失败冷却仍归 GameCatalogService，不复制其目录缓存规则。ResourceClient 可注入同线程 HttpClient 以验证回退，默认持有自身客户端。

补齐只走登记的一个目标，目标也不支持则明确失败，无递归和环。实际来源进入结果/任务快照，页面不把官方结果标成 BMCLAPI。官方 CurseForge 若要求凭据，交给认证/源站授权契约；禁止在客户端硬编码私钥，缺凭据明确失败并按队列继续，不能假报查询成功。

新源接入顺序：核实协议 → 登记能力 → 实现相应领域适配器 → 注册工厂 → 适配契约测试。不得新造页面请求器、HTTP 客户端、通用万能 provider 或独立重试循环。游戏、内容和文件传输各有领域端口，复用同一来源设置、能力决策与网络机制。

## Bugg 唯一入口（2026-11-10 修正）

`SourceSettings` 同时拥有来源顺序和唯一 `bugg_base_url`，默认 `https://mirror.bugg.icu`，在“设置→下载源”修改并持久化。`contracts/download_sources::source_url` 是镜像基址与路径的唯一拼接处；分类、搜索、详情、版本、依赖、整合包元数据、游戏目录和资源文件不得各存一份 Bugg 域名。`download.bugg.icu` 是旧下载站，不作为新源入口。

GUI 配置变化只发一次 `configuration_changed`；app 把顺序和基址快照同时交给目录、内容和游戏服务。查询服务取消旧请求，清除或隔离旧入口缓存并重新查询。游戏工作任务捕获启动时的基址和顺序，运行中不读取全局可变配置。官方发布者地址、下载响应中的文件地址及包导入的可信域名列表不是第二份源配置。

`ContentEndpoints` 只允许一份 Bugg 基址；官方平台地址保留为协议适配及测试注入，不能按请求类型绕过所选源。BMCLAPI 缺内容能力时仍按能力登记补齐官方；Bugg 请求失败只沿既定优先级回退，不临时发明另一个 Bugg 地址。

## 分清五件事

1. **CatalogProvider** 查项目、版本、文件元信息，可返回 CurseForge/Modrinth/Buggcraft 的项目 ID、候选地址、文件大小与哈希。搜索不等于下载。
2. **SourceResolver** 根据已知哈希优先精确找候选，哈希不足时再用规范化标题、长词组合、词尾单复数退化搜索；候选仍需与已知哈希/大小交叉核对，名字相似不是可信文件。
3. **SourcePolicy** 按唯一来源优先级和能力登记决定实际适配器。当前纯决策在 contracts/download_sources；未来文件策略扩展此规则，不另存每种资源的排序。调整顺序取消旧目录请求并重查；未来文件任务记录策略版本，在安全检查点切换，不能混写不同内容分片。
4. **TransferService** 只管 URL 请求、重定向、Range/ETag、临时文件、速度计算、校验与落盘；它不决定“该下哪个模组”。
5. **TaskManager** 管安装和下载任务的状态、子文件、日志、取消、恢复与持久化。所有页面通过 TaskId 观察它。

模块内按 SourcePolicy、SourceResolver、TransferService、TransferJournal、FailureQueue、TaskManager 分文件/类，单一职责；整合包、加载器、游戏资源、房间同步只调用契约，不复制下载循环。

## 候选和失败

下载站镜像不是所有 URL 的简单域名替换；每个候选必须有来源类型、可访问地址、预期文件信息和重定向策略。复用统一的实际来源队列与有界重试，不在每种内容另写循环。所有网络错误、超时、HTTP 不可用、无候选、哈希不一致分别记录；哈希不符不可继续安装。第一阶段不做多源分片或启动时全源测速。

## 文件下载状态机

    已排队 → 查候选 → 连接中 → 接收中 → 校验 → 已完成
                   ↓           ↓          ↓
                 换来源 ← 临时失败 ← 校验失败
                   ↓
             等待补齐 / 已取消

任务还有“暂停中、继续中、安装中、失败、完成”。失败队列只保存未完成文件的 FileId、目标路径、预期大小/哈希、已尝试候选、错误和下次可重试时间；成功文件保留校验记录，重启后只验证必要元数据或哈希后复用，不把整个整合包再下载一次。必需文件没齐时禁止启动；可选资源包/光影可以在确认后跳过。

默认每个来源最多 6 次**有界**自动尝试，瞬时错误间隔 3 秒；404、确知无此文件、哈希错等不适合重复请求的错误立即换源。取消不等 3 秒，禁用来源立即停止下一轮；网络请求必须有连接/空闲/总超时和可中断句柄。最后保留“继续补齐”入口，并明确剩余数，例如“已完成 216/229，正在补齐 13 个”。

## 原子性和速度

- 同一目标路径按 FileId 加锁，下载写到便携缓存的 .part；仅在预期哈希、大小都通过后原子改名。下载源切换时有效部分仅在 ETag/Range/同一内容确认后复用，否则丢弃分片重下该文件，其他已成功文件不动。
- 每个文件与总任务同时显示来源名称、阶段、接收字节和经过短时间窗平滑的实际速度；0 B/s 显示为“等待数据”，不消失。无法得知总大小时显示字节和阶段，不显示虚假百分比。
- 取消操作先让 UI 恢复交互，后台关闭请求与文件句柄并清理；切换页面只卸载观察者，不阻塞任务。进程重启重建 TaskJournal，再确认临时文件后续传。
- 测试覆盖来源配置在运行中变化、部分成功后失败、重复文件、取消后立即切换页、短连接断开、重定向、速度未更新、重启恢复和哈希篡改。

## 我们的源：重定向优先、缓存慎用

源站有独立的“资源可用性清单/来源观测数据”，管理员可导入和维护；**判断是否直连/重定向，先查已有数据，不在用户提出请求时把远端文件完整下载一遍测速。** 可信、快且稳定的文件直接重定向；可见的慢源或不可用文件才考虑缓存单个实体。整合包 ZIP 只允许作为普通下载对象重定向，不把整包当作房间缓存内容。

房主同步时先发送客户端内**文件信息**（相对路径、类型、大小、哈希、候选来源），源站返回“无需缓存/重定向”或“请求上传的单个文件清单”；获授权后只传被请求的模组、游戏核心、加载器、库、资源等实体文件。身份仅用于核实上传权限，下载行为遵循源站普通分发策略。新项目不能绕过已有源站与节点接口再发明第二套服务；协议及后台页面需与服务端对齐验收。

房间缓存默认 8 小时、后台可调、最长 32 小时，仅约束房间客户端临时缓存，不影响常规镜像资源。相同哈希实体用一份对象存储，多个房间各有独立引用到期时间；回收条件是**所有**有效房间引用都过期，先后创建不会错误缩短别人的有效期。过期对玩家无需逐秒展示，房主只看本次同步结果与“临时加速约 8 小时”的说明。未公开/敏感文件可被他人取得，房主勾选前要明确提醒勿共享敏感内容。


## 已落地的文件执行层（2026-11-08）

SourceCapability::GameResources 登记游戏文件能力，ResourceClient.resource_urls 复用 resolve_sources 的默认顺序/补齐/去重计划。Mojang 核心/资源、Minecraft Maven、Forge/NeoForge、Fabric/Quilt 元数据与 Maven 的路径映射集中在此；动态 query 和未知镜像能力使用官方候选，来源失败按计划逐个回退。目录查询继续使用 GameCatalogProvider，不在页面写 URL。

HttpClient 同一实现扩展 GET/POST、流式 QSaveFile、SHA-1/大小校验、超时与取消；资源服务最多 6 路，缓存有效则不下载。重试复用完整且校验通过的文件；本轮没有实现跨进程任务日志和单文件 HTTP Range 断点续传，不能宣称已有。安装取消不提交实例 JSON，也不把未完成临时文件当缓存。

2026-11-10：HttpClient 仅在 HttpRequest.sha1 非空时创建并更新 SHA-1 状态；未提供预期摘要的请求不计算无人使用的 SHA-1。提供摘要时继续逐字节验证，错误不提交文件；expected_size、maximum_bytes、TLS/重定向、取消和 QSaveFile 提交规则不变。调用方的 SHA-256/512 最终核对不受影响，未改变任何来源策略或低速缓存规则。

安装处理器有时分别使用同一 Maven 库的不同版本，下载阶段保留全部需要的文件；最终游戏命令才按继承规则选择有效版本，classpath 和参数在所有贡献合并后统一去重。文件校验、传输、ZIP 与 Java 方法均登记在第 18/22 份文档；禁止未来房间再写一套。

## 2026-11-12 持久续传契约

HttpClient 扩展 HttpRequest.resume，只有 GET、明确 SHA-1/大小的文件可保留暂存；ResourceClient 在原文件请求启用，不增加下载器。暂存按目标文件名/摘要/大小隔离，使用独占写锁；失败、取消或重启后校验前缀、以精确 Range 续接。忽略 Range 时从完整响应重来，错误区间拒绝拼接，摘要不符丢弃。完整核验后通过 QSaveFile 原子替换。原三分段保持，失败进入可续传普通请求；有普通暂存时直接续接。无摘要不保存可恢复片段。旧“不支持单文件续传”的记录为历史，新增能力按本轮证据验收。
