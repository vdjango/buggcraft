# 代码规范与复用门禁

## 唯一风格

**新项目统一 Google C++ 风格，以根目录 .clang-format 为唯一机器可执行格式。** C++20；类/结构名 UpperCamelCase，方法/变量 snake_case，常量 kUpperCamelCase，私有成员 trailing underscore，头文件按模块边界 include。调用 Qt 已有 API 保留其原生名称，不为适配风格包一层无价值方法。禁止每个模块自定缩进/命名、手工对齐长列表或混用第二套格式。Qt 对象和信号同样遵守本项目 snake_case，连接使用强类型 connect。配置见 [clang-format 官方选项](https://clang.llvm.org/docs/ClangFormatStyleOptions.html)。

QML 统一遵循 Qt 官方 QML 书写顺序：id → property → signal → JS 函数 → 对象属性 → 子对象，由 qmlformat 和 qmllint 检查；这是 QML 语言自身约定，不是第二套 C++ 风格。参考 [Qt QML 编码约定](https://doc.qt.io/qt-6.8/qml-codingconventions.html)。QML 的 JavaScript 只处理轻量显示行为，不实现下载、路径、联机、哈希或安装规则。

头文件只公开必要类型/契约，具体实现留 .cpp；避免全局单例、catch-all 隐藏错误、魔法状态字符串和直接跨线程改 UI。所有权优先 RAII；QObject 子对象用 Qt parent，非 QObject 用值类型/unique_ptr，避免二者叠加造成双重释放。错误用具名类型和结果值，取消是独立结果，不当作普通网络失败。

## 写代码前的强制检索

本项目必须使用 `$bugg-cpp-qml` Skill；入口在 AGENTS.md。已存在的符号先查 [已有方法与组件复用索引](18-已有方法与组件复用索引.md)，再读具体源码与调用方。本门禁适用于新方法、类、lambda、QML 事件处理器和新增业务代码块，不能以“没有新建函数”绕过查重。同一行为优先调用已有方法；需要扩展就在唯一所有者中补足，禁止复制后换名。

1. 先读 [12-共享接口与能力目录](12-共享接口与能力目录.md) 的责任表，再搜索目标名和语义：rg -n "SourcePolicy|retry|来源|镜像" src tests 文档。多个语言名称可分次搜。
2. 去现行项目查旧流程和测试：例如 rg -n "source_order|resolve_download_urls|download_error_message" E:/code/buggcraft/src E:/code/buggcraft/tests。确定已有行为和需保留的输入/输出，不直接复制实现。
3. 写下“现有服务/方法是否可用；若不可用，缺少什么契约；新增方法由哪个模块拥有”。找不到归属先改能力目录或 ADR，不新建 common2/util_extra。
4. 搜索本模块和相邻模块是否已经写同一重试/缓存/路径/校验流程；有则合并到所有者，新增调用方通过接口进入。
5. 更新或补齐功能文档和测试，再实施。代码评审用 [13-开发任务与变更模板](13-开发任务与变更模板.md) 留下检索证据。

禁止以“这个文件太大”为唯一拆分理由；按业务责任、线程边界和状态机拆。也不为了所谓代码复用率把两个含义不同的流程硬塞进通用基类。

## 书写标注

公共 C++ 类在头文件用 Doxygen 风格 `///` 或 `/** */` 标明职责、所属模块、线程与副作用。公共方法说明非显然的输入约束、结果、失败、取消和幂等行为；相关方法共享同一约束时可以在方法组上标注，简单 getter 不逐句重复代码。规则细节和调用链放能力目录，注释说明“为什么/受什么约束”，不堆砌无信息的逐行翻译。

```cpp
/// GUI 线程呈现模型；消费已确认身份，不做磁盘或网络 I/O。
class LaunchSession : public QObject {
 public:
  /// 返回空串表示身份确认通过；否则返回可读原因。can_start/start 共用。
  Q_INVOKABLE QString preflight() const;
  /// index 为现有实例索引；无身份发 identity_required，重复活动请求忽略。
  Q_INVOKABLE void start(int index);
};
```

QML 组件注明职责和输入/输出/状态所有者；信号只表达意图，状态由调用方或 C++ 所有者持有。通用交互标注在共享组件，不在每个使用页复制。对于异步任务、取消句柄和生命周期连接，标明线程回调与迟到结果处理。开发模拟必须明确写“模拟/预览”，不能写成真实服务已接入。待实现项说明缺少的具体能力，不添加含糊 TODO 堆积。

新增/删除/改名符号同步维护索引；修改公开契约同步能力目录和对应领域文档。页面宽度固定为常规 960、面板 410；未经用户要求不为容纳内容扩大窗口。

## 质量门禁

生命周期相关实现先读 [启动器生命周期与资源管理](19-启动器生命周期与资源管理.md)，不能按页面另写任务、身份或退出状态机。QML 组件边界检查运行 `cmake -P cmake/check_qml_boundaries.cmake`，同一检查已注册到 CTest；它阻止 Pages/Main 内联通用视觉和交互基础类型，不能以通过该检查代替语义复用检索。

- 本地与 CI：clang-format/qmlformat/qmllint 检查 → 静态分析/模块依赖规则 → 直接相关的单元与契约测试 → 必需平台编译 → 打包。打包完成不追加重复功能测试；产物 SHA、体积和必要清单属于打包元数据。
- 测试无网络的纯领域规则：来源顺序、哈希筛选、任务状态、重名决策、缓存到期交集、便携路径。适配器契约用受控假服务，真实跨网下载因不可达可跳过并标注，不让它误报为业务失败。
- 新增非 Qt 核心类必须可注入时钟、网络和存储接口，不依赖真实用户目录/全局状态才能测试。GUI 响应性用启动后拖动、取消和切页的真实交互验收。
- 依赖图中出现 UI→网络实现、模块 A→模块 B/infrastructure、多个 SourcePolicy 或多个 PortablePaths 直接阻断合入。

## 复用率如何看

不设置“代码复用率 80%”之类易被滥用的 KPI。看同一业务规则是否只有一处真相：来源顺序 1 处、文件重试 1 处、哈希核验 1 处、便携根解析 1 处、重名决策 1 处、任务状态机 1 处；关注重复决策数和调用方数量。减少行数不能替代正确的兼容性与可读性。
