# 自编译精简 Qt 与完整包体积实测

## 本次结果

7 MB 指的是原来的启动器 EXE，不包括 Qt、联机桥及依赖。本轮实际从 Qt 6.8.1 源码构建了独立 Windows x64 静态套件，再用相同启动器源码对照；完整离线实验包的 7z 从 21,196,289 B 降至 **16,207,494 B**，减少 **23.54%**。ZIP 从 32,120,578 B 降至 **23,323,777 B**，减少 **27.39%**。完整包尚未达到 10 MB。

所有 MB 按十进制；静态包 7z 为 15.46 MiB。它包含原生联机桥及其实际 DLL 依赖，不需要另行下载 Qt。它是未签名的本地验证样包，没有替换另一个窗口正在构建的 `build/bugg.exe`，也没有上传发布或部署。

## 实际裁剪

- Qt 仅构建 qtbase、qtshadertools、qtdeclarative、qtsvg、qtimageformats；关闭 Qt 示例、测试和基准的构建。
- Windows 专用套件关闭 Widgets、PrintSupport、SQL、DBus、OpenGL、Vulkan；保留 D3D 渲染与 Qt Quick 软件渲染。此配置不能原样用于 macOS/Linux。
- Quick Controls 保留产品已经选择的 Basic 样式；关闭其他样式、QML 调试/Profiler、Quick Designer 和未用粒子功能。
- 保留 PNG、JPEG、WebP、SVG、中文字体及输入、可访问性、Markdown/富文本、网络代理和系统 Schannel TLS；不为省体积删除语言或改写密码算法。
- 应用启用 `BUGG_OPTIMIZE_SIZE`：MSVC `/O1 /Gy /Gw`、LTO、`/OPT:REF /OPT:ICF`。应用模块跟随 Qt 套件选择静态/动态方式，静态时显式链接自己的 QML 插件；Windows 精简配置排除未用平台与 TGA/WBMP/ICNS 插件。
- Qt 各 SIMD 实现仍由库自身进行硬件分派，未全局使用 `/arch:AVX2` 或本机架构。体积收益不是指令集吞吐收益，也不是游戏帧率提升。

Qt 的静态链接、体积优化和链接器回收依据见 [Qt 6.8 优化构建](https://doc.qt.io/qt-6.8/build-optimized-qt.html)；插件选取依据见 [qt_import_plugins](https://doc.qt.io/qt-6.8/qt-import-plugins.html)。本表是实际构建测量，不是官方文档的理论估算。

## 可复现入口

使用 MSVC x64 开发者命令行，将 Ninja 加入 PATH。源码固定 Qt 6.8.1 的五个官方归档及 SHA-256；仓库脚本校验已有缓存和新下载。普通 Qt 套件保持独立。

```powershell
cmake -DPARALLEL=2 -P tools/build_size_qt.cmake

# 新构建目录，不能在原来的动态 Qt 缓存里更换套件。
cmake -S . -B build/size-static -G Ninja `
  -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF -DBUGG_OPTIMIZE_SIZE=ON `
  -DCMAKE_PREFIX_PATH=E:/code/.build-envs/qt-size-6.8.1/static `
  -DCMAKE_TOOLCHAIN_FILE=E:/code/.build-envs/qt-size-6.8.1/static/lib/cmake/Qt6/qt.toolchain.cmake `
  -DQt6LinguistTools_DIR=E:/code/.tools/Qt/6.8.1/msvc2022_64/lib/cmake/Qt6LinguistTools
cmake --build build/size-static --target bugg --parallel 2
```

LinguistTools 是同版本构建期翻译工具，不进入玩家包。脚本默认 Qt 构建并发为 6，低内存机器应降低；静态 LTO 链接会占用数 GB 内存。不要在应用链接同一套件时同时重新安装 Qt。首次脚本验收遇到该文件占用，应用链接结束后重跑成功；失败日志不能当作通过。最终仓库脚本顺序验证通过，日志在 `qt-recipe-verification.log`。

应用 `BUGG_OPTIMIZE_SIZE` 默认关闭，现有构建和固定预览入口没有被切换。脚本当前仅声明 Windows x64 实测配置；其他系统和架构需要对应套件、签名及测试，不能由本结果推断。

## 功能与安全验证

- 静态 Qt 实际读写 PNG/JPEG/WebP，实际解码 SVG；使用 Schannel 和系统证书成功获取 Minecraft 官方 HTTPS 版本清单。
- 原有 `RuntimeTest` 的语言切换、HTTP 下载原子提交/摘要校验、真实窗口关闭和生命周期测试通过：6 passed、0 failed、0 skipped（含初始化/清理）。
- 原有 `ContentTest` 的富文本图片解析和四种窗口尺寸内容流程通过：4 passed、0 failed、0 skipped（含初始化/清理）；沿用现有服务器夹具、模型和截图流程，未复制业务逻辑。日志保留了页面切换时的 `DelegateModel::cancel: index out range` 警告，没有把通过说成无警告。
- 样包以清除 Qt/QML 开发环境变量、只保留 Windows 系统 PATH 的环境实际启动。常规、面板、软件渲染和设置路由捕获成功；查看了软件渲染主页及内容详情的常规/面板截图。首次 1.3 秒硬件截图仍在初始化，只证明能加载，不用它声称界面就绪耗时。
- 测试 EXE、QtTest、PDB/LIB、CMake 开发文件、Python SDK 示例均未进入这份 30 文件样包。旧实验包曾把 `share` 中的一个 Python SDK 示例误复制到 licenses，新样包已按运行用途排除；原生程序没有 Python 运行依赖。
- 7z 完整性和 ZIP CRC 检查通过；Defender 对完整静态样包自定义扫描未发现威胁。不使用 UPX 或额外壳；未进行 Authenticode 签名、SmartScreen 声誉或其他杀软验收。

原生桥使用上一轮同一份字节产物，本轮只检查其仍在完整包中；桥转发回归见第 42 份报告，不把旧回归当成重新执行。真实 Microsoft 登录、游戏启动、公网联机及原生文件对话框交互未在本轮完整复验；保留模块不等于所有交互均已验收。
