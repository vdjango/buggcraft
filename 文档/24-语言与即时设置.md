# 语言、内存与即时设置

## 按需语言包（2026-11-11）

界面源文案简体中文内置；其他语言的 QM 作为发布版本的独立资产，不进入主程序或便携包。构建时生成内置格式 1 清单（版本、语言代码、文件名、大小、SHA-1/SHA-256）；文件名 `Bugg-language-<SHA-256>.qm`。运行时只下载编译清单内的文件，不信任远端新增语言或路径。沿用下载站 `/api/launcher/assets/<版本>/<文件名>` 和原有发布/撤回机制，语言附件不进入玩家的安装包列表。

LanguageService 是应用寿命的唯一请求/翻译所有者：GUI 的 set_code 接受语言选择，后台单工作复用 ResourceClient、valid_file/file_digest，校验缓存或下载，成功后才在 GUI 安装 QTranslator 并发布 changed。当前语言在下载/失败时保持；status 表示 requestedCode/state/error，取消和新选择使旧代次失效。单个包最大 256 KiB，仅一个在途任务和一个最新待处理选择。失败可重试，不删除其他已校验语言；重新启动离线复用缓存。缓存随便携根搬迁；改变缓存根取消旧工作并在新位置重试。退出由 ApplicationLifecycle 调用 shutdown 并异步等待 drained，禁止 GUI 等待线程。

options 继续列出本版本所有已生成 QM 的语言及自称/地区；不再要求它们内嵌。首次选择才下载，无全量预取。游戏语言代码、游戏 options.txt 和偏好保存仍归原所有者；UI 只发意图，新增等待/失败/取消呈现复用 LoadingIndicator、UiText、ActionButton。

本轮契约（2026-11-08）。新增前已检索 GameRuntime.instance_settings/save_settings、PageStateStore、SelectField、CheckOption、SettingRow、ProgressSurface，以及旧版 game_languages.py、qml_settings.py、SettingsForm.qml。沿用现有配置保存、任务流水线和组件；不复制旧 QML，也不增加 Python 运行依赖。

## 唯一所有者

| 能力 | 所有者与接口 | 线程和失败 |
| --- | --- | --- |
| 真实实例与外部变化 | GameRuntime.refresh_instances、目录监听与短时合并 | 后台扫描；新增目录尚无 JSON 时继续监听，坏记录不影响其他游戏；初始化期间首页不能显示安装结论 |
| 全局/实例游戏设置 | GameRuntime.instance_settings(id)、save_instance_settings、set_game_setting | id 为空表示全局默认，实例覆盖逐键合并；快照立即更新，复用串行原子保存，只有失败提示；运行中的游戏参数不被修改 |
| 启动器通用设置 | GameRuntime.preferences、set_preference(key,value) | 语言、下载并发、启动后行为统一校验，后台保存；切页不丢设置 |
| 语言列表和界面译文 | LanguageService（QObject 持有 QTranslator） | languages.json 仅提供语言自称/地区；只列已编译 QM 的界面语言。游戏资产索引单独决定游戏本身支持范围；qsTr/tr 统一翻译，retranslate 切换且保留页面/任务 |
| 游戏语言与窗口 | GameOperations.prepare 的同一准备边界 | 后台原子更新当前实例 options.txt 的 lang/fullscreen，保留未知项；参数合并最后才去重，不另造房间启动路径 |
| 内存界面 | DesignSystem.MemoryControl、ValueSlider | 全局与实例页共用；滑块/输入发编辑意图，自动模式隐藏手动编辑；显示真实物理/可用内存，不靠动画伪造用量 |

GameRuntime 的设置读取/保存仍汇入 ApplicationLifecycle 初始化和退出，禁止语言模块另存第二份配置、页面 Timer 写盘或监听目录后在 GUI 扫描。

### 实例扫描的索引复用（2026-11-10）

`game_language_codes` 继续是语言索引读取的唯一实现。可接收调用方拥有的 `QHash<QString, QStringList>*` 扫描缓存，默认空指针保持每次读盘；键在该函数内由 `safe_path` 生成完整资产索引路径，不能只用版本或索引 ID。缓存仅保存成功解析得到的代码列表，不持有完整 JSON；读取失败不写缓存。

`scan_instances` 每次后台扫描创建一个局部缓存，多个实例共用索引时只读取和解析一次，工作结束立即释放。下一次扫描、切游戏目录和启动前应用游戏选项均重新读取，不增加跨扫描全局缓存、锁或持久文件。一次扫描期间索引变更按下一次扫描观察。线程归属仍为调用工作线程，不允许多个工作线程共享可写缓存。

## 语言规则

游戏语言代码使用 Minecraft 原始值（例如 zh_cn、en_us、lol_us），不能用 QLocale 简化丢失游戏自定义语言。语言自称与地区不翻译，同名语言在结果中显式带地区。启动器只列出本版本已编译、可按需下载界面译文的 104 种非中文语言加简体中文；原有文案保留既有译文；本轮新增的 4 条语言下载提示已补英文，其他语种暂回退中文，待逐语种补齐和审校。此项是覆盖检查，不等于所有译文已做母语审校；缺失词条由 Qt 回退源文案。界面语言与所选游戏资产索引支持的语言是两套范围，旧游戏不支持所选代码时仅该游戏回退 en_us。支持右向左布局的语言按 QLocale 判定。

玩家选择后立即保存期望语言，语言包校验成功后更新界面；下载中或失败保留当前界面语言，不重建账号、导航或下载。已有游戏在下次启动应用同一语言；旧版本不含此语言时只对该游戏回退 en_us，并保留启动器所选语言。不改写其他实例或运行中游戏的 options.txt。

翻译资源放 assets/i18n/ts，新增源文案使用 qsTr/tr，经 lupdate 与 tools/update_translations.py 同步 TS、审校译文、lrelease 生成压缩 QM；languages.json 仅维护名称/地区。不翻译实例名、玩家名、路径、URL、加载器品牌和协议 ID。参数化文本使用占位符，不拼接语序；界面不能出现演示、服务接线等开发术语。

## 设置范围与交互

设置首页仅保留短名称和当前值。语言使用已有可搜索 SelectField；游戏设置按内存、显示、Java 分组，显示模式复用同一 SelectField，在全屏与窗口分辨率中单选；下载设置含并发和既有源优先级入口；启动后行为支持保持显示/收起。不添加尚未实际接通的多开、优先级、更新通道或语音开关。

### 旧版游戏设置核对（2026-11-09）

已对照旧版 qml_settings.py 的游戏设置字段、qml_start.py 的窗口模式分支及 core/launcher.py 的最终启动参数。旧版“最大化”实际传 --fullscreen；其他模式只传 --width/--height。新版沿用互斥行为，名称使用准确的“全屏”。配置继续保存 fullscreen 与 resolution，便于切回窗口时保留尺寸；界面仅显示一个显示模式选择器。最终命令在 build_launch_command 唯一边界按模式贡献 --fullscreen 或窗口尺寸，官方 has_custom_resolution 规则使用同一判断；options.txt 继续由 apply_game_options 更新，不建立第二套设置存储。

| 旧版项目 | 新版处理 |
| --- | --- |
| Java 与自动/手动内存 | 复用 JavaPage、MemoryControl 和 GameRuntime；每次启动重新匹配与计算 |
| 窗口模式 | 合并为显示模式单选，保留常用窗口尺寸，全屏不传宽高 |
| 版本隔离 | 统一启用实例独立目录，共享 assets/libraries；不增加可能混用存档的开关 |
| 启动器可见性 | 复用常规设置已有的保持显示/贴边收起，以及生命周期处理 |
| 调试模式 | 复用真实启动日志及实例日志入口，不额外增加开关 |
| 进程优先级 | 本次不迁移；保持系统正常调度，不增加没有必要的性能选项 |
| 实例独立设置 | 逐键覆盖全局值，复用恢复全局设置入口，不复制编辑器 |

不设保存按钮。切换开关、拖动滑块和确认输入时即时更新快照，后台合并写入；反复设置相同值不写盘、不刷通知。手动内存上限为当前物理和可用内存扣除 1–4 GiB 系统预算后的较小值，按 256 MiB 对齐，绝不提供固定 64 GiB 虚高上限；启动前再按当时环境校验。自动内存沿用每次初始化和准备前的实时重算。全局改变由未覆盖的实例继承；实例可以恢复全局设置。

## 自动内存与 Java（2026-11-09）

策略只由 platform/runtime/runtime_environment.automatic_memory_mb 计算，GameRuntime 的实例快照和启动 worker 共用。基础 2048 MiB，每个活动模组增加 20 MiB，房主每多承载一人增加 256 MiB，再向上取整到 512 MiB；结果不超过当前可用预算及 16384 MiB。例如 0/100/200/300 个模组，在预算充足时分别为 2/4/6/8 GiB。仅统计当前实例 mods 中启用的 .jar，不统计 .disabled；监听 mods 目录变化并重用实例扫描。此为保守的数量估算，模组的世界规模/贴图大小不同，不能声称满足所有整合包。

启动器初始化采样环境，实例扫描提供 modCount；每次真实启动重新采样内存并重新计数，自动值不写进配置。hostPlayerCount 为 GameRuntime.launch 的可选贡献字段，默认 1，仅房主传本机承载人数，普通入房客户端不增加；当前房间服务尚未提供可信成员数，因此尚未自动注入该字段。后续房间调用同一启动入口，不复制公式，不增加固定人数/内存设置。

保留按本次计算产生的 -Xmx，移除固定 -Xms256M；没有加入通用“优化参数”模板。Java 21/25 默认最大堆通常为可见内存的 25%，不能按模组数分配，删除 -Xmx 会丢掉启动器预算保护。默认 GC 与初始堆交给所选 JVM 自适应，最终参数仍经过唯一去重步骤。自动模式预算不足 2 GiB 时终止准备并明确提示，避免以 512 MiB 冒充满足默认最低需求；手动覆盖仍受实际预算约束。

所需 Java 版本以 Mojang 元数据 javaVersion.majorVersion 为准，缺失元数据回退 Java 8；不按启动器自己的版本表猜测。选择已探测候选直接保存；添加路径先检查现存绝对 java/java.exe，再复用 java_major 在工作线程执行 -version，正常退出且可解析版本才加入候选并保存。新选择、恢复默认、退出均使旧验证不能覆盖新状态；PNG 和伪装为空 java.exe 的文件都不能成为所选 Java。

依据：[Java 21 启动参数](https://docs.oracle.com/en/java/javase/21/docs/specs/man/java.html)、[Java 25 启动参数](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html)、[Java 25 GC 自适应](https://docs.oracle.com/en/java/javase/25/gctuning/ergonomics.html)。公式是启动器策略，不是上述文档对模组用量的保证。
