# 列表底栏、版本渐变与内容入口（2026-11-10）

本轮已实现好友/联机底栏和版本渐变调整。在线模组等内容的入口与接入步骤是下文建议，尚未实现在线搜索或在线安装，不以现有来源能力枚举代表服务已接线。

## 布局修改与复用

检索了 FriendsPage 的 RowLayout/ListViewport/SettingRow、RoomsPage 的 viewportHeight/分页、PageLayout 的边距和高度、ListRow 的行内对齐、SummaryButton/InteractiveSurface 的渐变，以及旧版好友列表和联机节点状态呈现。现有组件已经足够，本轮没有新增生产组件、业务方法、网络请求、定时器或缓存。

- 好友常规左栏此前只有内容自然高度，好友码跟在短列表后面，下方留空。现在左栏与右侧详情同高，原 ListViewport 占剩余空间，好友码留在左栏底部。面板仍按原来的有限列表自然高度展示。
- 好友列表、搜索行和好友码的左右边界一致；列表文字继续使用 ListRow 的既有垂直居中，不为单页复制文本行。普通好友页右侧仍为完整会话占位，私聊明确“待实现”，没有假消息或可用发送按钮。
- 联机页此前用固定减数估算常规列表高度。现在 ready 内容由一个 ColumnLayout 分配可用高度，列表伸缩，节点名称与延迟停在内容底部；错误提示占用列表空间。面板继续最多三项、分页和自然高度，不扩成空白大窗口。
- 版本摘要通过 SummaryButton.fadeOpacity 将左端浓度从 15% 调到 20%，继续交给唯一的 InteractiveSurface 渐变实现；颜色来自原有 BackdropPalette 平均色，右端透明。首页房间摘要仍为 10%，没有新解码或另一份颜色提取。

## 模组、资源包、光影包、整合包放置建议

以下为建议，尚未新增产品入口或接入在线内容服务。

| 用户意图 | 入口 | 操作方式 |
| --- | --- | --- |
| 找新内容 | 广场 → 模组 / 资源包 / 光影包 / 整合包 | 共用搜索、分页结果、详情；不增加主导航，不挤占启动首页 |
| 管理已有内容 | 当前实例 → 模组与资源 | 保留本地模组、资源包、光影的启停、添加文件和回收站；在线添加跳到同一个广场并携带当前实例和分类 |
| 安装整合包 | 广场整合包详情；已有本地文件走导入整合包 | 新建实例，继续使用现有重名确认、预检、下载补齐与原子发布流程；导出留在实例详情 |

从实例进入广场时预设 Minecraft 版本、加载器和分类，保留可见筛选；从全局广场安装时先选择目标实例。详情展示兼容版本、必要依赖和文件大小，再交给现有任务队列；不再为每种内容建一套下载进度页。返回时恢复原实例管理位置，搜索条件与所选项目归 PageStateStore。

### 当前已经存在的接点

- `InstanceFilesPage` 已接 `GameRuntime.refresh_content/change_content/add_content`，支持 mods/resourcepacks/shaderpacks 三类本地文件。它负责管理已装内容，不承担在线搜索。
- `GameRuntime.import_pack/export_pack` 与 `GameOperations` 已处理 CurseForge ZIP、Modrinth mrpack、Buggcraft buggpack 的现有导入导出、任务和提交。整合包安装应复用该计划/提交链路，不把整包丢进 mods 目录。
- 广场的 SearchPage 已有搜索与分类呈现，目录/内容详情在正式入口仍有“服务尚未接入”门禁；目前分类还没有光影包，不能把此原型当作已完成的四类内容市场。
- 来源契约已有 CurseForgeContent/ModrinthContent。查询接入应扩展所属目录模块的内容查询适配边界，复用 HttpClient 和 SourceSettings/resolve_sources；Minecraft/加载器目录的 GameCatalogService 不直接承担另一类内容状态机。下载仍交给 ResourceClient/GameRuntime，避免第二套网络客户端、来源顺序、哈希或任务队列。

### 在线来源与性能边界

Modrinth 的官方搜索支持 mod/modpack/resourcepack/shader 分类、版本/加载器 facets 与 offset/limit 分页；版本接口提供加载器、游戏版本过滤、文件哈希和依赖关系。接入时将供应商结果归一化到所属内容查询模块，不把不同 API 数据结构传遍 QML。[搜索 API](https://docs.modrinth.com/api/operations/searchprojects/)、[版本 API](https://docs.modrinth.com/api/operations/getprojectversions/)。

CurseForge 官方接口要求 API key，提供项目/文件/依赖查询；下载还须尊重项目分发许可与可用下载地址，不能假定任意文件都能经镜像交付。现有源站凭据和能力要由服务实际配置决定，不在 QML 或通用发布包硬编码密钥。[CurseForge 官方 API](https://docs.curseforge.com/rest-api/)。

内容查询使用有界分页、输入去抖、取消过期请求及包含分类/版本/加载器/来源的缓存键；缩略图异步且限制显示尺寸。安装复用现有工作队列、校验和最终提交，界面线程不做文件摘要或整包解压。本轮只是布局修复及接入设计，不声称新增性能提升，也不将 Windows 的看图结果冒充 macOS/Linux 实测。
