# 下载并发与整合包修复实测

2026-11-11，Windows 11 x64、MSVC Release、Qt 6.8.1。复用现有 ResourceClient、HttpClient、GameOperations 和 GameRuntime；没有第二套下载器。原入口保持 `预览首页.cmd → build/bugg.exe`。

## 实现及真实原因

- 核心、库、assets、模组、资源包、光影包、数据包、Java 等类别分别使用设置并发数，各类别同时推进。测试设置 2，三类别峰值合计 6，每类别峰值恰为 2。整合包资源与基础游戏文件合并调度，加载器处理器仍等待所需依赖。
- 已知大小和 SHA-1、不小于 8 MiB 的文件在原 HTTP 请求下用三个连续 Range；严格核对 206/Content-Range，服务器拒绝后回退普通下载，合并验证完整摘要与大小，再原子提交。取消同时撤销分段，不发布半文件。临时网络/408/429/5xx 同源最多重试两次，再沿既有来源顺序回退，已校验文件不重下。
- CF 文件有 edge 节点 404、mediafilez 同路径仍可用的实际案例，增加相同发布者 CDN 回退，保留摘要校验。公开 DropVersion 文件经统一源入口下载的 5,946,868 字节与官方 SHA-1 一致。
- 原 426 文件整合包逐项查项目与文件，需要 852 次查询，触发源站 120 次/分钟限制；随后未授权官方回退把错误覆盖成密钥问题。现在按最多 100 个 ID 调官方批量 POST，本包只需 10 次，减少 98.8% 的目录请求；结果按 ID 核对归属。无本机密钥时跳过未授权官方 API，保留真实限流/缺失错误。
- 自有旧代理的服务端 CF 密钥已迁入新源站并同步成都节点。后台「镜像设置 → 下载设置 → 主动缓存 → CurseForge 接入」可更新密码框中的密钥；仅服务器保存，不回显或发给客户端。旧启动器使用该自有代理，并非无需平台授权。
- CF 整合包里的 6945 Data Packs 以前被误判为非法元数据，现在下载至实例 datapacks，沿官方目录方式保留，不冒称自动启用到每个存档。导出原本已包含该目录。
- 完整单实例客户端 ZIP 沿原事务导入，仅提取游戏资产、库与该实例，排除账号/启动器和日志，不执行归档程序。兼容原版与自包含 Forge 描述，修正 FML 参数中的版本识别。
- Windows 下载 Java 后直接校验目标 bin/java.exe，修正路径分隔符造成的漏检；下载后仍不兼容时重新核对 PATH/JAVA_HOME 等已有候选。启动准备和无关后台下载分别持有任务 ID、取消域；正在修改同一实例的安装仍阻止启动。
- 子任务移除重复文件名、重复阶段文案，仅保留可区分的版本、传输速度/字节和必要失败原因。后台双平台每类各取前 N，可信 SHA-1/大小相同的对象只下载/保存一次，保留各平台 URL 及固定引用；一别名失败不污染另一别名。

## 性能结果与范围

同一二进制、同一 10 MiB 数据，单连接和三段都写入临时磁盘并验证 SHA-1。测试服务每连接固定节奏发送，三轮成对测量；系统另有真实归档下载进程，未清空系统文件缓存。

| 轮次 | 普通下载 | 三段下载 |
| --- | ---: | ---: |
| 1 | 220 ms | 119 ms |
| 2 | 216 ms | 117 ms |
| 3 | 220 ms | 116 ms |
| 中位数 | 220 ms | 117 ms |

中位耗时减少 **46.82%**，吞吐约 **1.88 倍**。普通耗时范围 216–220 ms，三段 116–119 ms。该受控结果证明分段机制收益，不能当作公网、所有文件或启动器整体提速倍率；两种模式读取同样内容并执行完整校验。

公网小资源探测：一份 37,839 字节资源，统一源入口 0.953 秒且重定向到官方，官方直取 0.907 秒；说明未缓存小文件仍受远端延迟影响，不能凭本机分段测试声称已跑满 200 Mbps。没有擅自改变用户来源优先级或增加下载前测速。

原始数据：`build/download-performance.json`、`build/download-ranges-repeat-1.log` 至 `-3.log`。分组及完整性回归：`build/download-bulk-native-tests.log`（7 passed，含初始化/收尾）；拒绝 Range、坏摘要和取消均验证通过。
