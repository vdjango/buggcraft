# 共享接口与能力目录

## 通用依赖约束（2026-11-12，实施中）

版本方言判断复用相邻源站项目的独立 `native/dependency_core`，以独立 CMake target 静态链接；不依赖源站 Python/HTTP 或其运行目录。输入原始版本、原始表达式及方言，输出满足/不满足/未支持；纯函数、可跨线程、无 I/O。包内元数据读取仍归安装 worker 的基础设施，事实缓存/源查询/取消沿既有 ResourceClient、HttpClient、安全归档及摘要机制；UI 不解析。方法及全部安装入口/原包继续和自动处理契约见 [源站第 46 号](../../bugg-source/文档/46-制品依赖约束与客户端兜底方案.md)。当前为实施契约，不代表客户端通用流程已完成。

2026-11-12 CurseForge 核心依赖补充：`ContentProvider.core_release` 仅对候选清单中登记的 CurseForge 核心项目，用当前文件 SHA-1 查证同一 Modrinth 发布；项目、文件摘要及明确游戏/加载器标签均须一致，再采用该发布的具体依赖约束，保留原 CurseForge 主文件身份和下载地址。不能把仅有依赖项目的记录解释为最新版兼容。无法查证时明确失败，不静默改用最新版；普通非核心项目不增加逐文件跨平台查询。`resolve` 沿用单一递归入口消费依赖自身 publisher；核心的必要依赖失败不发布可安装计划。`GameOperations.prepare_content_install`（原 prepare_shader_install）也为普通模组补齐实际加载器构建并重解析旧计划，避免旧计划绕过兼容规则；仍由原 worker/取消域持有，无新增下载器。

2026-11-12 选版契约：ContentCatalogSession 的目标快照包含 Minecraft、加载器及 loaderVersion；目标变化取消旧查询，目录与详情共用该快照。ContentProvider 复用源站 `/v1/catalog/shader-runtimes` 的有出处 `compatibilityRules`，按精确项目/发布 ID、游戏、加载器及加载器版本下界排除已确认错误组合；不猜测游戏版本范围，不无条件替换作者固定依赖，不以最新版必然兼容为前提。规则只影响匹配目标，普通文件仍按作者支持标签严格校验。GameRuntime 的安装预检快照携带原始 requestedPlan，只有目标和该计划都匹配时页面才能显示“已安装”或提交安装；旧预检不得套用到新项目。禁用的光影核心先由玩家处理并启用，安装光影不能自动替换/启用它。

2026-11-12 安装完成/调试日志：GameRuntime.installation_finished(task,instance) 只在完整游戏安装/导入成功且无缺依赖时发出，选择结果实例后由 ToolDeck 决定仍位于任务页时回主页，不用任务中间 progress=1 判断安装成功。refresh_debug_log(module,level,search,logger) 扩展原 worker，module 是来源，logger 可匹配真实记录器或日志明确指认的模组；XML/文本统一完整事件和堆栈，单文件最多读取 256 KiB，消息最多 12 KiB，返回 entries/modules/loggers/instance。来源和记录器选项从未过滤快照收集，取消与关闭仍归原文件任务。

2026-11-12 窗口与安装进度：WindowController 持有唯一原生托盘入口，仅 panel 显示托盘，唤回复用同一窗口/路由；退出调用窗口原有关闭链路。Main 的 panel 使用 Tool/置顶，其他页面使用 Window/任务栏且不置顶。系统没有托盘时不隐藏唯一任务栏入口。ResourceClient 在原 worker 内发布校验计数、获取元数据、连接/重试等待和传输进度，周期更新受节流约束；批次/阶段边界立即交付。GameOperations.report 不再二次丢弃 ResourceClient 已节流的状态，取消仍先检查。进度只说明当前阶段，不把单批文件校验完成冒充整个安装完成；GameRuntime 持有最终任务状态。

## 2026-11-11 下载诊断与全屏入口扩展契约

- `HttpClient` 独占传输机制：文件可指定首字节等待；收到数据后恢复空闲时限。`transient_failure(id)` 在响应通知前标记连接/传输中断，包含 HTTP 200 后的失败，不包含磁盘或摘要失败；`ResourceClient` 复用此分类有界重试。总时限与取消语义保持。
- `platform/diagnostics/diagnostic_log` 为跨线程有界结构化事件唯一所有者；不记录认证头和请求/响应正文，URL 去用户信息、query 与 fragment，导出文本脱敏。快照限制 2 MiB，溢出记录丢弃数；不在 GUI/网络回调写盘。
- `GameRuntime.export_diagnostics(url)` 在 GUI 接收保存位置，复用 `run_file_work` 与 `archive_write` 异步导出 ZIP；只包含脱敏快照及有限日志，不打包存档、凭据或完整配置。`diagnostics_status` 提供 busy/path/error，退出由已有 workers 汇聚；取消不提交半成品，不覆盖既有文件。
- `DesktopEnvironment.fullscreen_foreground(window)` 只读探测同屏前台全屏；`WindowController` 管入口自动隐藏与恢复，`EdgeDock` 继续拥有折叠和几何。普通主题不置顶，panel 置顶。全屏入口开关归 `GameRuntime.preferences`，缺省关闭。

整合包官方类型 6945（Data Packs）写入实例 datapacks 目录，与官方手动安装目录一致；复用原清单路径/摘要校验、下载、事务与导出，不冒称自动启用到所有存档，不自动注入额外数据包加载器。

CurseForge 整合包用官方 POST `/v1/mods` 与 `/v1/mods/files`，每批至多 100 个去重标识；仍由 ResourceClient 的 JSON 入口、同一源映射、传输与取消所有者处理，请求体只含官方字段。返回数据按 ID 映射后核对项目/文件归属，不依赖响应顺序。没有本机密钥时不尝试未授权官方 API，以免覆盖源站限流或真实文件错误。

完整客户端 ZIP 导入复用 `inspect_modpack/import_pack/commit_content`，仅接收唯一且自包含的版本描述，不猜测多个实例。只提取资产、库和该实例内容，排除账号/启动器配置/日志，不执行归档中的启动器或脚本。共用实例描述归一化和路径校验，先暂存后发布；客户端 JAR 跟随新实例名称，已存在目标不覆盖。

2026-11-11 下载修复契约：`GameResource.group` 可显式指定资源组，缺省按 assets/libraries/mods/resourcepacks/shaderpacks/runtime/installers/versions 路径归组；每组最多使用用户设置的并发，各组同时传输。`ResourceClient.json_many` 在同一 worker、传输所有者和取消域内按配置并发并去重 URL，原 json 入口委托该批次。整合包先并发解析清单，再合并原版与整合包文件下载；加载器处理器仍等待其依赖。`curseforge_file_url` 统一公开文件路径回退规则，保留访问限制和最终摘要校验。HttpClient 对已知大小、SHA1 且不少于 8 MiB 的文件尝试三个连续 Range，严格核对 206/Content-Range，拒绝时回退普通下载；合并校验后原子提交，取消不发布文件。启动准备和后台任务分别持有任务 ID 与取消域；仅正在改写同一实例的安装阻止启动。

2026-11-11 当前游戏光影补装契约：`GameOperations.install` 的 `updateExisting=true` 只允许同一游戏版本的原版实例补装明确选中的加载器，保留实例 ID、存档、设置和已有客户端 JAR；仅下载加载器依赖，不重新安装游戏或资源索引。已有其他加载器不得覆盖。`install_with_content` 带 `id` 时复用该分支，再走同一核心/依赖/光影事务；核心失败不得提交光影。加载器安装失败/取消不改写原版本 JSON；核心失败后已成功补装的加载器可供重试。任务提交和出队均阻止修改正在运行的目标。工作线程、取消和文件队列沿用原所有者。

2026-11-11 安全验收：Defender 对构建入口报告 Trojan:Win32/Bearfoos.A!ml 并隔离；在原因核实前暂停执行与交付该程序，不恢复隔离、不关闭防护、不添加排除项。既有功能测试不代替安全结论。

## 光影支持组件（2026-11-11）

候选核心项目及 JAR 内识别标记由唯一 Bugg 源入口 `/v1/catalog/shader-runtimes` 提供；这只是来源清单，不把项目级标签当作具体版本兼容证明。ContentProvider 沿用官方版本查询、文件摘要和 resolve，按游戏版本/加载器解析 Iris/Oculus 与必需依赖，光影计划标明 shaderSupport/prerequisite。原版引导现有 installWithContent 在当前实例补装 Fabric；没有安装目标时才创建新游戏。不暗改已有其他加载器。没有真实兼容版本返回可读错误，不装另一加载器的核心。

GameOperations.prepare_shader_install 在现有 worker 中只扫描活动 JAR 的 ZIP 目录，识别候选后才流式哈希，通过官方 hash→version 核对具体项目和兼容性；改名不影响识别。复用当前兼容核心及其依赖计划，不叠加最新版。检查与安装调用同一方法，实例变更/文件移除后安装时重新检查。缺失核心先复用 install_content_files/ResourceClient 补齐依赖，再提交光影包；核心/必要依赖失败不发布新的光影文件，可从原任务重试。普通模组保留主内容先装、依赖失败不回滚的行为。取消、明细、来源和退出沿用原所有者，没有新下载器或线程池。

2026-11-11 大厅目录：MultiplayerService.join_listing 仍为 GUI 异步命令，沿 room_generation_ 丢弃取消响应；room.resolve 只解析，成功后复用 join_room。确认失效/未发布移除对应旧条目，邀请拒绝、节点不可达和临时错误分别提示，临时错误保留列表。RoomsPage 仅把明确布尔 require_invite 呈现为加入策略，缺字段显示信息未同步并禁用加入。原生协议见相邻控制项目 docs/13。

2026-11-11 已开放世界：MultiplayerService.discover_worlds 仍为 GUI 异步唯一入口，建房/关联忙时不扫描；扫描重试清旧错误，失败清旧候选，取消沿 room_generation_ 拒绝迟到结果。CreateRoomPage.selectedWorldPort 是轻量选择呈现：有效草稿优先、唯一候选默认、多个无默认；扫描中不提交。probe_world 与建房后自动关联共用内部 world_version_matches，匹配完整版本标记，允许加载器展示前缀；create_room/connect_world 合并探测信息时保留实例规范 version。输入、取消、线程归属未变，无新增网络服务。

2026-11-10 改名识别与就地更新：GameOperations.check_content_install 在所属资源目录中按大小预筛、复用多摘要校验识别改名文件；installed.path 与 records.path 返回实际路径。安装沿用该预检结果，保留已验证文件名，不重复下载或创建另一份；替换版本仍需显式确认，并清理同项目旧收据。目录枚举与摘要只在原工作线程执行、支持取消，单次检查共享索引与摘要，不扫描无关目录。房间缓存仍由 RoomContentCache/源站以 SHA-256 为身份，路径只作展示与读取位置。

ContentCatalogSession 的结果列表和介绍文档使用会话持有的 ContentListModel；同项目译文通过 dataChanged/行增删原位发布，只有查询或项目身份改变才 reset。已命中译文保留到后台更新完成；缺失译文短暂重试，切页/关闭仍取消。图片块保留 HTML width/height 与段落对齐，展示不放大原始小图。MultiplayerService.status.roomOperation 区分 create/join，ToolDeck 按加入状态呈现专用等待页，取消复用 leave_room 的代际失效；失败恢复原入口，成功进入房间。默认创建公开且需邀请的房间。

## 内容译文接线（2026-11-10）

ContentCatalogService/request_content 扩展 translations 操作，最多一批 20 个项目：资源身份、原文 mc-text-v1 SHA-256 匹配后返回中文简介与安全图文块。固定使用 SourceSettings.bugg_base_url 下的公开 resolve、匿名会话、ensure、artifacts 接口；BMCLAPI/官方下载优先级不改变译文来源。复用现有 worker、HttpClient、content_description 和有界缓存；不新增网络所有者或地址设置。制品核对 SHA-256、资源/字段/语言/profile/原文哈希；过期译文不发布。

ContentCatalogSession 持有原文、译文显示选择与有限重试；先展示原文，失败不阻塞安装。匿名令牌只留于 C++ 服务内存，换源清除。内容页不可见、换项目、换源、关闭均取消后台请求和重试，迟到结果不发布。set_translation_enabled(bool) 仅切换显示/查询，不改变项目身份或安装计划；active 属性由 Main 页面可见性驱动。

2026-11-10 并发内容传输：独立依赖先由 GameOperations.prepare_content_files 复用既有预检、校验缓存和暂存，统一交给 ResourceClient.fetch(resources,continue_on_error=true) 按原 concurrency 设置并发；返回按路径的失败表，取消仍抛出。随后逐个复用 install_content_files 提交，提交前重新读取元数据，避免覆盖其他依赖 receipt；主内容先发布，依赖错误仍保留主内容。ResourceClient.set_transfer_progress 只扩展原 worker 的有界进度值回调，提供 path/state/progress/received/total/speedText/aggregateSpeedText/activeTransfers/transferText/detail，无新下载器、线程或 GUI 轮询。

2026-11-10 内容任务明细：沿用单条 GameRuntime 安装任务，task.contentItems 按主内容/每个依赖保存 key/title/versionName/filename/dependency/state/progress/detail；worker 经 GameOperations.set_content_progress 值回调、原 watcher queued 更新，最多 128 项，阶段终态即时，高频进度复用 100 ms 合并。切页/关闭/取消仍归原任务，完成明细经原任务持久化保存。check_content_install 补充 installed(path/versionName/versionId/matchesSelected) 与 dependencyConflicts；本地一致文件标记 installed 并复用，另一版本保留并要求显式替换，不按文件名假定兼容。详情页显示本地版本，仍可重新/替换安装。依赖冲突不得阻止主内容安装。

## 广场图文与兼容筛选补充（2026-11-10）

依赖采用“主内容成功、依赖尽力补齐”契约：plan.files 标记 dependency；required 自动解析，optional 不自动添加。单个依赖的查询、兼容或下载失败返回 missingDependencies（publisher/projectId/versionId/title/reason），不使已校验的主内容失败。主内容错误仍失败，取消仍取消，不以缺依赖冒充可正常运行。安装先复用原事务提交主内容，再逐个复用同一事务安装依赖；任务完成可带缺失依赖清单及“重试依赖”。GameOperations.install_content/install_with_content 返回 instance/missingDependencies；后者依然隐藏安装后发布，缺失依赖不阻止发布主内容。GameRuntime.set_content_request 装配 ContentCatalogService.requester 的值快照，仅在未解析依赖/补装重试时重新解析；沿用工作线程、来源、取消，不新增 HTTP 所有者。重试已完成但缺依赖的创建任务转为原实例的内容补装，不重复创建游戏。

沿用 ContentCatalogService/Session 单一所有者。categories 查询返回当前平台、内容类型的真实分类，Modrinth 搜索使用 categories facet，与 gameVersion/loader 求交；更换平台或类型清除旧分类，迟到分类响应不得覆盖新类型。中文名称仅翻译接口真实 slug，不伪造 MC 百科独有标签。CurseForge 公共网关未开放 categories，分类使用实测可匿名访问的官方 categories 端点；其他官方请求保持既有凭据规则。分类查询改用官方 categoryId（MR 仍为 categories facet），不再做本地后过滤、5 批扫描或游标补页；总数和分页来自上游响应。BMCLAPI 缺内容能力时按既有 SourceSettings 回退官方，CF 官方查询仍需要授权。新源站 bugg-source 和旧 packaging/content_gateway 已补分类参数契约；未部署，不把代码变更当线上完成。categories 增加 group，CF 用真实父子关系，MR 用官方 header；按组排序，父类对应组内“全部某类”，官方 ID 保持不变。

detail 扩充 body、bodyFormat、gallery、gameVersions/loaders；Modrinth body Markdown、CurseForge /description HTML 在原 worker 中经 Qt 文档解析为 text/image 块（正文最多 256 Ki 字符、图片最多 32 张、画廊最多 12 张）。Modrinth 字段实际为 HTML 文档时复用 Qt HTML 解析；图片链接补回 Qt 6.8 丢失的 Markdown anchor，image 块可带 link。RichDocument 将链接图片显示为小预览，正文插图保持较大阅读宽度；Qt 异步按视口解码并保持比例，失败保留正文/原站入口，不引入 WebEngine。描述与安装查询共享原取消、缓存和来源生命周期。

Session 保存真实 target，ensure_context 首次进入默认当前实例；用户改筛选不悄悄修改安装目标。安装前比较真实 target 与所选文件；不匹配阻止提交并提供恢复兼容筛选，原版模组提供创建兼容实例流程，预选游戏/加载器，沿用 InstallCatalogSession 和 GameRuntime 原安装队列。UI 不实现兼容规则或下载逻辑。

GameRuntime.install(kind=installWithContent,game,loader,loaderVersion,name,plan) 在一个原任务中调用 GameOperations.install_with_content：复用 install 将游戏放入确定性隐藏目录，再复用 install_content 校验/安装内容，最后复用 commit_content 原子发布实例。主文件失败或取消保留隐藏可重试文件，不发布可见半成品；依赖失败允许发布主内容并返回缺失项；重名沿用拒绝覆盖。InstallCatalogSession.prepare_selection 在 GUI 保存并校验异步目录选择，不增加网络机制或线程。

## 启动器更新（2026-11-10）

LauncherUpdateService 是应用级更新元数据/状态所有者；固定现有下载站 https://download.bugg.icu/api/launcher/update，当前版本由 CMake 2.0.1 唯一定义。首帧后自动检查一次，设置→关于可手动检查；同一请求去重。下载复用 ResourceClient/HttpClient、file_digest 和 archive_entries/archive_extract，在 worker 校验 HTTPS 清单大小/SHA-256，原生整包 ZIP 才可自动替换，旧版单文件包不能覆盖新版依赖。更新暂存在便携缓存目录；点击安装后启动隔离原生 helper 等待本进程退出，逐文件备份/替换、失败回滚，不写用户配置或游戏目录。GUI 不等待下载/哈希/进程，取消和退出沿用 Cancellation 与生命周期 drained。元数据空/最新/失败/可用/下载/待重启分别展示，不能把无可用安装包显示为更新成功。

## 核心契约的数据形状

- **FileIdentity**：文件类型、相对路径、预期大小、一个或多个可信哈希、是否必需；比较以哈希为主，名称只做检索线索。
- **SourceCandidate**：来源 ID、原始 URL、可能的重定向、元数据来源、可用时间、是否支持 Range；UI 只显示来源名，日志脱敏 URL。
- **DownloadRequest**：FileIdentity、目标目录、来源策略版本引用、任务优先级、取消句柄；每次换候选前查最新策略版本，不接受一个任意字符串路径就开写。
- **TaskSnapshot**：TaskId、阶段、完成/总文件数、成功/失败文件列表、累计字节、瞬时速度、当前来源、用户可执行动作；只读推送给 QML。
- **PackPlan**：实例目标、游戏/加载器版本、包内覆盖文件、外部候选、冲突决策与前置依赖；解析器不负责执行下载。
- **RoomManifest**：房间/实例标识、文件身份列表、房主允许共享的范围；不包含任意绝对本地路径或长期上传凭据。
- **AppError**：错误代码、用户可读说明、可执行恢复动作、内部诊断上下文；内部上下文不能直接弹给用户。

每个公开方法定下契约时补齐：输入不变量、正常输出、失败代码、取消后语义、调用线程/回调线程、是否幂等、文件系统副作用。新的“通用工具”若找不到三处真实调用，先作为所属模块私有方法，避免提前抽象。

- `DesktopEnvironment::available_geometry(QWindow*) -> QRect`：GUI 线程内读取当前窗口所在屏幕的可用工作区，包含多屏坐标并排除任务栏。没有窗口屏幕时回退主屏；无屏幕返回空矩形，由 EdgeDock 忽略。屏幕工作区变化发 `available_geometry_changed`。

### 首页启动状态契约

`Main.launchSession` 为可注入的呈现模型，提供只读 `status` 快照和 `start(index)` / `cancel()` / `stop()` 命令。快照字段为 state（idle/preparing/running/stopping/failed）、instanceName、title、detail、stage、progress（0–1，未知用 -1）、preview（开发预览标记）。正式所有者是启动/游戏会话模块的 C++ 呈现层；UI 不推断 Java 完成、不自行运行计时启动。后台事件通过排队连接更新 GUI 属性。

启动输入是当前实例索引，正式服务需解析为稳定实例 ID 与身份快照并校验；输出为状态通知，失败在快照中携带可读原因。重复启动在活动状态忽略；取消必须终止后续准备并避免迟到事件重新启动；停止仅提交异步请求，进程确认退出后恢复 idle。页面销毁不取消，会话结束才释放模型。当前 C++ LaunchSession 使用 QTimer 演示同一契约，绝不创建进程、联网或扫描磁盘。

### 真实身份、安装与启动契约

正式入口由 main 注入 AccountPort / GameRuntimePort，不依赖 Python，不使用预览成功状态。公共签名、输入/输出/失败/取消/线程见 [22-原生类与方法参考](22-原生类与方法参考.md)；完整图见 [23-真实安装启动与生命周期流程](23-真实安装启动与生命周期流程.md)。

- IdentitySession 仍是非敏感身份呈现唯一所有者。use_offline 校验名称；begin_microsoft 无缓存时委托 MicrosoftAccount 获取真实设备码，有缓存时复用 select 切回。complete_microsoft 复制授权码并打开微软页面；浏览器授权后异步完成 Xbox / XSTS / Minecraft profile，成功才发 committed。离开授权页取消，收起/切主题不取消。finish_microsoft 仅测试显式 preview_enabled 时可模拟，正式入口禁用。
- MicrosoftAccount 负责凭据恢复、有效期、刷新和登出。Windows DPAPI / macOS Keychain 保存 refresh token，Linux 当前不持久化；访问令牌只在 C++ 内存，不进入 QML/日志。登出删除本机凭据并清除微软角色，不声称撤销云端所有会话。
- LaunchSession.preflight 仍是身份确认唯一入口；GameRuntimePort.launch 接收稳定实例 ID、角色 ID 和可选参数贡献。首页与未来房间共用。无身份不推进，准备期间锁定选择；取消代数与连接断开忽略迟到结果。
- GameRuntime.install 接收 name/game/loader/loaderVersion。安装、文件准备和修复共用 GameOperations、ResourceClient、HttpClient；Forge/NeoForge 处理器使用匹配 Java 的绝对路径。所有必需文件及处理器输出通过校验才原子提交实例 JSON。
- prepare 复用文件流程；缺失可下载文件会修复，缺少安装器生成且无下载 URL 的 JAR 时明确要求重新安装对应加载器，不误报启动成功。安装处理器可能需要同一库的不同版本，下载保留它们；最终游戏命令再处理继承覆盖与 classpath / 参数语义去重。
- GameRuntime.initialize 在生命周期 mounted 后后台扫描真实实例、检测 Java/内存、恢复实例配置；自动内存每次启动器初始化及游戏启动前重算，不保存第一次自动计算的结果。GUI 只发布快照。切页、折叠不终止任务；shutdown 异步汇聚自有 worker，已经运行的游戏继续。
- ToolBar.activity 消费真实任务，复用 DesignSystem.ProgressSurface 绘制水面。进程创建成功便移除启动准备效果，下载任务独立；面板主题隐藏广场，NavigationBar 使用稳定 toolIds。

复用检索：先查现有呈现模型、HttpClient、目录来源/缓存、ToolDeck 和 DesignSystem，再核对旧版授权/安装/启动格式。只补原生缺失执行层，未复制 UI 或下载器；未接入的房间、内容搜索/整合包导入等保持明确不可用。
## 房间回到首页、聊天和内容同步补充契约

- 房间唯一快照仍归 `MultiplayerService`。顶部页头与首页摘要读取同一 `room`，切页不离开房间；Home 始终调用 `ToolDeck.goHome()`，摘要调用 `openToolPage(2, "room")`。
- `room.connectionMode/memberCount/latencyMs` 为归一化展示字段：世界提供者为 `local`，成员线路取原生实际 `path`；未知延迟为 -1，不把节点延迟冒充到房主延迟。
- `send_chat(text)` GUI 异步发送，最多 256 个 UTF-16 代码单元，与节点约束相同；消息由原生事件入列，按消息 ID 去重，保留 200 条。发送确认后才清输入草稿。事件轮询归服务，不随页面销毁；离房、登出和关闭递增代次，迟到结果不恢复旧消息。
- `renew_profile()` 复用启动恢复的设备 challenge/signature/refresh 协议；到期前自动刷新。授权撤销/过期进入可重新授权状态，清理当前连接；网络失败保留有效授权并稍后重试。好友导航只在节点已登录时可见。
- 房间内容准备使用 `GameRuntime.install(kind=room)` 的既有队列、取消和进度；`GameOperations` 复用 install、ResourceClient、安全路径和文件摘要。原生清单分页与 P2P 文件调用通过一个工作线程端口接到现有 NativeBridge，GUI 不等待；离房后端口拒绝旧会话。只同步 mods/resourcepacks/shaderpacks 白名单文件，不接收存档、账号、启动器配置或任意路径。
- 房主通过创建/房间设置的“加速缓存”授权源站缓存及原生文件共享；界面保持与旧版同一开关语义。源站决定需要补传的清单，RoomContentCache 只上传源站明确请求的本地文件。普通下载、缓存地址下载和 P2P 复用 ResourceClient 与原生文件端口，不通过节点中转大文件；清单与最终 SHA-256 校验后才发布实例。
- 局域网广播仍调用原生 `game.announce`，在加入房间时禁用原生默认标题广播，服务按 1.5 秒发布带 `【BUGG联机】` 前缀的彩色标题；离房立即停止。
- 房间复用 NavigationBar 切换聊天与成员，内容区域和底部操作固定；普通加入流程不显示 IP/端口。设置仍用页头图标进入，不增加房间操作卡片。首页只增加一行摘要，不重排已有版本、账号、启动区域。
- RoomContentCache 已接入 room-content-cache-v1 的授权、计划、指定文件补传、解析和释放。下载速度判断及低速缓存策略完全归源站；启动器不添加 512 KiB/s 阈值、不按速度回退。源站尚未准备完成时显示等待，不伪报加速就绪；线上真实文件已验证上传、源站确认和有效房间内 SHA-256 校验下载，证据及未验证边界见第 25 份文档。
- 成员准备状态通过 GameRuntime.room_progress 和同一启动状态信号进入 MultiplayerService，合并后调用节点 member_update；任务 ID、序号和游戏配置对应当前房间。离房/取消/退出拒绝迟到进度，不另建好友专用下载器。

房间匹配/准备/启动当前接口由 MultiplayerService、GameRuntime、GameOperations 原所有者扩展，完整签名及取消契约见第 22 份“房间配置匹配与统一启动补充”；不新设 RoomLauncher 或房间下载器。RoomSyncPage 作为房间游戏 tab 的同一个嵌入页面，旧 sync 路由保留复用。

受管控制接入（2026-11-10）：MultiplayerService 默认登录 origin 为 https://81.70.85.232（北京 IP 测试）；start/poll/refresh/revoke 都走控制入口。含 control 的批准 profile 直接经 NativeBridge.node.add 传入同一原生 Rpc，不再经旧 4096 字节接入码封装。桥负责中心身份、分配和重连，Qt 不复制区域评分。HttpRequest.ca_pem 为单请求可选 PEM 信任锚，仍校验证书链/主机名/有效期；只有该精确 IP origin 使用嵌入公开证书，不影响其他请求或系统 CA。
# 2026-11-10 来源入口契约补充

- `source_url(source, path, bugg_base)`：contracts 所有；输入来源 ID、以 `/` 开头的协议路径和基址值，返回完整 URL；BUGG/BMCLAPI 之外返回空 URL。保留基址路径前缀，无 I/O、无状态，可跨线程调用，不涉及取消。
- `SourceSettings::set_bugg_base_url(value)`：GUI 所有；验证绝对 HTTP(S) 基址、排除凭据/query/fragment，规范化尾斜杠；失败返回 false 并显示错误，成功更新唯一配置、发 `configuration_changed` 并复用异步保存队列。磁盘读取期间的新配置优先。
- `select_sources(order, bugg_base)`：目录/内容/游戏服务消费同一值快照；目录与内容的基址变化也视为切源，撤销旧查询并隔离缓存；游戏服务仅更新后续任务参数。既有请求取消语义不变，不增加网络探测或工作线程。

## 单文件原生装配契约（2026-11-11）

`NativeBridge(executable,parent)` 的路径可指独立桥，也可指采用 BUGG_SINGLE_FILE 的完整启动器。两者以同一个 `--native-bridge` 参数进入原生 RPC；普通多文件构建的独立桥仍兼容无参数启动。接口的串行有界队列、优先级、超时、取消、断连与 drained 屏障不变。GUI 仍只异步收发控制消息，数据转发归原生线程；子进程异常不会直接使 GUI 崩溃。

完整启动器的原生入口在任何 GUI 初始化之前调用相邻项目唯一的 `bridge::run_cli(argc,argv)`；主进程启动时不初始化联机网络。单文件指分发和运行不需要旁置 DLL/桥 EXE，不表示游戏、用户配置、缓存和按需语言不产生文件。`--licenses` 输出内嵌的 Qt/应用/原生依赖许可，不打开界面。

## 2026-11-11 稳定性补充契约

正版设备授权由应用级会话持有；切页、折叠、恢复窗口不取消，仅显式取消/退出取消。下载默认对瞬态失败最多自动重试六次，沿 ResourceClient 唯一规则，仍保留来源策略、完整性和取消。最终 classpath 在占位符展开前统一路径并去重。新用户默认紧凑 small，已有外观设置保留。日志查看复用诊断环形缓冲，按模块/级别/文本过滤，GUI 不扫描磁盘。节点列表与测量通过既有桥 RPC，未知延迟显示未知，禁止城市演示数据冒充在线节点。

## 2026-11-12 续传机制所有权

HttpRequest.resume 默认关闭；ResourceClient.fetch 沿用原请求启用。HttpClient.request 异步返回 ID，start_request 在所属工作线程按块恢复前缀状态；跨进程以 QLockFile 防止共写。来源切换仅在摘要/大小一致时共用暂存；区间、大小、SHA-1 和原子提交均归 HttpClient，业务重试仍归 ResourceClient。新符号更新第 18/22 号索引，实际测试与发布另记。
