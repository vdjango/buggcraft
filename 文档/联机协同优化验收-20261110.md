# 联机协同优化验收

本轮仅修改联机所属模块：NativeBridge 的未发送请求分级，MultiplayerService 的后台刷新/旧节点回复隔离，以及空房间事件处理。实例扫描、下载、渲染和 QML 由另一窗口继续维护；本轮没有调整页面或通用性能模块。

复用检索、接口和方法更新见第 12、18、22 份文档。节点/桥/SDK 与启动器的完整数据、构建和复现步骤统一维护在[转发与启动器联机优化实测](../../minecraft-tunnel-native/docs/30-性能报告/02-20261110-文件与游戏协同实测.md)，不在这里复制第二份结果表。

验证使用 `build-multiplayer-perf/`，避免重链接正在运行的主 build/bugg.exe。直接相关 Qt 回归 27 项通过，包含请求优先级、已发送请求不可抢占、空事件无 changed、真实消息/路径更新、授权、同步/缓存、取消和启动参数。真实隔离节点设备批准、旧后台请求期间更新节点句柄、好友和房间完整流程通过，使用本轮桥的独立正式安装目录。

同一 200 消息快照的空事件微基准交替三轮：25000 次调用中位数从 15.863 ms 到 0.135 ms，changed 从 25000 到 0，状态一致。这不代表启动器整体或游戏帧率的倍数提升。Windows/Linux 混合文件/游戏 P2P 的 p99 结果见完整报告，macOS/ARM64、新版真实 GUI 双客户端及弱网完整矩阵未在本轮执行。

原始证据在相邻节点项目的 `validation-artifacts/forwarding-20261110/`。没有更改窗口、QML 或 DOM，故未以旧截图声称本轮界面验收。测试夹具的 `BUGG_TEST_BUILD_DIR` 只选择独立验证目录，不改变产品运行入口。
