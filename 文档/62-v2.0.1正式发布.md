# v2.0.1 正式发布

发布所有者为 `.github/workflows/package.yml`。本次 GitHub Actions 使用一次性 Windows runner，干净 checkout 本仓库及固定原生桥提交 `f4480e00b6168cbdd8eef49040201e8cc734f25f` 编译，不上传本地候选冒充 CI 产物。构建结束移除临时 runner 及仓库构建机变量，后续默认仍使用 GitHub Windows runner。精简静态 Qt 6.8.1、静态 CRT、OpenSSL 和原生依赖复用既有构建脚本及已验证的构建工具链；静态程序不依赖旁置 Qt DLL。

`tools/package_release.py::main()` 只在构建期运行，输入版本、EXE、语言附件目录和输出目录；输出 Windows 原生 ZIP、版本标记、内容寻址语言附件和校验摘要，无启动器运行时依赖。此前没有与原生更新清单匹配的发布打包方法，所以在工具目录添加唯一入口。ZIP 的 `bugg.exe`、`Buggcraft.exe` 是同一 CI 程序，后者用于旧版更新迁移；没有放入存档、账号或本地配置。

下载站继续使用现有发布审核、文件哈希和更新接口。只有 ZIP 中两个 Windows 入口完全一致才提供旧版迁移文件；原生更新仍要求 `runtime=cpp`。构建的语言命名空间与发布版本一致，避免访问缺失的历史语言附件。Windows x64 为本次范围，其他系统不以本次产物冒充支持。

复查 `LauncherUpdateService::download`、`copy_file` 和既有实际 HTTP 更新测试后，在原 worker 增补 Windows 改名入口兼容：校验官方 ZIP 后，从标准 `bugg.exe` 复制到用户原文件名，再复用同一安装与回滚流程。没有新增下载器、安装器或 UI 状态。发行打包额外接受历史入口参数，用于尚未包含此修复的临时 v1.1.0，不在产品解析代码按旧版本名称特判。

发布前实际查看常规与面板任务页截图，发现 `TaskCard` 与身份页共用的 `DesignTokens.canvas` 仍为不透明白色，导致其他页面启用背景后的白字不可读。沿用现有颜色令牌，使其仅在 `pageBackdrop` 生效时使用用户设置的蒙版透明度，关闭后保持原颜色；没有另加页面样式。既有背景测试补查透明度及关闭恢复，并重新查看两种尺寸任务页：白底已去除，来源、标题、下载进度可见。

按发布过程中新增要求，将设置入口、页面标题和独立调试窗口统一命名为“问题反馈与调试”，沿用 `LogsPage`、原反馈弹窗与提交链路。

公网发布和升级验证证据在完成后补充；本地样包与之前的游戏启动实测不能替代线上发布证据。

本轮新增修复：媒体播放列表内容不变时不重建，静音、设置及任务快照不使视频重播；Windows 原有松键轮询同时处理移动，避免进入系统阻塞拖动循环。取消整窗模态模糊，保留有界白色弹窗及遮暗；媒体页与快捷账号菜单共用表面令牌。首页版本文字为常规 24px、紧凑 15px，空实例扫光；主按钮保留紫色。更新渠道在原设置保存，默认开发版 beta、可选 stable，开发版包含稳定版；设置变化及启动初始化沿 ApplicationLifecycle 应用，不添加定时任务。客户端保留服务端的语义版本次序并验证发布格式，允许合法开发版后缀。

直接验证证据：`build/video-native-drag-test.txt` 实际鼠标移动时媒体源重载 0、播放位置持续前进、GUI 最大事件间隔 28ms；`build/media-final-channel-test.txt` 实际视频、静音、任务更新及渠道选择通过；`build/update-preferences-final-test.txt` 设置持久化通过，`build/update-channel-test.txt` 验证开发/稳定渠道及旧请求隔离、开发版后缀。QML lint 和组件边界通过。常规/面板的空实例、任务、游戏身份、更新页，常规快捷身份菜单及首次约定/光影反馈弹窗截图均已实际查看，路径在 `build/verification/media-release`、`first-run-layout`、`background`、`pack-round2`：无整窗模糊外沿、按钮可读、媒体页无大片白底。图中测试视频是用户指定目录的本地素材，不随发布包分发。

节点先于启动器交付：原生节点提交 6748ddf 的五个平台及网页 CI 全通过，上海切换同一 CI 原生产物；直接公网完成 Minecraft 握手、262161 字节一致和 EOF，保留节点身份、配置与回退。正式节点号为 v0.3.12，其最终构建/部署结果待补；启动器工作流在对应节点发布完成后才公开启动器资产。
