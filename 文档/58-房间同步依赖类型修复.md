# 房间同步依赖类型修复

2026-11-14。用户报告 `1.21.1-minecraft--BUGG-c7f7ea22-420f5a15` 同步失败，界面错误为 `unknown_neoforge_dependency_type`。本轮从统一服务取得反馈 `761f8a4e-e109-4f70-9d44-76af2985935f`，没有要求用户重新上传日志。

## 原因及复用

两次失败均发生在文件传输完成后的依赖检查、正式提交之前。真实文件 `puzzleslib-v21.1.66-mc1.21.1+neoforge.jar` 的 `META-INF/neoforge.mods.toml` 为 Minecraft 和 NeoForge 两条依赖声明 `type="REQUIRED"`。其 SHA-256 为 `cb02de7e1d4a133746ec7b43a64eddc2cb621122cdc49e134a15272f456c31f2`，大小 1,451,120 字节。

NeoForge 官方 `ModInfo` 会先以 `Locale.ROOT` 转大写再解释 `DependencyType`；项目原生解析器却仅接受小写。参考：[FancyModLoader 官方实现](https://github.com/neoforged/FancyModLoader/blob/main/loader/src/main/java/net/neoforged/fml/loading/moddiscovery/ModInfo.java)。这是启动器共享解析器的兼容缺陷，不是 PuzzlesLib 声明无效。

检索调用链为 `GameOperations::sync_room` → `check_dependencies` → `DependencyFacts::collect` → `dependency::metadata_json`，修改源站拥有的共享 C++ 实现，并同步 `third_party/dependency_core` 独立构建副本。四种类型 `required/optional/incompatible/discouraged` 统一按 ASCII 不区分大小写解释，证据中的 `raw.type` 不变，未知值继续失败。源站 Python `parse_toml` 已使用 `.lower()`，无需修改另一套产品逻辑。

原生事实版本升为 `native-1.3.1`，旧原生持久结果重新扫描，源站现有 `1.3.0` 仍接受。复用原房间传输、SHA 校验、断点目录与原子提交，未增加后台任务、界面状态或绕过依赖校验。
