# 2026-11-11 启动器打包体积与误报实测

## 结论

Windows x64 Release 启动器主程序为 7,729,664 B（约 7.37 MiB）。只看 EXE 可以低于 10 MB；完整离线便携包必须包含 Qt、QML、图形运行时、联机桥及其依赖，当前精简实验包为 76,396,393 B 解压、21,195,570 B（约 20.22 MiB）7z，标准 ZIP 为 32,122,473 B（约 30.63 MiB）。完整包低于旧版 50 MB 的目标已达到，10 MB 完整离线包没有达到，也不应通过漏装运行库或把联网下载器伪装成完整包来宣称达到。

本报告是 Windows x64 隔离实验，不是正式签名发行物。包、清单、截图和构建日志都位于 `build/packaging-study/`；没有覆盖固定启动入口 `build/bugg.exe`，没有发布或部署。包体基于 12:48 保存的启动器快照；研究期间工作区 `build/bugg.exe` 在 12:59 被另一构建更新，因此不能把快照包体当成该较新构建的精确字节测量。

## 测试文件与运行时依赖

- 启动器开发 `build/` 下有契约、模块、集成及评审测试可执行文件；它们不进入运行时包。`windeployqt` 扫描到开发用 QML 导入目录时曾复制 1501 个文件、108.92 MB，其中混入 CMakeFiles、QML 开发元数据、`.qmltypes` 等。过滤后 325 个运行时文件、82.53 MB，界面仍能启动并正常截图。
- 联机项目的 CMake 安装树单独 staging 为 28,093,984 B、28 个文件，没有测试程序。不得把整个 build 输出目录打包；SDK 发包与启动器发包也要分开。启动器以独立进程调用桥，只需要桥程序及其 PE 导入闭包，不需要 SDK DLL、导入库和 SDK 头文件。
- 联机项目的 `cmake --install` 安装树单独 staging 为 28,093,984 B、28 个文件，没有测试程序；测试 target 只在开发构建目录。新版启动器 CMake 目前仍对安装树 `runtime/bin/*` 做通配复制，因此即使不会带入未安装的测试程序，也会额外复制 SDK DLL、core 和非启动器依赖。隔离样包按 `buggcraft-bridge` 的 PE 导入闭包生成，剔除了这些非必需文件。要让生产构建复用此收益，仍需把依赖闭包清单接入正式 staging，并在跨平台构建上验收。
- 不同版本/名称重复的 GCC 运行库、历史 DLL、CLI 核心或测试二进制不应通过 `runtime/bin/*` 通配符拷入用户包。发行 staging 应由目标专属清单或依赖导入闭包生成，并输出文件名、大小和 SHA-256 清单。SDK 包另按消费者的 ABI 保留共享库、头文件、导入库和许可证。
- 桥使用 `-Os -ffunction-sections -fdata-sections` 与链接器 `--gc-sections` 的独立构建，在本次导入闭包包中比此前桥包减少约 0.56 MB（归档对比）；这不是 SIMD 速度测试。尝试 LTO 时 MinGW GCC 15.2 的 `lto-wrapper` 在 `bridge/runtime.cpp` 触发内部编译器错误，故当前实测关闭 LTO。不要为了省少量体积让发布构建依赖该失败配置。

## 符号裁剪和功能验证

对隔离包副本中的 GCC PE 文件运行 `strip --strip-unneeded`。桥程序从 3,893,357 B 减至 2,963,149 B；libcrypto 从 7,131,555 B 减至 5,821,494 B；libdatachannel 从 3,482,621 B 减至 2,142,860 B；libssh 从 730,658 B 减至 559,922 B；libssl 从 1,358,038 B 减至 1,050,045 B。裁剪前后检查 PE 的 `.text`、`.pdata`、`.xdata`、导入和导出表一致。Windows Qt 主程序仍是 MSVC 编译物，不能拿 MinGW strip 处理。

使用精简重编译并 strip 后的桥运行：

- 桥测试：3 项通过，包含关闭压缩的原始转发与 EOF、两进程 P2P/中继、身份钉扎及帧预算。
- 原生 C++ 单元测试：110 项通过，0 失败。
- C ABI 桥测试：通过。
- UI 实际启动并捕获预览图；界面与现有基线一致。
- Windows Defender 当前定义版本对完整隔离候选目录自定义扫描：未发现威胁。

这只能说明该文件在此机器、此时的 Defender 扫描没有检出威胁，不代表 SmartScreen 声誉、其他杀软或正式发行后的零误报。

## 打包建议

1. 正式流程分开生成测试产物与运行时安装树；发布任务只从 `cmake --install` staging 加 Qt 官方部署结果收集明确依赖。发布包生成完成后检查禁止项：测试程序、测试数据、CMakeFiles、开发元数据、旧 DLL 备份、与当前进程模型无关的 SDK 产物。
2. 对体积仍敏感的动态库使用其官方配置选项关闭未使用功能，并用导入/导出检查和实际工作流回归验证。项目的 libdatachannel 已关闭 media、websocket、examples、tests。不要重写 OpenSSL、TLS、SSH 或 WebRTC 算法来换几 MB；维护和安全风险远大于体积收益。
3. GCC/Clang 可在发布 profile 评估 `-Os`、函数/数据独立段、链接时段回收和稳定工具链下的 LTO；MSVC 使用 Release 优化与 `/OPT:REF /OPT:ICF`，仅对副本 strip/裁剪。每个平台单独跑 ABI、启动、联机和安全扫描。LTO 是否开启以构建稳定性及实测收益决定。
4. 维护一份未 strip 的内部符号包用于崩溃定位；对外二进制再做 strip。strip 移除符号/调试信息，不会删除源代码注释（注释不会作为 C++ 源码文本留在普通机器码中）。对 `.so`/插件不可随意 `--strip-all`，必须保留导出 ABI。
5. 不用 UPX、未知加壳器或脚本冻结器；不关闭或要求玩家绕过安全防护。Windows 对发行 EXE 与安装器使用稳定发行者身份的 Authenticode 签名并加可信时间戳；签名有助于建立来源和信誉，但新文件仍可能触发 SmartScreen，且签名不保证所有安全软件零告警。将真实误报样本交 Microsoft 分析入口，不要求用户白名单。
6. Qt 动态部署需要随包提供所需模块、插件及许可证材料。本次候选只为体积和运行性验证，不是合规发行包；Qt、OpenSSL、libssh、libdatachannel、curl 及编译运行库的许可证与重链接材料须由正式发版任务逐项审查。
