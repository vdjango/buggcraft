# 2026-11-12 任务栏、安装进度与 Logcat 日志验收

## 本轮结果

- 常规窗口使用 `Qt.Window`，显示在任务栏，不置顶；悬浮面板在托盘显示，继续保持置顶。没有可用托盘时面板保留任务栏入口，避免窗口失联。托盘恢复沿用同一窗口、页面、登录会话和任务，不重新创建运行时。
- 游戏安装入口在获取元数据、检查已有文件、连接、等待首字节、下载和重试时持续报告状态。资源客户端统一节流，普通字节进度最多约每 100 ms、等待状态约每 500 ms 更新；终态和阶段切换立即提交，不让第二层节流吞掉状态。
- 原版/加载器安装及普通导入成功后，只有用户仍在任务页才返回主页并选中完成实例。失败、取消和离开任务页均不强制跳转。本轮没有扩展在线整合包的其他完成路径。
- 设置中有“日志与调试”入口；启动失败的主页按钮为“查看日志”。日志页使用固定工具栏、时间/级别/Tag/消息表格、下方完整事件详情和底部导出栏，替换卡片堆叠。支持来源、级别、模组 Tag、关键字筛选、暂停/继续跟随、选择复制和原有脱敏导出。

## 实现所有权和边界

窗口和托盘归 `Main` / `WindowController`；不增加第二个窗口运行时。安装继续复用 `ResourceClient` → `GameOperations` → `GameRuntime` → 既有任务模型；界面只消费状态。成功信号 `installation_finished(task,instance)` 不在缺依赖/失败/取消时发出。

日志继续由 `GameRuntime` 的原文件 worker 有界读取。每个文件尾部预算 256 KiB、最多显示 500 个事件、单消息最多 12 KiB；Log4j XML 的消息和 Throwable 合为一个事件，普通文本的后续堆栈继承原事件级别/Tag。优先 launcher-game.log，没有时回退 latest.log，避免同一输出重复显示。筛选前收集来源和 Tag，日志等级或模组缺失不伪造。不是读取整个历史文件的无限日志数据库。

`LogRow` 只处理行展示和选中意图，复用现有按钮反馈、颜色令牌和文字组件；详情复用 `TextAreaField.flat`，不在页面复制文本输入实现。页面滚动会暂停跟随；选中详情在继续刷新/筛选时可保留供复制。布局参考 [Android 官方 Logcat](https://developer.android.com/studio/debug/logcat)，不宣称实现 Android 的全部查询语法。

## 真实光影失败：原因与本地恢复

检查用户实例 `build/.minecraft/versions/26.3-neoforge-26.3.0.101/logs`，实际失败是 Sodium 0.9.2 的 `LevelExtractorMixin` 对 NeoForge 26.3.0.101 目标方法不匹配。并非两个光影 ZIP 同时存在导致；没有删除光影、世界或配置。

Iris 1.11.7 的发布元数据仍指向旧 Sodium。官方 [问题 3975](https://github.com/CaffeineMC/sodium/issues/3975)、[修复 PR 3948](https://github.com/CaffeineMC/sodium/pull/3948) 与 [问题 3950](https://github.com/CaffeineMC/sodium/issues/3950) 支持该判断；其他较新的测试版也有 [Iris 兼容问题](https://github.com/IrisShaders/Iris/issues/3466)。因此分别选择“最新”不等于组合兼容。

本地实例使用官方 Sodium `0.9.3-beta.1+mc26.3` 临时恢复，发布版本 ID `SS023RVV`，大小 1,209,577 字节，SHA-1 `c9412897122afb33007f6c0d6ee1b2248a9ebcf7`；实际下载核对 SHA-512，并检查修复版本不再包含出错 Mixin。原 JAR 改为 `.jar.disabled`，实例安装收据同步，原收据和 JAR 保留在 `D:/BuggBuild/window-progress-20261112/shader-rollback`，不是删除后不可恢复。该版本是 beta，不能标成稳定版。

随后把配置/模组/光影复制到隔离根目录，不复制账号或存档，复用缓存与 Java，以原生 `GameRuntime` 实际启动。88.614 秒的针对性流程通过，日志进入渲染初始化/纹理 atlas 建立，未重现原 FATAL/Mixin 异常；测试只停止自己创建的游戏进程。未进入世界游玩、未做 FPS 对比或长时间稳定性测试。

自动兼容判断仍沿用现有 Minecraft/加载器具体文件、作者必要依赖、活动核心检查和摘要验证；本轮没有加入版本号硬编码的永久覆盖清单。作者元数据缺陷或未声明的运行时冲突不能仅靠版本标签完全预判，用户不应手工维护每次普通依赖升级，但也不能承诺任意模组组合免测试。
