# 按需语言包与单背景体积实测

## 实测结果

语言包已经移出主程序；简体中文使用内置源文案，其他语言首次选择时下载，校验后缓存，之后可离线使用。默认背景只保留 `home-siege-1.webp`。没有音频资源需要拆分，本轮处理的是前文讨论的界面语言包。

Windows x64 完整样包包含启动器、精简静态 Qt、原生联机桥、桥依赖和应用本地运行库。MB 按十进制，未省略必要依赖。

| 项目 | 上一轮精简静态 Qt | 本轮按需语言、单背景 |
| --- | ---: | ---: |
| 主程序（已含 Qt/QML） | 30,346,752 B | 26,548,736 B |
| 完整目录 | 52,800,436 B | 49,002,420 B |
| ZIP / Deflate 9 | 23,323,777 B | 20,905,102 B |
| 7z / LZMA2、32 MiB 字典 | 16,207,494 B | **14,219,568 B** |
| 交付文件数 | 30 | 30 |

7z 再减少 1,987,926 B，约 **12.27%**。与第 43 份报告的官方 Qt 基线相比，本轮完整 7z 从 21.20 MB 降至 14.22 MB。仍未达到 10 MB，不能把 26.55 MB 静态 EXE 和此前 7 MB 动态 EXE 单独比较。

两轮包清单逐项比较，除 `bugg.exe` 外其余 29 个文件的路径、大小和 SHA-256 一致；Qt 套件、压缩参数、原生桥字节均沿用上一轮。源码差异在 `on-demand-source-changes.json`，主要为语言资源、翻译所有者、生命周期、界面状态、背景和验证代码；没有把未执行的桥库重编译算进本轮收益。

## 语言按需机制

构建使用 Qt `lrelease -compress -nounfinished`，生成 104 个独立 QM。仅按本次清单引用的附件统计：总计 7,882,457 B，单包 48,010–84,054 B；例如英文 84,054 B、繁体中文 48,010 B。104 个包无需全量下载。此前全部 QM 经 Qt 资源压缩后在 EXE 中仍占约 3.74 MB；本轮只嵌入语言名称和版本/摘要清单。

`LanguageService` 仍是唯一所有者，复用 `ResourceClient`、安全路径、原子下载提交和摘要校验；没有复制下载器或引入 Python 运行依赖。后台校验大小、SHA-1、SHA-256 和 QM 可加载性，成功后 GUI 才安装翻译。损坏包不应用；失败可重试，取消或快速重新选择时旧结果不覆盖新意图。一次仅一个 worker，退出进入既有 `ApplicationLifecycle` 的取消/异步排空流程。完整契约见 [24-语言与即时设置](24-语言与即时设置.md)，接口和方法索引已同步。

原文案译文保留；新增下载提示补有英文，其他语言尚有中文回退，不能宣称逐语种翻译已审校完成。游戏本身的语言资产仍由原来的 Minecraft 准备流程管理，没有移除。

## 图片和运行库

默认背景从四张降到一张，原始图片文件减少 93,804 B。另外三张已移出项目，归档于工作区 `.task-archives/2026-11-11-unused-launcher-backgrounds`，不参与构建。用户自选多张背景仍复用 `BackdropCarousel`，默认单图不启动轮播。

原生桥的构建收集规则从复制整个 `bin` 改为 `cmake/StageWindowsBridge.cmake`，使用 CMake 的 PE 依赖闭包，输出 `runtime-files.sha256`。实际用混有 SDK/其他文件的原始 `build/native/bin` 验证，只选出桥及依赖 9 个文件；同样检查了上一轮精简桥目录。依赖缺失或落到开发者 PATH 的非系统库时构建失败。规则不会清除旧目标目录残留，发行必须使用干净 staging 或按清单取文件，不能把旧目录整体压缩。

本轮样包沿用之前已验证的精简桥，不含测试 EXE、QtTest、PDB/LIB、CMake 开发文件、Python SDK 示例、TS/QM 全量目录。D3Dcompiler_47 和本地 MSVC 运行库保留；微软说明运行时使用的独立编译器需要随应用部署，不能以开发机可运行为由删除。依据：[DirectX 部署说明](https://learn.microsoft.com/en-us/windows/win32/directx-sdk--august-2009-)。

## 发布接线

运行时沿用下载站版本资产 URL：

```text
https://download.bugg.icu/api/launcher/assets/<版本>/Bugg-language-<SHA-256>.qm
```

现有下载站的 `LauncherReleases` 已扩展为允许原生 ZIP 附加语言资产；验证命名摘要、256 KiB 上限和 QM 文件头。发布后才可获取，撤回后不可获取；附件不进入玩家安装包列表，不增加 ZIP 下载计数。沿用原发布权限和版本资产接口，未增加另一套文件服务。这里扩展的是既有下载站后台，不是启动器的 Python 依赖。

正式发布时先构建匹配版本的清单和 QM，通过已有管理员发布 API 与对应版本 ZIP 一起上传，再发布。原生版本至少有一个平台 ZIP，不能只上传语言附件作为完整版本；不要把所有语言重新装入 ZIP。当前管理员浏览器文件选择器及 GitHub 同步的语言附件自动上传尚未扩展，因此本轮附件使用已支持的发布 API，而不能假定拖入旧网页即可发布。

本地 `language-release-2.0.1/` 已按内置清单选出准确的 104 个附件及审核用 `packs.json`；`packs.json` 不需要作为公开资产上传。开发构建目录可能有历史 QM，发布只取当前清单，不扫整个缓存。不同版本的同名摘要语言内容不变；客户端始终按自己内置版本和摘要请求。

**尚未部署下载站的新校验代码，也未上传这些语言附件。** 因而当前公网不能视为已上线按需语言。没有变更服务器或另一个窗口使用的固定 `build/bugg.exe`；本轮是源码实现和独立样包验收，不是正式发行。

## 验证证据

- `RuntimeTest`：7 passed、0 failed、0 skipped（含初始化/清理）。覆盖真实 QM 下载、摘要损坏拒绝、重试、取消、快速换语言、断网后重新创建服务复用缓存，以及既有 HTTP 原子下载、真实窗口关闭和生命周期用例。
- `ContentTest`：5 passed、0 failed、0 skipped（含初始化/清理）。实际打开 Main.qml，在常规/面板主题验证加载、失败、点击重试成功和单背景首页；保留原富文本与四种尺寸内容流程。逐张查看了加载/错误/成功及首页截图，没有重叠或裁切。日志仍有原来的 `DelegateModel::cancel: index out range` 警告，不称作无警告。
- 下载站本轮完整模块测试 29 项通过；新增附件发布/撤回可见性、列表不混入附件、错误摘要拒绝两项定向复验通过并保存日志。
- `qml_component_boundaries` 检查通过。完整样包清除 Qt/QML 开发变量并仅保留 Windows 系统 PATH，常规、面板、软件渲染和语言设置路由均实际启动退出成功。短定时截图不作为启动就绪耗时。
- ZIP CRC、7z 完整性检查通过；Defender 对该完整目录扫描未发现威胁。没有使用 UPX、自解压壳或关闭防护；未签名，不保证 SmartScreen 或其他杀软结果。

这些结果仅证明本轮 Windows x64 样包。原生桥转发沿用上一轮相同字节及旧回归证据，本轮没有重新做公网联机吞吐测试。macOS/Linux、正式签名、静态 Qt 发行所需完整许可/重链接材料和完整玩家交互仍需各自验收。

## 后续体积空间

压缩前主程序约 26.55 MB，桥及依赖约 16.63 MB，剩余主要是 D3D 编译器和运行库。下一步有价值的是同工具链裁剪/重编译 curl、OpenSSL 等库，以及进一步审计 Qt 注册类型保留；这需要 TLS/DTLS、打洞和转发回归，不能直接删除 DLL 或只复制库里几个函数。与此前源码构建 Qt 的收益一样，应分别实测完整包和玩家流程，不先承诺能到 10 MB。
