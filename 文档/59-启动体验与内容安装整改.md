# 启动体验与内容安装整改

2026-11-15，本轮按用户 1–8、10–18 项要求实施，保持既定窗口尺寸、顶部导航位置和页面布局。

## 所有者与规划

- 弹窗：复用 `ModalSurface/ChoiceDialog`，明确不透明正文、常显滚动轨道与阅读提示；模态期间只模糊启动器底层，弹窗本身保持清晰。呈现状态归 DesignSystem，不进入业务会话。
- 导航：复用 `NavItem/InteractiveSurface`，保持位置、尺寸和选中线，未选中项增加轻微常态表面和明确的键盘焦点。
- 背景：复用 `AppearancePage/BackdropCarousel/WindowFrame`，图片和文件夹共用同一播放列表。目录读取放入 GameRuntime 原文件 worker，有界扫描；不新增监视器。透明度只影响景色上的 UI 表面，正文和弹窗保持可读。模糊提供关闭、顶部、上下边缘、整体模式；暗角独立调节，默认保留中间景色。GPU 复用 MultiEffect，软件后端保留渐变遮罩。
- 好友及游戏列表：原快照和原索引不变，仅呈现排序；自己置顶，在线朋友在离线之前，通知保持服务项，离线状态明确。好友行缩紧。
- 光影与整合包：复用 `instance_descriptor` 和原内容预检，识别导入包真实加载器与已有核心；原版补装复用 `updateExisting`，不新建实例。修复无加载器时长期计划及目录回退；四加载器共享依赖解析，不按单一模组写例外。
- 语言：复用 LanguageService/ResourceClient 的有限重试、内容摘要缓存与取消，核对内置语言清单与线上制品一致；真实失败写入诊断。
- 下载：复用现有有界并发和 HTTP Range，实测 CF 冷源文件并发；低速备用来源切换沿原 HttpClient/ResourceClient，不新增下载器，不承诺服务器不存在的限速策略。
- 吸附：唯一状态仍归 WindowController/EdgeDock。入口在非游戏时置顶并可恢复原主题；游戏期遵循吸附显示/隐藏设置。无动作不隐藏；隐藏在游戏结束后恢复原窗口；吸附隐藏在游戏结束后恢复吸附条；关闭在联机期间降为隐藏并说明。

## 日志与根因

已读取 `error/Bugg-diagnostics-20261114-221935 copy.zip`（590551 字节）的任务、版本及网络信息。原版 26.3 的实际 metadata 确实没有加载器；Fabric 目录 HTTP 200，却因 intermediary=0.0.0 被当成游戏版本不匹配而全部过滤。官方按游戏查询的接口允许该占位映射，修正共用解析规则后可保留全部候选，不为 26.3 特判。实时官方目录为 255 个候选，0.20.1 的 profile 也能获取，见 `build/experience-fabric-live.json`；这不等于已运行这些组合。

临时 EXE 版本 1.1.0 曾被用于语言资源目录，线上对应目录没有文件，造成 404。语言资产现在使用独立、内容摘要命名的 1.0.0 命名空间，104 份 QM 已补齐，未发布 EXE、未改发布索引；英语/繁中/日语的公开 HTTPS 下载及大小、SHA-256 通过。原 LanguageService 的校验、离线复用、失败保留当前语言、重试与取消继续复用，失败诊断保留 URL 和真实错误。

导入包错误 `unknown_neoforge_dependency_type` 与 PuzzlesLib 的大写 REQUIRED 归同一个共享解析器；此前已修复的大小写归一化继续沿用，未知值仍报错。新增本地父版本合并和现代 NeoForge FML 参数识别，避免把导入包误认作原版；缺失本地父文件时仍保留子文件自己的声明，不在扫描中联网或隐藏实例。

## 下载实测与改动

Windows 11 x64、MSVC 2022、Qt 6.8.1，使用原生 ResourceClient，4 个 CF CDN 文件共 5,357,650 字节，独立临时目标、每份做 SHA-1 校验，不经过本机/源站文件缓存；公网 CDN 自身缓存不可控。按 1、4、4、1 交替测得 18.112、42.922、87.691、39.156 秒。加入低速回退后的两次观察为 1 路 44.302 秒、4 路 25.222 秒。网络波动明显，这些数据不能证明 CF 禁止多线程，也不能宣称固定倍数提升或按此写死线程数。

真实导入发现少量文件持续有数据但吞吐很低，旧空闲超时不触发。现在只有存在备用候选时，对连续 10 秒低于 4 KiB/s 的文件沿原重试换源；最后候选不启用最低速率门槛。首字节等待独立计时，已下载部分仍按同一文件摘要续传，最终大小/摘要不匹配绝不发布。隔离真实 HTTP 测试验证低速连接 → 备用地址 → 完整摘要及原子提交；Range 拒绝/错误范围/取消测试通过。受控 10 MiB 的三个 Range 为 114 ms，单连接 210 ms，仅说明该模拟场景，不能当作公网提速承诺。

原始证据：`build/experience-cf-measurement.json`、`build/experience-cf-after.json`、`build/experience-download-regression.txt`。源站未命中仍沿已有重定向下载和摘要校验，不等待重新缓存整个包后再给启动器。

## 真实整合包与本地枚举性能

用户的“香草纪元：食旅纪行 Release2.7.1（含 MCEF）”原始 ZIP 已用原生安装路径导入到隔离实例 `VanillaEpoch-experience`，422 项资源完成校验并提交，未覆盖用户原实例，也未启动游戏。完整导入耗时 694.144 秒，原始记录为 `build/experience-real-modpack-after.txt`；第一次 300 秒的测试超时记录保留，不计为通过。包内真实声明告警仍按原流程呈现，不以保留包作者文件冒充约束全部兼容。

这次导入还暴露了本地 CPU 耗时：原 `archive_entries` 对每个 JAR 成员调用以系统临时目录为根的 safe_path，产生大量与只读枚举无关的文件系统查询。现复用同一个私有成员名校验，真正提取/发布时仍做目标边界和符号链接检查。500 项同一 ZIP 的旧路径校验单步为 359.2842 ms，新完整枚举为 1.9161 ms；两者范围不同，不视为整包导入加速倍数。路径穿越、绝对路径、盘符、反斜杠穿越、取消的检查通过。

修改后对真实安装结果只读检查：425 个根 JAR、448 份根模组声明，耗时 2123 ms，识别到已有 Oculus；没有重新下载这些 JAR，也没有启动游戏。证据：`build/experience-archive-performance.json`、`build/experience-installed-scan.json`、`build/experience-archive-tests.txt`。完整 422 项导入是在上述枚举优化前跑通，优化后只复验路径安全及实际安装结果枚举，避免无必要地再下载整包。
