# 全新 QML 界面与组件清单

> 状态：设计规划。旧版 QML 只用于核对“用户必须能完成什么”，不是新界面的代码、布局或视觉来源。本文件不是已实现声明。

最新补充：当前采用浅色工具面板。收起时是一条菜单，点击启动/搜索/联机/好友/设置后，整个面板按需伸展；不是大页面，也不做悬浮球。以下组件清单是完整产品的候选范围，不能全堆在首屏。已实现范围与验证见 [15-首页交互原型与预览](15-首页交互原型与预览.md)。

2026-11-08 更新：设置提供「悬浮面板 / 常规页面」两种布局，共用同一个工具条和浅色视觉。常规主题使用标准顶部导航「启动、广场、联机、好友、设置图标」，收起/关闭在右上角。内容扩大间距、压缩说明、按步骤展开，不把小面板直接拉宽或把按钮铺满页面。DesignSystem 负责通用控件，Shell 负责呈现与动画，Pages 组合控件并发出意图。已补齐的 UI 页面与入口见 [17-页面清单与操作流程](17-页面清单与操作流程.md)；其中业务服务尚未迁移。禁止在 Main.qml 内联导航、按钮、输入和页面布局。

贴边后可进一步折叠为细小拉手：上边横向、左右竖向，点击弹开、离开延迟收起。新组件 DockHandle 只提供拉手视觉和点击/拖动意图，复用 AppIcon；状态与动画进度由 EdgeDock 唯一管理。

## 边界：全新界面，项目内部复用

新项目重新制作主窗口、导航、全部页面、弹窗、按钮、列表和反馈状态。**不复制**旧版 launcher/、multiplayer/ 等目录的 QML，不把现有按钮换色后称为重设计。旧项目仅用于记录必要功能、字段和兼容流程；视觉与交互由新原型决定。

QML 可以复用组件、布局和按钮：把新写的通用元素放到一个 Bugg.DesignSystem 模块，页面 import 后组合使用。同一个按钮组件承载主操作、次操作、危险操作等状态；同一布局组件承载空态、列表态和详情态。业务规则与数据仍由 C++ 服务及呈现模型管理，QML 只负责显示、输入和发送命令。新组件的改动必须能在所有使用它的页面生效。

## 新界面的三层结构

| 层 | 示例 | 职责与复用边界 |
| --- | --- | --- |
| 设计令牌 | DesignTokens.qml、Typography.qml、Motion.qml | 颜色、字体、间距、圆角、焦点、动画时长；页面禁止硬编码重复值 |
| 通用组件与布局 | ActionButton、TextField、ModalSheet、NoticeBanner、TaskProgressRow、PageFrame、SplitPane、SectionHeader、EmptyState | 完整的外观、键盘与状态处理；只从公开属性/信号接收页面信息，不访问下载或联机服务 |
| 业务页面 | HomePage、DownloadsPage、TasksPage、RoomsPage、InstancesPage、SettingsPage | 组合通用组件，绑定 C++ 页面模型，处理页面内导航；不复制通用组件实现 |

页面中的“建房步骤”“下载来源排序”“重名决策”可各自成为独立的流程组件，但其专用逻辑属于对应页面/呈现模型，不能为追求复用全部塞进 DesignSystem。跨两个以上页面且语义一致时，才提升为通用组件。

## 组件目录与公开接口草案

    qml/Bugg/DesignSystem/
      DesignTokens.qml       # 单例；配色、尺寸和间距
      ActionButton.qml       # text、variant、busy、enabled；clicked
      IconButton.qml         # icon、accessibleName、variant；clicked
      TextField.qml          # label、value、placeholder、error；edited
      PageFrame.qml          # 标题、操作区、内容 slot、状态区
      SplitPane.qml          # 主内容/详情内容；窄窗口自动切换
      SectionHeader.qml      # 标题、说明和右侧操作
      ModalSheet.qml         # 焦点圈、Esc、遮罩、确认与取消
      ConfirmDialog.qml      # 强调删除路径和危险动作
      NoticeBanner.qml      # 成功、警告、错误及恢复动作
      EmptyState.qml        # 说明、下一步操作
      TaskProgressRow.qml   # 文件名、实际来源、速度、进度、失败原因
      SourceOrderList.qml   # 按键/拖动排序及禁用状态
      StepTimeline.qml      # 建房共享同步与安装分步进度
      qmldir / CMakeLists.txt
    qml/Bugg/Pages/
      HomePage.qml
      DownloadsPage.qml
      TasksPage.qml
      RoomsPage.qml
      InstancesPage.qml
      SettingsPage.qml

先定义组件公开属性、信号和可访问名称，再做页面。页面不得依赖组件的内部 id；组件不得 import 业务页面。组件中的异步状态通过外部 model/属性传入，不在 QML JavaScript 中自己建立网络请求或扫描文件。

## 全页面重新设计的交付清单

| 页面 | 全新布局的关键区块 | 必须保留的用户能力 |
| --- | --- | --- |
| 首页 | 实例主卡、启动状态、房间快捷入口、任务小摘要 | 启动前 Java/实例可用性与错误原因可见 |
| 下载 | 内容类型切换、搜索、来源顺序、导入入口、结果/详情双栏 | 真实来源与任务状态清楚可见；切源立刻影响下一下载尝试 |
| 任务 | 分组任务列表、文件进度/详情、等待补齐和失败原因 | 取消立即响应；只补失败项；成功项不重下 |
| 联机 | 房间大厅、节点与连接状态、成员、建房/加入流程 | P2P 自动优先、中继兜底；共享加速同步进度可感知 |
| 实例 | 实例列表、版本信息、目录和操作区 | 重名决策；移除记录/永久删除文件清楚区分 |
| 设置 | 账号、便携缓存、Java、来源排序、更新与诊断 | 每项有简短解释；无需用户填写协议内部字段 |

弹窗也全部重新制作：首次启动引导、下载确认、重名选择、删除确认、建房共享、登录反馈、失败补齐与问题反馈。每种弹窗有一个明确主操作与一个退出路径，不把多步流程塞进系统原生 message box。

## 视觉与交互定稿顺序

1. 先画六页线框和六条主流程，明确各页信息优先级；旧界面截图只用于核对遗漏功能。
2. 再完成新的令牌、字级、图标、按钮、输入、列表、弹层和空态；给组件做正常/悬停/禁用/忙碌/危险/错误/键盘焦点状态展示。
3. 做主窗口与首页、任务页的可点击原型，确认窗口刚出现就可拖动、取消和切页不冻结。
4. 补齐剩余页面及窄窗口布局，检查中文长名称、超长文件名、实际下载源、0 B/s 与网络错误如何显示。
5. 以 100%、125%、200% 缩放及键盘操作审查每页，并由真实用户完成建房、加入同步、下载失败补齐等任务；通过后才锁定视觉系统。

新视觉暂以清晰、克制和高信息密度为原则；具体色板和动效由原型验证，不能简单保留旧版紫色大按钮与像素化背景。完整验收见 [07-界面设计与交互规范](07-界面设计与交互规范.md) 和 [11-分阶段实施与验收](11-分阶段实施与验收.md)。
