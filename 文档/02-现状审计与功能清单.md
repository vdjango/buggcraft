## 已发现的集中化机会

- 来源规则目前散在 content_mirrors、content_routes、modpack_sources、downloads、bugg_mirror；新架构让 SourcePolicy 只定义排序与可用性，SourceResolver 只负责找候选，TransferService 只负责字节传输与校验。不能每个安装器各写一套重试。
- 下载与导入、房间同步在不同页面有各自的进度/取消机制；新架构让 TaskManager 持有任务生命期，页面只是观察者。页面关闭不取消任务，除非用户明确点取消。
- multiplayer_controller 单文件承担过多状态与 UI 协调；拆成 NodeService、RoomService、SocialService、RoomSyncService 和薄的页面呈现模型。联机传输仍由原生 Bridge 负责。
- settings 与 path helper 多处可能解释目录；新架构由 PortablePaths 提供唯一的路径决策，迁移适配器只读旧配置，不另立运行时路径规则。
- Java 自动/手动与安装器可执行路径要归一为 JavaSelectionService 的实际可执行文件，不能只存“自动”字符串而返回空路径。

## 功能范围分级

- **首批必需**：启动/便携、实例、Java、游戏本体与四类加载器、下载和导入、联机大厅与房间、文件补齐、离线/微软账号、更新、诊断。
- **紧接首批**：好友/邀请、模组/资源包/光影搜索、导出、房间文件加速和可见进度、辅助源管理、皮肤与翻译现有能力。
- **待验证保留**：旧客户端中低使用频率入口，先记在迁移清单，不删除用户数据；是否简化由使用场景与兼容测试决定。

禁止以「首批」为理由发布一个不能加入现有房间、无法导入旧包或会丢现有实例数据的版本。分批指开发顺序，正式切换有单独验收门槛。
