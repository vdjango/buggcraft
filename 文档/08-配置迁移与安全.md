# 配置迁移与安全

## 路径契约

假设 ZIP 解压目录为 BuggRoot：可执行文件与所需 Qt/Bridge 运行文件在 BuggRoot；应用自己的设置、下载缓存、诊断日志、临时文件、Java 运行库、任务日记在 BuggRoot/.buggcraft 或用户设置的**显式便携缓存根**。游戏默认目录为 BuggRoot/.minecraft；仅当不存在时创建并加入游戏目录列表，已有目录不覆盖、不重建、不移动。

PortablePaths 在启动时先定位可执行文件所在的真实目录，确认目录及子目录可写和路径无越界，返回 ConfigRoot、CacheRoot、RuntimeRoot、GameRoot。程序不得把自己的文件默默写到 AppData、Roaming、HOME、系统临时目录或工作目录。不能写入时给出明确修复操作或让用户选择一个便携的可写目标，并记录这个显式选择；不以改回用户目录“修复”问题。macOS .app 可能位于不可写安装目录，须在 macOS 原型阶段验证可移植放置方式，不承诺只要拷贝 .app 就可写入旁边。

配置文件仅保存相对路径或受控绝对路径标记；新选择的便携缓存目录必须位于 BuggRoot 内，复制整个 BuggRoot 到另一台电脑后重算相对路径。外部自定义 Minecraft 目录不随包迁移，界面要标记“外部目录”并在缺失时提示重新定位。Java 运行库路径和下载 .part 不得指向旧机器盘符。

## 迁移步骤

1. 启动后识别旧版设置文件 schema 版本，只读解析到新模型，不在原目录原地写回。
2. 先备份旧配置和任务记录到 BuggRoot/.buggcraft/migration-backup；备份位置、文件清单和恢复说明可见。
3. 转换账号元数据、实例目录、来源排序、Java 选择和任务状态；每项记录“已转换/需重新授权/不支持”的结果，失败保持旧客户端可用。
4. 新配置写到临时文件，校验后原子替换；版本号及迁移完成标记一同提交。重复启动幂等，不重复添加实例。
5. 先以只读方式对照样本配置、典型 ZIP/mrpack/buggpack、现有 .minecraft 文件树与启动结果；验收后才引导用户切换默认启动器。不得在首次启动清理旧文件。

## 凭据与隐私

账号刷新凭据、节点身份令牌与上传授权不进入普通日志或诊断包；诊断提交前显示收集类别、脱敏并取得用户动作。便携文件夹跨设备复制时，系统密钥链绑定的令牌可能无法恢复；账号与配置必须保留，敏感令牌若不可安全迁移就提示重新登录。不要为了“拷贝即用”改为明文保存长期 token；可研究用户口令保护的可移植加密文件，但要单独做威胁建模与 UX 评审。

来源 URL 与重定向要阻止携带用户凭据跳到不可信主机；下载按预期哈希验收。解压拒绝绝对路径、..、符号链接越界与超限内容。源站临时文件可被下载获得，房主在共享前要知道这一风险。日志、错误文案不能泄漏密码、完整令牌、私人目录结构或内部节点凭据。

## 更新与回退

更新版本与游戏实例数据分开。下载站向用户提供 ZIP，启动器内部更新可使用适配的原始资产，但必须验证签名/哈希与版本；失败保留旧可执行文件。配置 schema 做向后兼容窗口，切换新版本失败能回到旧版且不丢实例。用户主动退出或崩溃恢复后的任务状态与文件校验记录由同一 TaskJournal 管。

北京IP测试证书仅对精确控制origin请求提供公开信任锚。Windows Schannel 对匹配的自签名叶证书返回 SelfSignedCertificate 时，HttpClient 仅确认该精确证书/错误，绝不忽略其他链错误、过期或主机不符；未提供该请求PEM仍拒绝，不向系统CA安装证书。Qt官方同类用法见 https://doc.qt.io/qt-6/qsslsocket.html#ignoreSslErrors-1 。改用受信域名证书后移除此测试信任锚。
