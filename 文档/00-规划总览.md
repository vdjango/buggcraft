# Bugg C++/Qt 启动器规划总览

> 状态：2026-11-08 原生开发版本。已接入真实身份、实例、安装和启动，尚未完成联机服务与完整发布验收。现行发布版仍在 E:/code/buggcraft。

## 一句话目标

打造朋友一起玩的游戏大厅，让「选择现有实例 → 建房 → 邀请 → 自动补齐必要文件 → 开玩」成为可靠、可恢复、能看懂进度的流程；同时保留完整的游戏下载、导入、实例和 Java 管理。后续多人语音围绕现有联机房间展开，不另建独立语音房间体系；当前先完善游戏启动页。迁移不是把 Python 逐行翻译成 C++。

## 已确认的基线

- 现行仓库约 137 个 Python 文件、29,209 行 Python，约 73 个 QML 文件、6,610 行 QML；最大的联机控制器约 2,762 行，下载与整合包也有上千行单文件。此为规划时的文件统计，不是最终质量评分。
- 本地现行 Windows 单文件可执行程序约 48–53 MB；原生联机组件还会增加完整便携分发体积。**完整的 Qt + 原生联机 + 所需运行库的 ZIP ≤10 MB 不能先承诺。** 先做最小原型与真实部署清单测量；“主程序文件 ≤10 MB”与“完整离线包 ≤10 MB”分开统计。
- 新 UI 采用 **Qt Quick/QML + C++20 后端**，从零设计全部页面、布局和视觉组件。QML 的复用仅指**新项目内部**共用新写的按钮、弹窗、列表行、布局和设计令牌；现行 QML 只供核对功能与交互，不迁移其代码和样式。CMake 用 qt_add_qml_module 管理组件与页面；不引入 WebEngine。QML 运行库会增加完整分发体积，第一阶段必须验证中文排版、高 DPI、无障碍、启动响应和真实 ZIP 尺寸，不以牺牲现有功能来虚报 10 MB。
- 不重写已经存在的 C++ 联机传输协议与节点服务。新客户端通过明确的 BridgeClient 适配现有原生组件，维持 P2P 优先、中转兜底。是否并入进程必须另立兼容性与体积决策，不能为缩包盲目改协议。

## 不可丢失的既有约束

配置、缓存、下载暂存、运行库放在启动器旁边的 .buggcraft 或用户选定的便携缓存根目录；同级 .minecraft 只在不存在时创建，并作为默认游戏目录。用户移动整个 bugg 文件夹后仍能启动。文件名冲突有明确决策流程，不能静默覆盖。联机方式不可选：先 P2P，失败后中转。下载站面向浏览器交付 ZIP。新客户端切换前，旧客户端继续可用。

## 阅读和维护方式

总览只保存跨模块决策。详细规则只在对应领域文档维护，其他文档链接引用；方法列表集中在共享能力目录，避免文档也出现多份冲突规则。阶段完成必须附代码位置与测试结果，不能把“已规划”改写成“已实现”。

## 外部依据

- Qt 官方 [部署说明](https://doc.qt.io/qt-6/deployment.html) 说明静态与动态部署各有成本，完整包必须包含所需运行库和插件；Windows 官方 [部署说明](https://doc.qt.io/qt-6/windows-deployment.html) 给出依赖收集方法。
- Qt 官方 [网络访问类](https://doc.qt.io/qt-6/qnetworkaccessmanager.html) 提供异步 API，网络对象受其所属线程约束。
- 格式采用 LLVM/Clang 提供的 [clang-format Google 预设](https://clang.llvm.org/docs/ClangFormatStyleOptions.html)，具体选项固定在根目录 .clang-format。

这些是设计依据，不是对目标尺寸或兼容性的证明。目标需用原型和用户流程测试验证。
