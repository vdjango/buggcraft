# 2026-11-10 实例扫描性能优化

本轮优化新版启动器的实际实例扫描。40 个实例共用一份资产索引时，扫描中位数从 **310.629 ms 降到 51.070 ms，耗时减少 83.56%**；40 个实例共用四份索引时从 **313.942 ms 降到 91.575 ms，减少 70.83%**。这是暖缓存实例扫描结果，不是整体启动、联网、下载或游戏帧率提升。

## 检索与实现

先读取项目 AGENTS、唯一 bugg-cpp-qml Skill、方法索引、生命周期/界面状态契约和性能规范。检索 `scan_instances`、`refresh_instances`、`game_language_codes`、`apply_game_options`，并对照旧版 `core/game_languages.available_languages`：新版此前为每个实例单独打开、解析其资产索引；多个实例共用索引时重复做相同工作。

复用原 `game_language_codes`，只增加可选扫描缓存参数；读取与提取规则仍只有这一份。缓存键由原 `safe_path` 在函数内部生成完整路径，避免不同游戏目录的同名索引串数据。`scan_instances` 每次工作只持有一个局部 QHash，保存语言代码，不保存大 JSON；按本次遇到的不同索引数量增长，工作完成释放。下一次扫描、切目录、独立启动前设置游戏语言都重新读取。错误和缺失文件不写缓存，修复后能立即重试。

涉及的生产文件只有 `game_runtime.cpp`、`language_service.h/.cpp`，均使用 Qt 跨平台接口，没有新服务、依赖、线程、后台计时器或全局缓存，也没有修改编译指令集基线。缓存只能由单个工作线程使用；没有把磁盘操作移到 GUI。生命周期与退出语义沿用原 GameRuntime。

## 实测方法

新增 `tests/performance/instance_scan_test.cpp`，直接调用产品 `GameRuntime.refresh_instances`，等待其真实 `instances_changed`。计时包含完整实例目录扫描、版本 JSON/语言处理、目录监听重建和 GUI 结果交付；不只测缓存查找。测试不调用 `initialize` 的 Java/环境探测，因此不能当作整个启动器初始化耗时。

修改生产实现前构建并保留 `build/instance-scan-before.exe`；修改后生成 `build/instance_scan_test.exe`。两者使用同一份计时/数据生成逻辑和 Release 配置，均静态链接各自版本的业务实现。原始报告保存两个二进制的 SHA-256。数据使用确定生成的本地资产索引：每份 **601,306 字节**，4096 个普通资源项及两个语言项，大小接近本机已有的 413–597 KB 游戏索引。版本元数据和模组目录使用明确的基准夹具，不冒称用户游戏库。

每个进程先做一次完整扫描预热，再测一次完整重扫；文件生成、预热、输出比较均在计时外。共 9 组成对样本，交替先后运行修改前/后程序，无构建、其他测试或测试游戏并行；用户桌面和其他用户进程仍存在。操作系统文件缓存未清空。每次结果与该进程的预热快照完全一致，去除临时目录字段后，再比较前后完整实例快照 SHA-256；保留游戏版本、加载器、模组数量、语言等字段，未通过减少输出获得收益。

环境：Windows 11 24H2 x64（10.0.26100）、Intel Core i9-10850K、20 逻辑线程、Qt 6.8.1、MSVC 2022 Release，`/O2 /Ob2 /DNDEBUG`。未启用全局 AVX 或 `-march=native`。**未测 macOS、Linux、ARM64、冷缓存或实际启动器总启动时间。**

| 场景 | 修改前中位数（最小—最大） | 修改后中位数（最小—最大） | 耗时变化 |
| --- | --- | --- | --- |
| 40 实例，共用 1 份索引 | 310.629 ms（248.141—418.518） | 51.070 ms（44.314—200.698） | 减少 **83.56%** |
| 40 实例，共用 4 份索引 | 313.942 ms（225.251—336.668） | 91.575 ms（61.197—153.542） | 减少 **70.83%** |
| 8 实例，各用不同索引 | 61.789 ms（48.472—87.178） | 56.738 ms（51.946—68.963） | 减少 8.17%，范围重叠，不认定稳定收益 |
| 单实例 | 8.921 ms（7.637—13.479） | 9.472 ms（8.097—14.151） | **增加 0.551 ms / 6.18%**，没有收益 |

没有剔除较慢样本。单实例没有重复解析可消除，结果存在轻微回退；范围重叠且环境未隔离，不能据此证明全部差异均由缓存开销产生。不要将多实例最佳结果推广到所有游戏库。

按算法推导的索引解析次数：共用一份时 40→1，共用四份时 40→4，各自独立时保持 8→8；对应应用逻辑读取约 22.94→0.57 MiB、22.94→2.29 MiB、4.59→4.59 MiB。此为逻辑操作推导，**不是物理磁盘 I/O 计数**；未做 CPU 火焰图或峰值内存采样，不编造这些数据。

## 正确性与构建

- 新增两个正确性用例：同一扫描命中缓存确实无需再次读取文件；缓存清理/缺失/坏 JSON 后可重读，游戏根目录隔离；真实 GameRuntime 重扫能看到新语言，切目录不会复用旧范围。
- 三项原生相关回归通过：游戏选项保留及语言回退、外部实例/即时设置重启、生命周期初始化与非阻塞退出，日志 `build/scan-runtime-regression.txt`，共 5 passed（含初始化/清理）。
- `instance_scan` CTest 通过，两个正确性用例通过；四个性能数据行默认跳过，显式设置报告变量才运行。测量中四个场景的前后全部输出一致。另有 sessions/catalogs/file_digests 三项 CTest 通过，完整构建/验证日志 `build/scan-final-verification.log`。
- 原生 Release 构建通过，本次程序为 `build/bugg-current.exe`；保留用户已经运行的旧 `bugg.exe`。本轮没有改页面或 QML，不把之前的界面截图/测试冒充本轮 UI 修改验收。
- 本轮没有启动任何 Minecraft 进程；结束时核对，没有遗留测试 Java 进程。

## 原始数据与复现

稳定副本：[实例扫描性能原始数据](28-实例扫描性能原始数据.json)。每组细分 JSON、QTest 日志及汇总保留在 `build/performance-instance-scan/`；驱动日志 `build/performance-instance-scan.log`。

先构建、保留修改前的 `instance_scan_test`，再构建修改后版本；基准控制逻辑相同。修改前的扫描循环调用 `game_language_codes(root, metadata)`，修改后传入本次局部缓存。不要在发布程序中加入性能测试开关或另一套扫描实现。用同一 Qt 和 Release 工具链运行：

```powershell
$env:PATH = 'E:\code\.tools\Qt\6.8.1\msvc2022_64\bin;' + $env:PATH
python -X utf8 tests/performance/compare_native_benchmarks.py `
  build/instance-scan-before.exe build/instance_scan_test.exe `
  build/performance-instance-scan --pairs 9 `
  --build-description 'MSVC 2022 Release /O2 /Ob2 /DNDEBUG, Qt 6.8.1'
```

Python 只运行、交替排列和比较原生测试进程，不实现扫描业务，不成为启动器运行依赖。当前机器测试通过后停止重复测量，不为报告追加无关优化。
