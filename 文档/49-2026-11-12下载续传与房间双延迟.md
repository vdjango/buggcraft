# 下载续传与房间双延迟

本轮只验收可校验资源的持久续传、房间 RTT 快照和成员显示；不代表全部历史要求完成，也不把本地夹具称为公网游戏联测。

## 玩家可见变化

- 已知大小和 SHA-1 的资源下载中断、取消或启动器重开后，可以从已保存片段接着下载。切换下载地址但内容身份相同时也能复用片段。
- 源站不支持续传时重新接收完整文件；错误区间、内容编码和摘要错误拒绝拼接，不把损坏文件提交到游戏目录。
- 房间成员同时显示“到节点”和“到房主”。未知显示待测，过期或离线样本清空；旧客户端只有一种测量时不填造另一种。

## 复用与执行边界

下载仍归 HttpClient/ResourceClient，不引入第二个下载器。HttpRequest.resume 默认关闭，只在明确 GET、目标文件、大小与 SHA-1 时启用。已有分类并发、分段、来源回退和六次瞬态重试继续由原所有者执行。QLockFile 防止同一部分文件共写；完整大小和摘要验证后通过 QSaveFile 提交。已缓存前缀只恢复进度，不计入新下载速度。

成员测量沿用原桥的节点回显、Minecraft status ping 与 P2P 心跳；独立记录线路采样时间，普通准备进度不能刷新旧 RTT。节点控制层仍有 Python 运行依赖，本轮没有完成其原生迁移。未改 Session 公共对象布局。

可恢复片段位于目标目录下 `.bugg-downloads`；成功及摘要错误会清理本次片段。不同内容身份留下的旧片段目前没有独立过期淘汰机制。原子提交需要将暂存内容写入最终文件，因此增加一次本地复制；未据此宣称磁盘吞吐提升。
